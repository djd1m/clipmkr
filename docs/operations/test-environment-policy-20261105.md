# Единый тестовый стенд на рабочем VPS

## Решение владельца

05.11.2026 владелец поручил упростить проверки: запускать их на рабочем VPS
с каталогом `/home/clipmkr`, а не распределять приёмку между несколькими серверами.
Используется существующий Compose project `clipmkr-stage-20261028`; дополнительные
контейнеры и параллельный полный стек не создаются. Настоящий Cloud.ru S3 сохраняется.

Предыдущим сообщением остальные продуктовые задачи временно отложены. Настоящее
решение меняет целевой тестовый стенд, но не является согласованием макетов,
закрытием feature-adr gates или разрешением публикации приложения на Cloud.ru.

Адреса подтверждены текущими интерфейсами VPS и DNS, контейнеры — Docker ps,
числа — SELECT из обеих БД через PostgreSQL внутри соответствующего контейнера.
Чтения не являются общим транзакционным снимком: рабочий сайт продолжает принимать
изменения. Персональные данные, пароли, секреты и подписанные ссылки в документ не включены.

**Актуальная БД пользователей пока не перенесена в приложение на этом VPS.**
Наличие резервных копий или временных восстановлений для QE этого не доказывает.
Текущая локальная версия также не соответствует опубликованному приложению.

## Что нужно подготовить до проверок здесь

1. Через feature-adr определить границу операции, сохранение существующих локальных
   данных и совместимость схемы; зафиксировать настоящий план и применимые gates.
2. Сохранить и проверить резервные копии. Получить согласованный PostgreSQL-снимок
   текущего сайта и восстановить его в существующем локальном PostgreSQL без
   удаления исходной БД и существующих пользовательских данных.
3. Проверить роли, лимиты, кредиты, связи записей/клипов и платежную историю. Это
   будущая сверка, она ещё не выполнялась для переноса на этот VPS.
4. Развернуть согласованную версию приложения. Для локальных проверок обеспечить
   отдельный S3-префикс tests/* с копиями нужного медиа и проверкой ссылок/хэшей:
   локальная очистка и тестовые действия не должны изменять исходные объекты сайта.
5. Подключить существующий HTTPS-маршрут к приложению и проверить вход, загрузку,
   просмотр/скачивание на этом адресе. Ранее опубликованная IP-заглушка не является
   работающим кабинетом. Разрушающие тесты выполняются в отдельных тестовых БД
   существующего PostgreSQL, сохраняя пользовательскую копию.

Это план подготовки, а не выполненное развёртывание. Приложение, БД, DNS, S3-объекты
и платежная маршрутизация при записи настоящего решения не изменялись.

## Границы после копирования

Локальная БД будет самостоятельным снимком. Последующие регистрации, загрузки,
оплаты и изменения ролей на clipmkr.ru автоматически в неё не попадут. Постоянная
репликация и обратная запись тестовых данных в исходную БД не согласованы.
Нельзя перезаписывать рабочую пользовательскую историю локальным снимком при
последующей доставке кода. Будущая приёмка платежей потребует отдельно проверить
callback для фактического тестового адреса; сейчас она владельцем отложена.

Поставка сохраняет порядок: проверки и ручная приёмка на этом VPS, затем отдельное
разрешение на доставку того же проверенного артефакта на Cloud.ru. Production/DNS
переключаются только по отдельной явной команде владельца.
