# Подключение Resend к Clipmkr

Актуально на05.11.2026. В Clipmkr уже есть готовый адаптер Resend; новый SDK или почтовый модуль не нужны. 05.11.2026 Resend включён на test clipmkr.ru: проверочное письмо получено владельцем, запрос восстановления через приложение принят; завершение reset→login отмечается отдельно. Выполнение требований и текущая приёмка: `features/resend-activation/`.

## 1. Подтвердить домен

Откройте [Resend → Domains](https://resend.com/domains), выберите **Add Domain**, укажите `clipmkr.ru`. Если домен уже есть со статусом **Verified**, используйте его.

Resend покажет DNS-записи для отправки. В панели DNS домена добавьте их, точно копируя тип, имя и значение из Resend. Конкретные значения берите из своего кабинета: они зависят от домена и региона. Для отправки могут потребоваться DKIM и SPF/Return-Path записи, включая MX на указанном служебном поддомене.

Существующие MX основного домена сохраняются. Приём входящей почты для восстановления пароля подключать не требуется. После добавления записей запустите проверку в Resend и дождитесь **Verified**. Адрес сайта и его A-записи не меняются.

[Официальная инструкция по доменам](https://resend.com/docs/dashboard/domains/manage-domains).

## 2. Отключить отслеживание

В настройках домена выключите **Open tracking** и **Click tracking** для транзакционных писем восстановления. Так ссылки доступа не будут оборачиваться трекингом.

[Рекомендации Resend для транзакционной почты](https://resend.com/docs/dashboard/domains/introduction).

### Если показано Unsupported Domains для .ru

Предупреждение о том, что custom tracking subdomains требуют TLS-сертификат и часть региональных доменов не поддерживается certificate provider, относится к **собственному поддомену отслеживания**. Это само по себе не является доказательством запрета обычной отправки с .ru.

Для текущего подключения оставляем Open tracking и Click tracking выключенными, custom tracking subdomain не создаём. Проверяем записи отправки SPF/DKIM и статус Verified основного sending domain. CNAME/CAA, предлагаемые именно для Tracking, не являются необходимой частью этого подключения.

[Точный раздел Resend: Unsupported Domains](https://resend.com/docs/dashboard/domains/tracking#unsupported-domains).

Если Resend отдельно отклоняет именно добавление/проверку sending domain или реальную отправку, сохранить точный текст/этап ошибки и проверить отдельно. До успешной реальной проверки не объявлять .ru отправку работающей. Возможный другой путь — уже имеющийся SMTP-адаптер Clipmkr либо подтверждённый другой домен владельца для отправителя; основной сайт и ссылки восстановления при этом остаются на clipmkr.ru. Выбор альтернативы не применять без решения владельца.

## 3. Создать ключ отправки

В [Resend → API Keys](https://resend.com/api-keys) создайте отдельный ключ:

- имя: `clipmkr-test`;
- права: **Sending access**;
- домен: `clipmkr.ru`.

Ключ с этими правами используется приложением для отправки. Полный административный доступ для работы существующего адаптера не требуется. Sending access не следует считать доступом к чтению полученного письма для автоматического E2E.

[Официальная инструкция по ключам](https://resend.com/docs/dashboard/api-keys/introduction).

## 4. Заполнить закрытый профиль на управляющем VPS

Путь: `/root/.config/clipmkr/mail/resend.env`. Каталог имеет права0700, файл0600. Файл находится вне Git, его значения нельзя публиковать в репозитории или чате.

```dotenv
N5_MAIL_MODE=resend
N5_RESEND_API_KEY=
N5_MAIL_FROM="clipmkr <noreply@clipmkr.ru>"
CLIPMKR_MAIL_TEST_TO=
```

В `N5_RESEND_API_KEY` поместите свой настоящий ключ вне чата. В `CLIPMKR_MAIL_TEST_TO` укажите свой разрешённый ящик для проверочного письма. Отправитель должен принадлежать подтверждённому домену. `CLIPMKR_MAIL_TEST_TO` — настройка проверки, не новая переменная приложения и не адрес всех пользовательских писем.

Само заполнение файла не меняет работающий контейнер. После настройки сообщите исполнителю: «готово, домен Verified».

## 5. Подключение приложения

Исполнитель валидирует профиль штатным `loadMailConfig`, сохраняет исходную конфигурацию и резервную копию, проверяет фактический target. На текущем тестовом стенде `clipmkr.ru` обновляется только web-сервис проекта `n5-clipmaker`; используется тот же проверенный образ приложения. Меняются только `N5_MAIL_MODE`, `N5_RESEND_API_KEY`, `N5_MAIL_FROM`. Другие настройки, данные, остальные сервисы и Cloud.ru сохраняются.

Для Cloud.ru действует отдельная ручная приёмка владельца. Настройка Resend не является разрешением переключать production/DNS или переносить туда конфигурацию.

## 6. Приёмка восстановления

Проверяются отдельные факты:

1. На `/forgot` доступна отправка инструкции.
2. Для согласованного тестового аккаунта Resend принимает письмо.
3. Письмо действительно приходит в разрешённый ящик, ссылка ведёт на правильный origin Clipmkr.
4. Ссылка позволяет один раз задать новый пароль; затем работает вход с новым паролем. Повторное использование ссылки отвергается.

Ответ API Resend `accepted` сам по себе не доказывает доставку и успешную смену пароля. Для полного роботизированного прохода нужен отдельный QA-аккаунт и доступ к полученному письму; иначе последний этап проходит владелец вручную. Пароль существующего владельца/пользователя автоматически не меняется.

Факт включения, приём письма провайдером, получение пользователем и завершение reset→login отмечаются раздельно. Секреты, адреса получателей, сессии и ссылки с reset token остаются в закрытом контуре.
