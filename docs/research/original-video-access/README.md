# Доступ к исходной записи: предложение для согласования

11 ноября 2026. Исследуемый код: `58e72ab7f2b24e3574d56ddb561cf9b074ed6b73`.
Статус: исследование и синтетический макет; в приложении не реализовано. Макет не согласован.

Просмотр и скачивание своего исходника полезны: сверить выбранные моменты с полной записью,
вернуться к контексту разговора, забрать ранее загруженный файл. Рекомендуем компактную строку
**«Исходник · Смотреть · Скачать»** под заголовком записи. Она вторична по отношению к готовым
клипам. Не нужен отдельный раздел кабинета, файловый менеджер или новая панель массовых действий.

[Открыть интерактивный макет](mockup.html): обычное состояние и просмотр исходника в том же
рабочем пространстве, с возвращением к выбранному клипу. Все название, размер, кадры и данные
в макете вымышлены; кнопка скачивания объясняет предложение и не обращается к хранилищу.

Имя исходного файла в `video` сейчас не сохраняется: имя используется при создании ключа/расширения;
клиентский upload-resume хранит его только для продолжения передачи. Поэтому обещание скачать
«с исходным именем» потребует отдельного решения. Минимальный вариант — безопасное
`Исходная запись <дата>.<проверенное расширение>`; не называть MOV/MP3 файлом MP4.

## Жизненный цикл и фактическое наличие

[`retention.ts`](../../../apps/web/src/server/retention.ts) удаляет просроченные клипы и миниатюры,
а при стирании аккаунта очищает весь `videos/<account>/` и производные файлы. Фиксированного
автоматического TTL исходника в этом проходе нет. [`legal-documents.ts`, пункт 6.2](../../../apps/web/src/lib/legal-documents.ts)
прямо отделяет хранение исходника от срока клипов. Отказ при проверке файла вызывает cleanup
исходного объекта в `VideoService`; незавершённый multipart ещё не является доступным файлом.
Внешние S3 lifecycle/операционные source-purge правила этой read-only проверкой не установлены.
Поэтому нельзя обещать вечное хранение, переносить срок клипа на исходник или показывать
«доступен» только по `status=done`, `object_key` либо успешной обработке в прошлом.

Отдельное приватное доказательство текущего наличия одной собственной записи: существующий
`/root/.config/clipmkr/zoom-screen-layout-20261111/source-probe.private.json` содержит успешный probe
исходника (1646,586938 с; 1816×968; H.264/AAC; 135342652 байт). Получение объекта ранее выполнено
в соседнем исследовании. Здесь файл повторно не скачивался; в Git не включены медиа, ключ,
идентификатор аккаунта и подписанный URL. Одна запись не доказывает наличие остальных исходников,
работоспособность будущего браузерного route или поддержку всех кодеков.

| Состояние | Предлагаемое поведение |
| --- | --- |
| Объект подтверждён, видео воспроизводимо браузером | Смотреть + Скачать; длительность и фактический размер; срок только если он известен |
| Передача не завершена | «Исходник ещё загружается»; без просмотра/скачивания; существующее продолжение загрузки |
| Обработка идёт, загрузка уже завершена и объект доступен | Смотреть/Скачать допустимы независимо от стадии нарезки; обработку не перезапускать |
| Объект удалён или известный срок истёк | «Исходный файл недоступен» / «Срок хранения исходника закончился» только при подтверждённой причине; готовые клипы живут по своему сроку |
| HEAD/S3 временно не отвечает | «Не удалось проверить исходник. Повторить»; не объявлять его удалённым |
| Только аудио | «Исходная аудиозапись · Слушать · Скачать», нативный audio; без пустого видеоэкрана |
| Контейнер/кодек не поддержан браузером | Понятный отказ просмотра и доступное скачивание; не запускать автоматическую платную конвертацию |
| Запись/аккаунт удалены, чужой или неизвестный ID | Одинаковый 404, без метаданных и подписи |

До реализации нужен небольшой read-only inventory runtime: актуальный bucket/namespace,
внешние lifecycle/purge правила и несколько допустимых собственных примеров с разными состояниями.
Без этого не назначать конкретную дату окончания хранения в UI. Срок хранения исходника — отдельная
продуктовая политика и стоимость, не часть этой визуальной идеи.

## Предлагаемый контракт и границы доступа

Одинаковое действие для обычного пользователя и блогера; лимиты 90/120 минут относятся к загрузке,
не к разрешению прочитать собственный файл. Владелец продукта видит здесь **только свои записи**:
его отчёты по блогерам не дают автоматического доступа к чужим медиа. Гостевые пакеты,
реферальные ссылки, публичное превью и showcase исходник не получают.

Кандидат будущего контракта: `GET /api/videos/<id>/original` и `?download=1`;
имя route ещё не согласовано. Сначала существующая session/rate-limit/UUID/active-account/ownership
проверка и `deleted_at IS NULL`, затем проверка завершённого объекта и применимой политики.
Ключ брать из БД, не из URL/тела клиента. Возвращать 404 для чужого/несуществующего,
503 для временной ошибки, 302 на короткую подпись с `private, no-store` и `no-referrer`.
Не добавлять подписанные URL в обычный `video.list`, логи или долговременное браузерное хранилище.
Фактический размер получать HEAD/сверять с сохранённым `actual_bytes`; не брать declared size за истину.

Подпись ограничивать 900 с и меньшим известным сроком исходника. Подписанная ссылка — временный
bearer-доступ: выход из аккаунта не отзывает уже выданную подпись до её конца. Политика, требующая
немедленного отзыва, потребует другого способа выдачи и должна быть согласована отдельно.
При протухании ссылки во время нового seek — одно обновление авторизованного URL с сохранением
позиции и состояния pause, без бесконечных retries. Не утверждать, что 900 с хватает на просмотр
120-минутного видео: новые Range-запросы после истечения подписи могут отказать.

Для просмотра важны Range/206/Content-Range/Accept-Ranges и корректный Content-Type на **настоящем
Cloud.ru S3**, включая мобильный seek/fullscreen. Текущий multipart создаёт
`application/octet-stream` ([`multipart.ts`](../../../packages/s3/src/multipart.ts)); helper сейчас
не принимает ResponseContentType. Значит, необходимо безопасно расширить существующий signer
или другой установленный metadata seam для проверенного MIME; расширение имени не доказывает кодек.
Для скачивания — серверный `Content-Disposition: attachment` с безопасным UTF-8 именем и верным
расширением. Текущий helper содержит fallback `clip.mp4`: обобщить осторожно, сохранив контракт клипов.
`download` у ссылки в браузере сам по себе не гарантирует скачивание через другой origin.
Не загружать весь большой исходник в Blob/память JS; передавать получение браузеру/S3.

## Макет и будущее доказательство

Строка под заголовком не меняет основной путь «выбранный клип → скачать». «Смотреть» заменяет
область просмотра на исходник, без autoplay; «К клипам» восстанавливает выбранный клип. Одновременно
играет один файл. На телефоне — строка с переносом метаданных, тач-цели ≥44 px, штатный fullscreen.
Скачивание не запускает обработку, не расходует кредиты и не считается скачиванием клипа в growth.

Перед кодом: согласовать этот конкретный макет и объём, затем feature-adr/dz routing/recall,
requirements/reuse/ADR/plan/K1/K2 и OpenSpec delta. Этот документ не является разрешением реализации
или gate-квитанцией. Авторитетные ограничения: [AGENTS](../../../AGENTS.md),
[core-cjm](../../acceptance/core-cjm.md), [план поставки](../../plans/2026-11-05-ui-recovery-cloud-delivery.md).

Инвентаризация будущего воздействия: signer используют `screen-runtime`/clip/showcase; `VideoScreen`
потребляют список, детали, dashboard SSR и 5-секундный poll. Авторизация/сроки/namespace — общие seams;
загрузка и worker retry зависят от того же source object. Не добавлять HEAD каждого файла в каждый
poll без измерений: отдельная read-проекция/проверка по запросу предпочтительна.

Существующие якоря для будущего плана проверок (сейчас **не запускались**):
`tests/progress-screen.test.ts`, `tests/progress-screen.integration.test.ts`, `tests/retention-route.test.ts`,
`tests/retention-policy.test.ts`, `tests/retention-storage.test.ts`, `tests/guest-pack.test.ts`,
`tests/s3.test.ts`, `tests/s3-public-endpoint.test.ts`, `tests/storage-prefix.test.ts`,
`tests/browser/video-screen.test.ts`, `tests/browser/ux-simplification.test.ts`,
`tests/trust-guards.test.ts`, `tests/units-and-guards.test.ts`.
Перед правкой проверить точные source guards/mutation anchors и фиксированные SHA в потребителях;
не перепривязывать чужие historical receipts к новой ревизии.

Минимальная будущая приёмка: аноним/другой аккаунт/owner против чужой записи не получают объект;
свои роли получают только свои файлы; incomplete/missing/expired/deleting/503 различимы;
attachment MIME/имя/размер корректны; Cloud.ru выдаёт 206 и seek на длинном файле после протухания
подписи восстанавливается; MP3/MOV/неподдержанный codec дают честный fallback; mobile/keyboard/focus
и возврат к клипам не сбрасывают выбранный клип; нет параллельного звука, повторной нарезки,
начисления, попадания исходника в guest/showcase и секретов в telemetry. После изменения — один
необходимый общий прогон, локальные повторы только затронутых проверок, независимый QE и поставка
по существующему порядку. Текущий docs-only результат не доказывает эти сценарии.

Проверка макета: локальный Chromium, 1440×1000 и 390×844; начальное состояние и открытый исходник,
перенос строки, отсутствие горизонтального overflow, возврат к клипам. Результат: обе ширины без горизонтального overflow, обе кнопки исходника высотой 44 px,
ошибок JavaScript нет; переход к исходнику, возврат к выбранному клипу и демонстрационный ответ
скачивания прошли. Скриншоты осмотрены: [390 px](mockup-390.png), [просмотр 1440 px](viewer-1440.png).
Команда: `node` с `require('/home/clipmkr/node_modules/playwright')`, Chromium headless,
локальный `file:///tmp/clipmkr-original-and-feedback-research-20261111/docs/research/original-video-access/mockup.html`,
`browser.newPage({viewport:{width,height},deviceScaleFactor:1})`, `page.screenshot({fullPage:true})`,
click/assert для `#watch`, `#return`, `#download`; terminal exit 0. Это визуальная проверка макета,
