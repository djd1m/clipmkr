Статус — рекомендация к выбору лицензии. Владелец уточнил цель — запретить конкурентам продавать сервис на коде Clipmkr.

## Предлагаемый выбор

Для защиты нынешнего SaaS предлагается официальный текст **Elastic License 2.0, ELv2**. Лицензиат получает права использовать, изменять и распространять код в рамках её условий. Предоставление ПО третьим лицам как hosted/managed-сервиса с доступом к существенному набору его функций ограничено. Этот пункт применяется и к бесплатному сервису. Правообладатель может продавать собственный сервис в пределах прав, которыми располагает. [Официальный текст ELv2](https://www.elastic.co/licensing/elastic-license)

Переименованный сайт, который на коде Clipmkr принимает видео клиентов и выдаёт нарезку, по нашей оценке попадает в целевой сценарий ограничения. Самостоятельная установка для внутренних задач компании и услуги по её настройке рассматриваются в FAQ Elastic как разрешённые сценарии. Встраивание отдельных функций в другой продукт оценивается по фактическому объёму доступа. FAQ описывает подход Elastic к своим продуктам, применение к Clipmkr требует учёта конкретного сценария. [Примеры Elastic](https://www.elastic.co/licensing/elastic-license/faq)

Возможность распространять и продавать копии для самостоятельной установки сохраняется при соблюдении условий ELv2. Для ограничения также конкурентных дистрибутивов требуется отдельно рассмотреть PolyForm Shield. Числовой порог существенности функций в ELv2 отсутствует, поэтому оценка конкретного продукта зависит от его устройства и предоставленного доступа. [Права и ограничения ELv2](https://www.elastic.co/licensing/elastic-license)

Для описания проекта подходит формулировка «публичный исходный код под ELv2, source-available». Поставленная цель ограничения конкурентного бизнеса несовместима с определением open source OSI, которое предусматривает коммерческое использование и свободное распространение. Продажа собственного SaaS сама по себе совместима и с открытыми лицензиями. [Определение OSI](https://opensource.org/osd)

## Сравнение вариантов

| Вариант | Защита и последствия |
| --- | --- |
| ELv2 | Основной кандидат для ограничения стороннего hosted/managed-сервиса с существенным набором функций. Автоматического перехода на открытую лицензию в тексте нет. [Условия](https://www.elastic.co/licensing/elastic-license) |
| PolyForm Shield 1.0.0 | Более широкий запрет использования кода в конкурентном продукте, включая бесплатный и распространяемый для самостоятельной установки. Есть специальные условия о новых и прекращённых продуктах лицензиара. Подходит при намерении ограничивать также конкурентные дистрибутивы. [Текст](https://polyformproject.org/licenses/shield/1.0.0) |
| BSL 1.1 | Производственное использование определяется через Additional Use Grant. Каждая версия переходит под указанную Change License к Change Date либо через четыре года после первого публичного распространения этой версии, смотря что наступит раньше. Потребуются дополнительные параметры. [Текст BSL](https://mariadb.com/bsl11/) |
| FSL-1.1-ALv2 | Ограничивает конкурирующее коммерческое предоставление, но через два года для каждой версии вступает в силу дополнительная Apache-2.0. Это осознанно ограниченная по времени защита. [Шаблон Sentry](https://github.com/getsentry/fsl.software/blob/main/FSL-1.1-ALv2.template.md) |
| MIT / Apache-2.0 | Разрешают конкурентное коммерческое использование при соблюдении условий. [MIT](https://opensource.org/license/mit) · [Apache-2.0](https://www.apache.org/licenses/LICENSE-2.0) |
| AGPL-3.0 | Разрешает платный конкурентный сервис. Для модифицированной версии с сетевым взаимодействием §13 требует заметно предложить её соответствующие исходники взаимодействующим пользователям. [AGPL](https://www.gnu.org/licenses/agpl-3.0.html) |

AGPL плюс отдельная коммерческая лицензия позволяет предлагать другие условия, однако конкурент сохраняет возможность соблюсти AGPL. Такое двойное лицензирование требует достаточных прав на выдачу обеих лицензий, включая права на сторонние вклады. [FAQ FSF](https://www.gnu.org/licenses/gpl-faq.html#ReleaseUnderGPLAndNF)

## Границы применения

В исследованном корне Git не найден общий LICENSE. Публичная доступность репозитория сама по себе не предоставляет общей лицензии на использование всего проекта. Для собственного и стороннего кода нужно проверить применимые разрешения. [GitHub о лицензировании репозитория](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)

Новая лицензия собственного кода действует вместе с применимыми лицензиями компонентов, моделей, шрифтов и медиа. Отдельно проверяются заимствования из прежних проектов, права контрибьюторов и уже выданные разрешения. Корневой LICENSE не меняет лицензии FFmpeg, Libredesk или других поставщиков. Реестр наблюдений и нерешённых вопросов приводится в [аудите компонентов](dependency-audit.md).

Собственные названия и бренд, загруженные пользователями файлы и сгенерированные клипы требуют самостоятельного описания прав. Публикация исходников приложения не означает разрешения распространять пользовательское медиа.

## Порядок применения после выбора

1. Уточнить правообладателя и проверить достаточность прав на покрываемые файлы.
2. Зафиксировать охват собственного кода и отдельные сторонние notices.
3. Добавить оригинальный текст выбранной лицензии в LICENSE и понятное описание разрешённого использования в README. Правила приёма новых вкладов должны учитывать выбранную лицензию и будущие коммерческие разрешения.
4. Согласовать формулировки с юристом для предполагаемых юрисдикций и опубликовать один коммит во всех трёх репозиториях.

Исследование сравнивает опубликованные условия лицензий. Возможность защиты конкретного сервиса в споре, применимость условий в нужной стране и достаточность прав владельца не установлены этим исследованием.
