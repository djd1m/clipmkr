# Карта доказательств и воспроизводимость

Исследование ограничено публичными первоисточниками и чтением существующего кода. Ни приведённые возможности, ни репутация проекта не означают, что функция проверена нами в интерфейсе или на пользовательском медиа.

## Утверждение → основание → граница

| Утверждение | Основание | Вид доказательства и ограничение |
|---|---|---|
| В Clipmkr уже есть детекция лиц и две панели | Закреплённые пути faces.ts, detect_faces.py, format.ts в [инвентаризации](oss-candidates.md) | Наблюдение исходного кода. Принадлежность лица автору и готовый режим камера + игра отсюда не следуют |
| Старый dual означает двух людей | format.ts:64–75 и ADR-009; [отдельная граница режима](architecture-options.md) | Действующая семантика. Для camera/content нужна будущая явная дельта требований/ADR и макет |
| Найти лицо недостаточно, чтобы выбрать автора | planFollow выбирает самое большое лицо; независимые области в clips-studio; официальные описания конкурентов | Факт алгоритма + инженерный вывод о риске. Новая точность распознавания не измерена |
| Два ROI могут собираться одним encode | Native split/crop/scale/vstack и официальный FFmpeg filtergraph | Подтверждённые операции и предложение композиции. Ускорение/экономия не замерены |
| ROI не восстанавливает скрытые слои | Операция crop и состав композитного входа; [разбор ограничений](architecture-options.md) | Физическая граница метода. Нет обещания восстановить лицо или игру под камерой |
| Постоянная голова требует строгого режима | Точное пожелание владельца, границы видимости input | Предложение будущего требования. Fallback без камеры не считается выполнением; выбор режима не сделан за владельца |
| При compaction нужна единая D′ | planDuration, mapTime, xfade/acrossfade в [native code](architecture-options.md) | Наблюдение кода. Двухфайловый sync и drift ещё не реализованы/проверены |
| Нужны разные метрики coverage | [План пилота](streamer-cjm-and-pilot.md) | Предложенный метод: весь экспорт и условно видимый input отдельно, gaps не скрываются |
| OSS различаются лицензией и свежестью | Primary LICENSE/README, API commit/release и выбранный source path | Датированный срез. Stars не качество; code license не автоматически лицензия weights |
| Шесть продуктов дают полезные ориентиры | P1–P15 в [источниках](sources.md) | Официальные функции/самоотчёты. Не все имеют доказательства коммерческого успеха; UI/качество здесь не тестировались |
| Coding/education — возможная первая ниша | Текущий transcript-oriented selection, задача сохранить объяснение и код | Гипотеза автора. Нет интервью, готовности платить, оплаченной конверсии или доказанной ёмкости рынка |
| Долгие стримы не отменяют caps | upload.ts, core-cjm: 90/120 минут, индивидуальный лимит, 2 000 000 000 байт | Действующее требование и source constants. Multi-hour ingest отдельно не согласован |
| Готовность рынка зависит от доставки/поддержки | Опубликованный инцидент S3/partial result и backlog; [этапы пилота](streamer-cjm-and-pilot.md) | Требование к полному клиентскому пути. Не препятствует отдельной разрешённой локальной оценке геометрии |

## След чтения и качества

В `features/streamer-facecam-research/source-retrieval-receipts.json` сохранены фактические URL, время, размеры/хэши полученных публичных тел и ошибки прямого HTTP-чтения. Сырые HTML и сторонние исходники хранились только во временном каталоге исследователя, не в продукте. Ответ 200 подтверждает получение байтов, а не истинность вывода; просмотр через Web и прямой HTTP — разные наблюдения.

До создания публичного набора были записаны требования, инвентаризация и план; K2 завершился PASS, а поддерживаемые dz checkpoints реально подтвердили artifacts router/requirements/plan. Это процессная проверка, не тест будущего renderer. Уровень S задан для doc-only research; продуктовая сложность будущего изменения отдельно не оценена как «простая».

Перед передачей выполняются проверка локальных ссылок, declared scope, whitespace, читаемости, источников и code/spec anti-drift. Собственный отчёт автора — `features/streamer-facecam-research/08_qe_report.md`; независимые отчёты — `features/streamer-facecam-research/reviews/`, вне измеряемых семи документов. Статус внешнего review не встраивается в пользовательский README.

## Нерешённые вопросы

Нет сравнения детекторов на наших материалах, проверки модели на VTuber, подтверждённого автоматического camera identity, стоимости нового layout, синхронизации отдельного OBS-файла и рыночной проверки. Не установлены права на конкретные будущие источники/гостей/музыку. Framedrop не включён в основной shortlist из-за недоступности первоисточника. Рабочие исходники, согласованные фикстуры и решение владельца понадобятся для следующего этапа; они не создавались этим исследованием.
