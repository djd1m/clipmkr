# Создание персонального доступа владельца в Libredesk

Владелец прямо поручил создать аккаунт с логином и паролем 05.11.2026. Операция выполнена на существующем https://support.clipmkr.ru/, без изменения приложения Clipmkr или Cloud.ru. Это реальная административная настройка, а не разработка новой функции.

## Выполнено и проверено

Оператор `gpt-6.1-sol high` использовал существующий технический вход и штатный API Libredesk v2.9.0: проверил отсутствие целевого аккаунта, создал персонального агента с ролью Admin и `send_welcome_email=false`, установил случайный пароль штатным механизмом, проверил вход и профиль. Прямой INSERT пользователя, собственное хеширование и сброс пароля System не применялись.

Независимый `gpt-6-astra xhigh` отдельно выполнил native login и чтение собственного профиля. Оба ответа200; совпадение персонального аккаунта, active agent, Admin и разрешений conversations:read_all, conversations:read, messages:read, users:manage подтверждены. Первый проверяющий parser ожидал объекты ролей, тогда как эта версия возвращает массив строк; после сверки настоящей схемы проверка повторена успешно. Изменять права для получения PASS не потребовалось.

Координатор отдельным read-only агрегатом подтвердил: активных персональных агентов теперь1, System/Admin сохранён. Проверки переписки и реального ответа клиенту не выполнялись. Письма, тестовые обращения и сообщения не отправлялись; конкретные диалоги не открывались. Оператор сверил неизменность метаданных диалогов, отметок чтения и количества сообщений. Штатные auth-сессии, отметки входа и аудит создания аккаунта являются ожидаемыми изменениями.

Первоначальный подготовительный metadata query ошибся в имени таблицы и завершился до входа/создания. После исправления проверка отсутствия аккаунта повторена; существующие учётные записи не сбрасывались. Ни один такой отказ не записан как успешная операция.

## Как использовать

Открыть https://support.clipmkr.ru/, войти выданной персональной учётной записью, перейти в All conversations и выбрать Open. Права позволяют читать все очереди и управлять сотрудниками. Пароль и логин переданы владельцу в чате и сохранены в закрытом профиле на управляющем VPS; в Git их нет. Учётная запись Clipmkr и учётная запись Libredesk остаются разными.

Историческая [проверка отсутствия персональных агентов](runtime-metadata.md) описывает состояние до этой операции. Первоначальный [review](review.md) относится к исходному исследованию; подтверждение создания и независимого входа приведено здесь, его нельзя подменять тем ранним review.
