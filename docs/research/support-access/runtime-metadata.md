# Дополнение: фактически настроенные сотрудники Libredesk

5 ноября 2026, после первичного документального исследования. Координатор выполнил отдельную SQL-проверку агрегатов в `BEGIN READ ONLY … ROLLBACK` на действующем helpdesk. Это новый этап проверки: прежнее ограничение evidence.md «SQL не вызывался» относится к первоначальному исследованию, не к этому дополнению.

Результат команды: exit0. Активных неудалённых пользователей type=agent, кроме технической записи с email=System, **0**. Техническая System активна и имеет роль Admin. Человеческих агентов с conversations:read_all **0**. Проверены memberships/permissions; тексты обращений, сообщения, пароли, токены и API-ключи не извлекались. Настройки и данные не менялись.

Практический вывод: персональный агентский доступ сотрудников/владельца пока не настроен. Наличие System/Admin не доказывает, что владелец знает пароль, может войти, получил уведомление или видел обращения; невозможность технического входа тоже не утверждается. Нужен персональный аккаунт сотрудника в Libredesk и подходящая роль, например с conversations:read_all/conversations:read/messages:read для просмотра всей очереди. Создание аккаунта, восстановление пароля или выдача прав этим исследованием не выполнялись.

Адрес просмотра остаётся https://support.clipmkr.ru/ → доступный список → Open. Существование персонального owner аккаунта Clipmkr не создаёт агента Libredesk автоматически. Подробный маршрут и различие прав — [README](README.md). Независимый исходный [review](review.md) относится к первоначальным двум MD; это дополнение отдельно не объявляется проверенным тем review.

Проверяемый агрегат: users.type=agent AND enabled AND deleted_at IS NULL; human дополнительно email<>System; принадлежность ролям users→user_roles→roles. Возврат персональных записей, staff API и чтение текстов диалогов не нужны для этого вывода. Приватная квитанция команды хранится внеGit; реальные идентификаторы и адреса людей не публикуются.
