# Матрица паттернов: доказательство → кандидат → проверка

**MUST** означает уже обязательный принцип Clipmkr из core-CJM/согласованных решений, а не новое требование из банков. **Стоит проверить** — гипотеза для будущего согласования. **Не применять** — перенос не обоснован текущим scope. В каждой строке «эффект» пока гипотеза. Источники и уровни V/D/S — в [реестре](sources.md); задания T1–T8 — в [плане](validation.md).

| ID / паттерн → проблема | Банковское evidence / уверенность | Кандидат Clipmkr / переносимость | Риск / проверка / статус |
|---|---|---|---|
| P01 Фокус на текущем объекте → много конкурирующих задач | T01 V: один счёт или компактная группа; высокая для графики | Текущая запись, player/скачивание; высокая для принципа | Скрыть остальные записи; T1/T3; MUST сохранить согласованную иерархию |
| P02 Подписанные стабильные разделы → потеря ориентации | T01 V, A03 V: нижние tabs с текстом; высокая для видимого | Один обнаружимый вход в работу/настройки/роль; высокая для ориентации, низкая для bottom nav на Windows | Лишний mobile shell; T1/T5/T7; стоит проверить названия, не вводить новую nav автоматически |
| P03 Быстрое основное действие + отдельный каталог → регулярная задача тонет | T01 V, A04 D, A05 D; средняя | Загрузка отдельно от настроек; блогерская ссылка отдельно от редких кампаний; высокая | Спрятать условно важное; T1/T5; MUST в рамках согласованного UI |
| P04 Контекстное раскрытие → поле не нужно на этом шаге | T04 D: необязательное поле; T06 D: i; A06 D; средняя | Дополнительное оформление после выбора файла, резюме параметров; высокая | Потеря значений/невидимый расход; T2; MUST сохранение значений, стоит проверить обнаружение |
| P05 Последствия до подтверждения → непреднамеренный расход | T04 D: итог на кнопке; A05 D: комиссия заранее; средняя | Цена/объём/срок пакета перед уходом к провайдеру; высокая | Убрать цену в advanced; T4; MUST core-CJM |
| P06 Намерение отдельно от завершения → преждевременный успех | T03 D: обработка отдельно от завершения; A06 D: отдельное подтверждение; средняя | Pending/confirmed/failed от сервера, корректный возврат; высокая | Успех по URL, повторное начисление; T4; MUST core-CJM |
| P07 История привязана к объекту → трудно объяснить событие | T03 D: операция→документ; A08 D исторический: вопрос по операции; средняя/ограниченная актуальность | Запись→статус/допустимое восстановление; платёж→подтверждение; высокая | Утечки чужих данных, технический мусор; T3/T4; MUST права, стоит проверить подачу |
| P08 У ожидания есть видимый статус → пользователь повторяет действие | T03 D: часы+текст; средняя | Реальная стадия, пауза/возобновление по контракту; высокая | Фальшивый процент/дубль обработки; T3; MUST |
| P09 Полезный default можно изменить → повторный ввод | A03 D **web («Альфа-Онлайн»)**: основной счёт изменяем в операции; средняя | Сохранённые текущие настройки с явным резюме; средняя | Скрытые параметры запуска; T2; стоит проверить, без новых defaults |
| P10 Поиск по задаче/известному ключу → большой каталог | T06 D: название/ИНН; A03 V: search; средняя | Сначала прямые входы; поиск записи только при подтверждённой проблеме списка; средняя/низкая сейчас | Построить лишний search; T1/T5; стоит проверить потребность |
| P11 Помощь в контексте → надо заново объяснять проблему | A08 D исторический, T03 D: поддержка при задержке; средняя | Помощь возле ошибки/записи с безопасным ID; высокая для контекста | Выдать секретный URL/приватное медиа; T3/T8; стоит проверить |
| P12 Обратимая персонализация и тема → разный контекст восприятия | T01 V/D; A05 V **web**; средняя | Существующие темы/компоновки, текущий выбор обнаружим; высокая | Настройки вместо выполнения задачи; T7/T8; MUST сохранить согласованное, новые варианты не требуются |
| P13 Семантика/шрифт/не один цвет → недоступен следующий шаг | T05 D, A04 D только главная; средняя как заявление | Keyboard/NVDA, reflow, текст ошибки/статуса; высокая для web-принципа | Объявить доступность по screenshot; T8; MUST по текущим требованиям, без ложного WCAG verdict |
| P14 Разнести обязательное и предложения → всё выглядит срочным | T01 D: важные/прочие уведомления; A03 V: сервисы и яркие офферы; средняя | Ошибка/восстановление выше вторичных подсказок; высокая | Банк сообщает преимущества, не измеряет distraction; T3/T4; MUST не скрывать нужное, новые уведомления не вводить |

## Что не переносить буквально

| Банковский control | Почему не следует автоматически переносить | Переносимый принцип |
|---|---|---|
| Пять нижних tabs, шторка, long-press/swipe/drag | Native и mobile web различаются; Windows/keyboard нуждаются в явных controls; число разделов Clipmkr другое | Стабильная ориентация и доступный переход |
| Биометрическое банковское подтверждение, QR-перевод | Иные риски/инфраструктура; исследование не меняет auth/оплату | Ясная граница подтверждения и честный итог |
| Карусель счетов как главный просмотр | За пределами viewport предмет может быть незаметен | Выбор объекта с понятной принадлежностью |
| Геймификация, «выгода», партнёрский маркетплейс | Не отвечает загрузке→клипам/оплате/статистике; создаёт конкурирующую цель | Вторичные предложения не закрывают рабочее действие |
| Автоподстройка каталога, голосовой поиск, AI-рекомендации | Нет evidence потребности в Clipmkr; цена новой capability | Уменьшать повторный ввод там, где проблема измерена |
| Красный как единственный маркер неуспеха | Публичный текст T03 не доказывает дополнительный accessible label | Статус словами, причина и допустимый следующий шаг |

## Противоречие, которое полезно сохранить

Т‑Банк заявляет удаление отвлекающего контента с главной, но оставляет экосистемные разделы. Альфа раскладывает экосистему за шторой/вкладками и продолжает показывать предложения. Обе стратегии могут быть разумны для разных задач; **нет данных**, что одна повышает task success Clipmkr. Самый сильный вывод — не копировать количество возможностей и визуальную поверхность, а проверить, видит ли наша роль нужный следующий шаг без потери обязательного состояния.
