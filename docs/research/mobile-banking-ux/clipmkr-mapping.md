## Роли и приоритет

- **Обычный пользователь:** выбрать файл → передать/продолжить → получить и просмотреть/скачать клипы; оплатить пакет при необходимости. Банковская аналогия — ясное действие и статус, не банковский каталог.
- **Блогер:** тот же путь клипов плюс готовая собственная ссылка, копирование и принадлежащая ему статистика. Финансовый объект нельзя подменять начисленным долгом/автовыплатой; оценка вознаграждения имеет действующие правила.
- **Владелец:** назначить блогера, найти нужного человека, посмотреть период/разбивку. Упрощение не означает убрать причину назначения, серверные права или контроль последствий.

**P0** — уже обязательная приёмка/сохранность состояния, денег и прав; **P1** — обнаружение действий/настроек, проверять после P0; **P2** — исследовательские улучшения только после подтверждения потребности. Это порядок проверки, не новое обещание объёма разработки. Паттерны P01–P14 — из [сопоставления](patterns.md); T1–T8 — из [плана проверки](validation.md).

## Переиспользование раньше новых controls

Не предлагается новая библиотека, state runtime, схема ролей или глобальный поиск. В текущем [reuse inventory](../../../features/ux-simplification/02_reuse_inventory.md) уже перечислены `Uploader`, `WorkspaceHeader/WorkspaceSettings`, `LimitsPanel/UpgradeScreen`, `VideoDetail/ClipCard`, `PartnerPanel`, `BloggerAdmin`, `video.retry`, HTML `details/dialog/label/button` и CSS tokens. Это минимум три существующих класса паттернов: шаги загрузки/возобновление; объект результата/контекстные действия; роль/навигация/настройки. Исследование переиспользует эту инвентаризацию, не заявляет повторный аудит или тест каждого компонента.

## Граница native ↔ responsive web

| Принцип | Mobile Clipmkr | Chrome/Windows Clipmkr |
|---|---|---|
| Ориентация | Явный текущий раздел и подписи | Та же терминология; привычный pointer/keyboard путь |
| Вторичное по запросу | Явно открываемая группа с резюме | Клавиатурный focus, Enter/Space, сохранённое состояние |
| Статус операции | Не теряется при прокрутке/возврате | Reload, несколько вкладок, отсутствие ложного успеха |
| Тема/доступность | Reflow и реальный mobile reader | Увеличение текста, keyboard/NVDA, обе темы |

Банковские шторка/свайп/биометрия/пять tabs не становятся средствами реализации. Если дальнейшее тестирование подтвердит проблему согласованного UI, следующий шаг — отдельный конкретный макет/дельта с согласованием владельца, затем feature-adr/OpenSpec по фактическому изменению. Само исследование не останавливает текущую реализацию.
