# Clipmkr. Действия в основном сценарии кабинета

25.11.2026, `main` `bb1f5b833fb6465b002404500ac77b9170f24e89`. `git diff --stat ed654d7216e4f4a76f81d7184ade309824ecb355...HEAD -- apps/web/src apps/web/public` пуст. Обязательная приёмка требует загрузить запись, воспроизвести результат и скачать файл (`docs/acceptance/core-cjm.md:8–13`).

Счёт начинается после входа. Активация — клик, тап или эквивалент с клавиатуры. Выбор и подтверждение файла в системном диалоге считаю одним логическим действием, число физических кликов в нём зависит от ОС. Скролл, ожидание хэша/рендера, автоматическую навигацию и системные диалоги сохранения не считаю. `N ≥ 1` — число доступных клипов одной записи.

| Цель | Текущий путь |
|---|---|
| Загрузить один файл и дождаться клипов | С `/dashboard` **2 активации Clipmkr + выбор файла в ОС**. «Выбрать файл» открывает диалог → выбор файла → «Создать клипы». Проверка файла, передача, успешное завершение, переход на запись и опрос `video.get` / `clip.list` каждые 5 секунд идут автоматически. После запуска **0 действий**. Это минимальный путь с явным запуском после проверки файла и возможностью посмотреть стоимость или изменить параметры перед запуском. `apps/web/src/app/dashboard/page.tsx:21–22`, `apps/web/src/app/upload/Uploader.tsx:123–139,147–172,177–203,222–247`, `apps/web/src/app/videos/[videoId]/VideoDetail.tsx:124–165`. |
| Просмотреть все готовые клипы | На открытой записи с уже выбранным готовым клипом **`2N−1`**. Для первого — Play, для каждого следующего — нажать строку «Фрагменты» и затем Play. Выбор меняет видимую карточку, предыдущий плеер ставится на паузу. Фильтра готовых, перехода на следующий с запуском и продолжения по окончании в кабинете нет. `apps/web/src/app/videos/[videoId]/VideoDetail.tsx:68–90,187–201`, `apps/web/src/app/clips/ClipCard.tsx:27–31,111–114`, `apps/web/src/app/globals.css:345`. |
| Скачать все готовые клипы | На открытой записи с уже выбранным готовым клипом тоже **`2N−1`**. Для первого — «Скачать», для каждого следующего — выбрать строку и нажать «Скачать». Кнопка вызывает `download(clip_id, title)`, затем `startClipDownload` открывает `/api/clips/{id}/file?download=1`. Массовое скачивание уже есть в гостевом пакете, в кабинете у записи его нет. `apps/web/src/app/videos/[videoId]/VideoDetail.tsx:187–201`, `apps/web/src/app/clips/ClipCard.tsx:77–81,119–121`, `apps/web/src/app/clips/useClipDownload.ts:4–25`, `apps/web/src/server/guest-page.ts:55–70,86–93`. |

Если открывать готовую запись из списка кабинета, просмотр и скачивание требуют ещё **1** активацию (`apps/web/src/app/videos/VideoList.tsx:12–17`). При первом открытии выбирается доступный клип, если он уже есть. При ожидании рендера существующий выбор сохраняется даже после появления другого готового клипа, поэтому с выбранной недоступной карточки нужно ещё **1** действие. Список содержит все фрагменты и показывает заголовок и длительность, без отбора по доступности. Например, при пяти готовых клипах и уже выбранном готовом просмотр всех и скачивание всех по отдельности требуют по **9** активаций. `apps/web/src/app/videos/[videoId]/VideoDetail.tsx:89–90,158,194–200`.

Два кандидата для согласования. Экономия рассчитана по исходникам, фактическое удобство требует проверки на задачах пользователя.

1. **«Скачать все готовые» в кабинете записи при `N ≥ 2`.** С `2N−1` до **1** активации Clipmkr на запуск скачиваний (9 → 1 при пяти клипах). Использовать модель существующего гостевого действия с отдельными MP4 и текущий `startClipDownload` кабинета с проверкой `available` и срока хранения. Существующий файловый маршрут повторно проверяет права и доступность. Доставка всех файлов одним нажатием зависит от разрешения браузера на несколько скачиваний, это ограничение отмечено в текущем гостевом интерфейсе. ZIP или новый серверный маршрут — отдельное расширение для возможного согласования. `apps/web/src/server/guest-page.ts:86–93`, `apps/web/src/app/clips/useClipDownload.ts:4–10`, `apps/web/src/server/screen.ts:116–130`, `apps/web/src/server/clip-file.ts:22–49,68–69`.
2. **«Следующий готовый» рядом с плеером, с запуском по нажатию.** Для последовательного просмотра всех доступных клипов с первого готового с `2N−1` до **`N`** активаций (9 → 5 при пяти). Использовать текущий порядок, признак доступности, `selectClip` с защитой черновика и тот же `<video>` с координацией паузы. Один пользовательский жест должен переключить клип и запустить плеер в Chromium/WebKit. Простая кнопка перехода с отдельным Play даст прежнее число действий. `apps/web/src/app/videos/[videoId]/VideoDetail.tsx:67–77,187–200`, `apps/web/src/app/clips/ClipCard.tsx:27–31,111–114`.

Оба кандидата относятся к результату одной записи. Текущая форма загрузки, проверки, платежи, квоты и гостевые права входят в контракты, которые требуется сохранить при возможном согласовании. Макеты и код в этом аудите не создавались.
