Задача: сохранить смысл действий в браузере в вертикальном клипе из конкретной предоставленной владельцем записи. До выбора компоновки pipeline, render и UI продукта не меняются.

## Наблюдение на настоящем медиа

Нужная запись найдена через текущую runtime binding и фактический `DATABASE_URL` web, read-only SQL: длительность 1646,6 с, исходный объект 135342652 байт, четыре готовых клипа. Использован только GET исходного объекта и существующего клипа в настоящем Cloud.ru S3. Подписанные URL, ключи объектов и пользовательские кадры в Git не включаются.

`ffprobe` подтвердил source H.264 1816×968 и текущий clip №1 H.264 1080×1920. Настоящий исходный кадр на 316,4730625 с содержит браузер примерно x0 y40 w1496 h886 и webcam x1496 y0 w320 h180. Кадр существующего клипа на +10,000 с показывает лицо, правый край окна и большую чёрную область; центральное действие браузера отсутствует.

Две эти точки не объявляются точно синхронными: выбранный source interval длится 52,531 с, готовый клип — 34,280 с; в продукте есть уплотнение пауз. Все три **предложения** используют один и тот же source frame, без генеративного изменения содержимого/лица. Подписи поверх — элементы макета, не цитата из расшифровки.

## Варианты и ограничения

| Вариант | Область исходника | При ширине360 CSS px | Компромисс |
|---|---|---|---|
| 01. Весь экран + PiP | browser1496×886 | символ20px →≈4,8px | Весь контекст; мелкий текст, лицо закрывает угол |
| 02. Работа + отдельное лицо | x320 y190 w930 h704 | символ20px →≈7,7px | Основная работа крупнее; рамка, боковая навигация и края потеряны |
| 03. Фокус на действии + лицо поверх браузера | x550 y100 w720 h720 | символ20px →10px | Деталь крупнее; начало длинных строк и окружение могут исчезнуть |

Размер20px — ориентир по визуально наблюдаемому исходному тексту, а не OCR-замер каждого символа. Расчёт масштаба не доказывает комфортное чтение человеком. Вариант01 — базовый для обсуждения; вариант03 — дополнительный ручной крупный план. Реальный алгоритм выбора области, слежение за действием, переходы и временная стабильность здесь не реализованы. До реализации необходим выбор владельца, затем соответствующий feature-adr план и проверки на движущемся видео.
