# Нехватка диска на действующем VPS: разбор и выполненная очистка

Дата: 3 ноября 2026. Проверен действующий сервер сайта и тестового стенда.
Переключение production на Cloud.ru не выполнялось.

## Исправление: выбран неверный сервер

После очистки владелец уточнил, что проблема места относилась к текущему серверу
сессии. Описанные ниже инвентаризация и удаления выполнялись по SSH на другом
сервере — VPS сайта. Это ошибка выбора цели: полученные там 20,72 ГиБ свободного
места не являются результатом очистки текущего сервера.

Повторная локальная проверка текущего сервера: доступно 66,04 ГиБ; Docker показывает
25 образов, из них девять без ссылок контейнеров, и около 36,58 ГиБ неиспользуемого
сборочного кеша, отмеченного как не разделяемый с образами. Это предварительные
оценки, а не выполненная очистка. Архив 112 образов с VPS сайта занимает здесь
4,64 ГиБ. Существующие рабочие образы текущего сервера не удалялись; импортированные
для проверки временные копии удалены после сверки.

Для дальнейших операций целевой сервер должен быть явно назван до удаления;
его hostname, адрес, файловая система и исходный замер места фиксируются в
приватной квитанции и сверяются с запросом владельца. Показания разных серверов
не подменяют друг друга. Ниже сохранён фактический протокол уже выполненных
операций на VPS сайта.

## Причина

На системном разделе около 98,3 ГиБ доступной файловой ёмкости размещены
несколько проектов: на момент проверки работали 64 контейнера. Расход связан
прежде всего со слоями образов и накопленными рабочими копиями. Пользовательское
медиа находится в удалённом S3; его удаление не требуется для этой очистки.

Первичная полная инвентаризация после очистки старых образов Clipmkr и его
временных каталогов, перед переносом старых журналов мониторинга:

| Категория | Занято, примерно |
|---|---:|
| Хранилище слоёв containerd | 39,8 ГиБ |
| Каталог Docker, включая тома | 5,5 ГиБ |
| Рабочие каталоги в `/home` | 17,8 ГиБ |
| Инструменты и история работы в `/root` | 7,2 ГиБ |
| Временные каталоги `/tmp` | 5,1 ГиБ |
| Системные журналы | 2,3 ГиБ |
| Существующие резервные копии в `/var/backups` | 1,8 ГиБ |
| Системные программы в `/usr` | 3,4 ГиБ |

Из 39,8 ГиБ containerd около 30,7 ГиБ приходится на распакованные snapshots,
9,1 ГиБ — на хранилище содержимого образов. В рабочих каталогах около 10,4 ГиБ
занимают дополнительные Git worktrees. История сессий инструментов сохранена.

Docker показывал 151 образ, из них 39 используемых. Его оценки размеров образов
и build cache перекрываются из-за общих слоёв: складывать их нельзя. Из
показанных 8,8 ГБ build cache освобождаемыми были только 266 МБ. Признак
«не используется» у Docker-тома сам по себе не разрешает его удалять.

Крупных удалённых файлов, продолжающих занимать место через открытые дескрипторы,
не найдено. Дополнительно подтверждён резерв ext4 около 5 ГиБ — стандартные
5% блоков. Резерв файловой системы не изменялся.

## Что выполнено

1. Удалены четыре старых образа Clipmkr и 50 старых тегов N5, не используемых
   ни одним работающим или остановленным контейнером. Применялось удаление
   точных тегов без `--force`; текущие и необходимые контейнерам образы сохранены.
2. Семь старых временных каталогов Clipmkr перенесены в приватный архив на
   управляющем сервере. Перед удалением проверены отсутствие bind mounts и
   процессов с рабочим каталогом внутри них, чистота Git worktrees, целостность
   gzip и состав архива. Два worktrees с изменениями оставлены на месте.
   Полное восстановление этих временных каталогов не заявляется.
3. Восемь закрытых журналов `atop` за 19–26 октября перенесены в отдельный
   приватный архив. Все файлы архива полностью прочитаны и сверены по SHA-256
   с оригиналами. Непосредственно перед удалением повторно проверены хеши и
   отсутствие открытых дескрипторов. Последние журналы, текущий открытый файл
   и настройка хранения мониторинга сохранены.

Результат первых трёх этапов: освобождено суммарно около **6,2 ГиБ**, доступно около **9,7 ГиБ**
вместо примерно 3,6 ГиБ до очистки. Показания меняются по мере работы сервисов.
После каждого этапа проверены идентификаторы и состояния всех контейнеров,
их образы, время запуска и число перезапусков: изменений не обнаружено.
Базы, Docker-тома, исходное медиа, чужие рабочие каталоги и резервные копии
в `/var/backups` не удалялись. Общий `docker system prune` не применялся.

Приватные перечни, архивы, контрольные суммы, SSH-параметры и детальные
инвентаризации хранятся вне репозитория с ограниченными правами. Документ
содержит только агрегаты и описание действий.

## Дополнительная очистка 112 образов по согласованию владельца

После явного согласия владельца повторно проверены 112 выбранных образов:
ни один не использовался работающим или остановленным контейнером. До удаления
весь набор с тегами сохранён напрямую на управляющий сервер, без промежуточного
архива на исходном VPS. Приватный архив занимает **4,64 ГиБ**, имеет права `0600`;
зафиксирован SHA-256, проверена целостность gzip.

Выполнен настоящий импорт архива в отдельный временный Docker daemon с собственным
пространством имён containerd. Совпали все **112 идентификаторов образов и их теги**.
Контейнеры из архива не запускались. После проверки временные импортированные образы
удалены, проверочный daemon остановлен; постоянные контейнеры управляющего сервера
не изменились. Сам архив и приватные квитанции сохранены.

На исходном VPS образы удалены точными ссылками через `docker image rm --no-prune`,
без `--force` и общей очистки. Все 112 исходных идентификаторов исчезли. Проверка
после удаления подтвердила сохранность состояний **68 контейнеров**, включая время
запуска, PID, образы и счётчики перезапуска, и неизменность набора **77 томов**.
Основной и тестовый сайты до и после операции отвечали HTTP 200 на `/health`.

Фактически дополнительно освободилось **11,0 ГиБ**: доступное место выросло
с **9,71 до 20,72 ГиБ**. Это измерение файловой системы, а не сумма оценок Docker.
С учётом прежних этапов за время диагностики освобождено около **17,2 ГиБ**.
В финальной выдаче Docker осталось 66 записей образов, из них 39 используемых;
27 неиспользуемых записей с идентификаторами вне исходного списка дополнительно
не удалялись.

## Ограничения и дальнейшее сопровождение

20,7 ГиБ — результат очистки, а не автоматический допуск к выпуску. Перед
доставкой требуются фактические размеры архивов, новых слоёв, места распаковки,
сохраняемой версии для отката и временных файлов обработки видео. Недостаток
запаса должен останавливать доставку до изменения работающего приложения.

Старый `scripts/cleanup-our-docker.sh` для этой задачи не запускался: он содержит
общую очистку build cache и удаление тестовых томов. Сейчас тестовая БД содержит
сохраняемые данные, поэтому такой сценарий к действующим стендам неприменим.

Для этого VPS полезно хранить ограниченное число неиспользуемых образов каждого
проекта и архивировать завершённые рабочие копии после проверки изменений.
Автоматическое расписание очистки и глобальные изменения Docker не вводились.
Если фактический запас под новый выпуск окажется недостаточным, нужен отдельный
план расширения диска либо переноса проверенных неактивных артефактов; пользовательские
данные и текущие версии остаются сохранёнными.

## Уточнение: сколько занимает именно Clipmkr

Отдельная readonly сверка на том же VPS: 19 контейнеров, относящихся к N5/Clipmkr.
Включены основной и тестовый стенды, поддержка и два сохранившихся старых MinIO.
Используются семь разных образов; одинаковые образы нескольких воркеров повторно
не считаются.

| Категория Clipmkr | Размер, примерно |
|---|---:|
| Образы: распакованные слои, сжатое содержимое и метаданные, без повторов внутри набора | 3,50 ГиБ |
| Именованные тома, включая БД и старые данные MinIO | 1,20 ГиБ |
| Журналы контейнеров | 0,15 ГиБ |
| Изменяемые слои контейнеров | менее 1 МиБ |
| **Итого** | **4,9 ГиБ** |

Сумма размеров семи образов до устранения общих слоёв — 3,72 ГиБ. Для оценки
3,50 ГиБ сопоставлены Docker history и OCI config, а распакованные слои и сжатые
blobs посчитаны по уникальным digest. Это оценка набора образов, а не обещание
освободить весь этот объём при удалении проекта: часть образов и слоёв нужна
также другим проектам. Общий build cache отдельно целиком Clipmkr не приписывается.
Рабочие Git-копии и приватные архивы в эту оценку Docker не включены.

Около 0,8 ГиБ томов приходится на сохранившиеся данные старого MinIO. Проверенные
web/STT/render сервисы используют Cloud.ru S3; старые MinIO и их данные в этой
сверке не удалялись. Общие 45 ГиБ Docker/containerd из основной таблицы относятся
ко всем проектам VPS, а не только к Clipmkr.
