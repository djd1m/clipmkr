# Независимое ревью: временный cross-model режим

Решение владельца 2 ноября 2026: «пока claude code недоступен вместо cross-familly подхода
cross-model подход, в рамках которого проверяем не теми моделями что кодили и в сессии
без контекста кодинга». Это действующее исключение из прежнего OWN-002 в CLAUDE.md.

1. Кодирование и проверка выполняются разными моделями; фиксируются точные model ID.
2. Проверяющие работают в новых сессиях без истории кодирования. Для агентов используется
   `fork_turns=none`; модель проверки задаётся явно.
3. Сначала проверяющий читает согласованные требования/OpenSpec, ADR, архитектуру и план.
   Он самостоятельно изучает реализацию и необходимые тесты. Прежние ревью, заявления
   автора об успехе и отчёты завершения не являются входными доказательствами.
4. Отчёт содержит конкретные нарушения, severity, файл/строку, сценарий и границы проверки.
   Отсутствие подтверждения E2E не подменяется заявлением о дефекте либо о прохождении.
5. Исправление находки получает независимую повторную проверку другой моделью.
6. После восстановления Claude Code возвращаемся к cross-family по отдельному явному
   обновлению статуса; недоступный или неавторизованный CLI не считается проведённым ревью.

Для новых запусков действует [матрица моделей](model-matrix.md), обновлённая владельцем
04.11.2026: автор `gpt-6.1-sol high`, независимая проверка `gpt-6-astra xhigh`.
Уровень рассуждения одной модели не заменяет различие моделей.

Первые чистые сессии текущей работы наследовали модель родителя: они независимы по контексту,
но без подтверждённого различия моделей не маркируются cross-model. Последующее финальное
ревью запускается с явно заданной `gpt-6-astra`; исправление восстановления complete поручается
`gpt-6.1-terra`, чтобы различие модели для этого изменения было проверяемым.
