# Независимое cross-model ревью плана Cloud.ru

Дата: 03.11.2026. Проверенный документ: [план](../2026-11-03-cloudru-production.md).
SHA-256: `b414bf99cb99d9b8f24b8473522de567571ecaf7451a0ffd0999d6bd5b44cb8c`.
Этот SHA относится к полной версии, которую независимо проверили обе модели.
После проверки публикации конкретные адреса, UUID и имена ресурсов заменены условными обозначениями.
Полный оригинал и соответствия сохранены в закрытом операторском архиве вне Git; логика плана не менялась.
SHA-256 текущей публичной версии: `7871d5a40154cfabe1843b5633b64e6c4e5bab591b1c2d0f70de656870809173`.
Содержательные выводы рецензентов относятся к исходному плану; это не новая аттестация SHA после редактирования.

Рой: две новые сессии без coding-контекста:
- `/root/cloud_plan_arch`, запрошенная модель `gpt-6-astra`: архитектура, данные, reconciliation/CJM.
- `/root/cloud_plan_ops`, запрошенная модель `gpt-6.1-sol`: эксплуатация, edge/webhooks, restore/rollback.

Третий агент не запустился из-за лимита потоков и не включён в результаты.
ID моделей и fork_turns=none — metadata вызова инструмента, не независимая runtime attestation.
Автор плана — координатор. Рецензенты сначала получили черновик и требования, затем сами
изучили исходники и официальные источники; прежние coding-review отчёты не были доказательствами.
Затем каждый перепроверил замечания другой модели по первичным источникам. После правок обе
модели повторно прочитали общий кандидат и подтвердили один SHA. Никакая модель не исправляла
проверяемый продукт. Текущая работа — планирование и чтение, не изменение реализации.

Основные исправления: ранняя изоляция клона от production S3, полный freeze всех писателей,
согласованный PG/Redis restore и reconciliation, судьба второй БД, HMAC-сессии и ссылки,
реальный test-webhook, доверенный XFF, TLS/DNS без proxy-loop и обратный перенос после новых записей.
Уточнения перепроверки: внешний test-route существует; Cloud backup зависит от конкретного
сервиса/API; Suspended несовместим с текущим erasure; успешный старый migrator не доказывает
rollback compatibility. Возможные зависимости helpdesk учитываются отдельно.

Оба финальных reviewer не нашли блокирующих пробелов **плана**, но не подтвердили готовность
площадки. Фактические STOP-gates остаются в документе. Сохранённые отчёты не являются
разрешением на migration/resize/DNS, успешным E2E на Cloud.ru или доказательством сохранности
непрочитанной целевой БД. Ранее подтверждённый /health200 не подменяет такую проверку.

Через Hub успешны live vm_get/vm_list/disk_list/list_security_groups. Пробный vm_exec отклонён
mcp-safe из-за отсутствия действующей разрешённой VM-session; guard не обходился.
Секреты, полные API-ответы, edge-конфиги, данные БД, backup и подписанные URL в Git не включены.
