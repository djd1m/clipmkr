## Проверенные неоднозначности

1. **Freeze и background writers.** Формулировка «freeze касается worker/watchdog» не читается как немедленная остановка посреди drain, поскольку следующий абзац задаёт последовательность: сначала ограничить ingress, дождаться принятых задач, закончить commits, затем остановить все writers. P4 выполняется без web/workers; P5 запускает только нового владельца. Во время реализации классифицировать маршруты по фактическим записям, а не по HTTP-методу: read-like GET может писать статистику или состояние оплаты. Это уточнение команды барьера, не незакрытый blocker текста, который уже требует fence всех writers.
2. **Cloned S3.** G2 запрещает запуск восстановленного web с production deletion rights; E2E credentials принадлежат только изолированному хранилищу. Existing n5 dataset не заменяется production clone. Negative IAM тесты ограничены operator canary, пользовательский Delete не предлагается.
3. **HMAC.** Неизменный production secret сохранён вместе с таблицей session; stage отделён, а тест c/n5 не принимается за сохранение clipmkr.ru cookie. §5 добавляет guest tickets/referral cookie и срок старых подписей.
4. **R1/R2.** Новые фоновые изменения тоже переводят в R2. Поэтому запуск нового web может немедленно исчерпать R1 даже без браузерного POST; формулировка §7 это явно учитывает. Если отсутствие изменений доказать невозможно, применим R2/roll-forward, а не предположение об R1.
5. **Вторая БД.** Обещание сохранения данных не подменено простым backup: G1 явно требует решение о доступе и истории существующих Cloud.ru пользователей. До решения STOP.
6. **Production off и тестовая оплата.** §5 сохраняет test endpoint на test backend и не считает main404 успешной оплатой; общая CJM-приёмка не разрешает включать настоящие списания.
