## Действующие правила исполнения

1. Ближайший результат — проверенный пользовательский сценарий тестовой оплаты на clipmkr.ru. Следом — приёмка кабинетов трёх ролей; Cloud.ru только после установленной ручной приёмки.
2. Перед каждым блоком назвать результат, ограниченный объём, исполнителя и критерий завершения. Исправления пишет gpt-6.1-sol high, независимую проверку выполняет gpt-6-astra xhigh согласно матрице проекта. Для этой организационной записи дополнительные агенты не запускаются.
3. Служебная задача включается в критический путь только с объяснением, какой шаг приёмки она блокирует. Отдельно фиксируются дефекты продукта, инструмента проверки и неопределённость требования.
4. Если за 30 минут нет нового проверяемого результата, сообщить причину и пересмотреть способ достижения результата в пределах согласованного объёма. Это контрольная точка, а не повод отменить защиту, требования или независимый QE.
5. Повтор полного прогона допускается после изменения кода, новых данных или конкретной незакрытой проверки. Не повторять зелёные проверки для создания видимости прогресса.
6. Статус содержит: полученный результат со ссылкой, фактически работающий процесс либо его отсутствие, один ближайший шаг, блокеры. Срок даётся с зависимостями; время ожидания решения не выдаётся за выполнение.
7. Согласования запрашиваются только для решений, которых ещё нет. Разрешение ручного cross-model QE уже получено; повторять запрос на каждый цикл нельзя. Изменение требования автоматически из этого не следует.
