## ADDED Requirements

### Requirement: TEST предупреждение расположено у финансового действия
Система SHALL показывать тестовую оплату и отсутствие реальных списаний около кнопок
покупки пакетов и прежнего тарифа только при testMode=true. Existing TEST badge сохраняется.

#### Scenario: Покупатель в TEST-режиме
- **WHEN** пользователь открывает /upgrade в TEST-режиме
- **THEN** около каждой кнопки оплаты явно написано, что оплата тестовая и реальных списаний нет

#### Scenario: Обычный посетитель
- **WHEN** посетитель открывает лендинг или вход даже при TEST-конфигурации
- **THEN** глобальное финансовое предупреждение не показывается

### Requirement: Учебные финансовые расчёты маркированы
Система SHALL перед статистикой блогера и финансовыми расчётами владельца показывать
TEST, отсутствие реальных списаний и учебный характер выручки/расчётов только при
существующем server config payments.mode=live и testMode=true. Это включает достижимую
legacy-статистику на /dashboard для is_blogger != true: предупреждение находится внутри
существующего details «Партнёрская программа» перед PartnerPanel; общего баннера нет.

#### Scenario: Блогер или владелец смотрит TEST-расчёты
- **WHEN** авторизованная роль открывает свой экран статистики в TEST-режиме
- **THEN** до финансовых показателей видит явное предупреждение учебного характера данных

#### Scenario: Обычный аккаунт или владелец открывает legacy-статистику
- **WHEN** аккаунт с is_blogger != true открывает «Партнёрская программа» на /dashboard в TEST-режиме
- **THEN** перед выручкой внутри этого блока видит TEST, отсутствие реальных списаний и учебный характер расчётов

#### Scenario: Блогер открывает личную ссылку без финансовой статистики
- **WHEN** блогер открывает summary личной ссылки на /dashboard
- **THEN** новый общий финансовый баннер не добавляется; финансовая статистика на отдельном экране остаётся маркирована

#### Scenario: Среда без TEST-платежей
- **WHEN** payments off либо live/non-test
- **THEN** предупреждение учебного характера данных не показывается

### Requirement: Финансовое поведение сохраняется
Система SHALL сохранить checkout policy, provider/webhook routes, суммы и права доступа,
existing account TEST badge и конфигурацию Cloud без изменений.

#### Scenario: Ограниченное UI исправление
- **WHEN** перенос предупреждений выполнен
- **THEN** все действия оплаты и статистики продолжают использовать существующие обработчики
