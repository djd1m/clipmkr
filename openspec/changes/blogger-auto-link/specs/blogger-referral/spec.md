## ADDED Requirements

### Requirement: Блогер получает готовую стабильную личную ссылку

Система MUST автоматически выдавать назначенному блогеру личную реферальную ссылку
и показывать её открыто в кабинете рядом с проектами. Блогер MUST иметь возможность
скопировать полный URL без придумывания кода. Система MUST переиспользовать самый ранний
существующий код аккаунта, сохранять прежние ссылки/атрибуции и не создавать дубликаты
при повторе/параллельном первом открытии. Публичный origin MUST браться из конфигурации.

#### Scenario: Первый вход блогера
- **GIVEN** владелец назначил аккаунту статус блогера и личного кода ещё нет
- **WHEN** блогер открывает собственный кабинет
- **THEN** получает одну личную ссылку и «Копировать ссылку» без ручного поля кода
- **AND** ссылка принадлежит блогеру, а не владельцу, назначившему роль

#### Scenario: Прежний код и повторное открытие
- **GIVEN** у блогера уже есть один или несколько кодов
- **WHEN** он обновляет страницу или открывает кабинет одновременно в двух вкладках
- **THEN** личный адрес использует самый ранний код и новые коды не появляются
- **AND** остальные кампании, статистика и атрибуции сохраняются

### Requirement: Автоматическая выдача сохраняет права и блокировки

Автоматический путь MUST проверять активный аккаунт и статус блогера на сервере.
Монтирование компонента обычного пользователя MUST NOT создавать партнёрский код.
Блокировка MUST NOT обходиться новым активным кодом, перезагрузкой или повтором запроса.
Загрузка, ошибка, повтор и блокировка MUST быть различимы; ошибка копирования MUST
оставлять возможность выделить полный адрес вручную. Чужая статистика MUST быть недоступна.

#### Scenario: Обычный аккаунт
- **GIVEN** у аккаунта нет статуса блогера
- **WHEN** открывается кабинет или напрямую вызывается автоматический API
- **THEN** автоматическая личная ссылка ему не создаётся

#### Scenario: Прежняя ссылка заблокирована
- **GIVEN** личный код заблокирован
- **WHEN** блогер открывает кабинет или повторяет запрос
- **THEN** показана блокировка, сохранена статистика, новая активная ссылка не создаётся

#### Scenario: Ошибка загрузки или clipboard
- **GIVEN** данные ссылки не загрузились или браузер отказал в копировании
- **WHEN** блогер видит результат действия
- **THEN** показана ошибка с повтором загрузки либо возможностью выделить URL вручную

#### Scenario: Мутация и конкурентное изменение роли
- **GIVEN** сервер подтвердил блогера при рендере страницы, но роль могла измениться
- **WHEN** выполняется POST автоматической выдачи с пустым объектом
- **THEN** активность аккаунта и роль проверяются повторно под блокировкой account
- **AND** обычный или удаляемый аккаунт получает отказ без создания partner/partner_code
- **AND** GET и SSR остаются без побочного эффекта выдачи кода

#### Scenario: Фильтр кампаний и другая заблокированная кампания
- **GIVEN** у блогера есть самый ранний личный код и дополнительные кампании
- **WHEN** выбрана статистика другой кампании либо одна из кампаний заблокирована
- **THEN** личный адрес остаётся самым ранним кодом и новый код не создаётся
- **AND** блокировка и история каждой кампании сохраняются

#### Scenario: Заблокированный личный код в раскрытом списке кампаний
- **GIVEN** personal mode, самый ранний личный код blocked и другая active кампания
- **WHEN** блогер раскрывает статистику и список кампаний
- **THEN** копирование blocked личного кода недоступно во всех представлениях, включая этот список
- **AND** статистика обоих кодов, действия другой active кампании и поведение обычного mode сохраняются

#### Scenario: Два блогера получают только собственные ссылки и статистику
- **GIVEN** два активных блогера A и B без кодов, с разными действительными сессиями
- **WHEN** они последовательно и конкурентно вызывают автоматическую выдачу, затем повторяют запрос
- **THEN** каждый получает свой стабильный id/code, различный между A и B и принадлежащий его account в БД
- **AND** dashboard каждого содержит только его коды, запрос чужого code_id получает 403 без выдачи чужих данных
