## ADDED Requirements

### Requirement: Реальная сессия при регистрации
Регистрация SHALL выдавать cookie успешного входа только при созданной действительной сессии.

#### Scenario: Новый адрес
- **WHEN** пользователь регистрирует новый email с допустимым паролем
- **THEN** создаются один аккаунт, сессия и применимый однократный бонус, открывается кабинет

### Requirement: Повторная регистрация
Обновлённая форма согласует register outcome заголовком `X-Clipmkr-Registration: outcomes-v1`. Через этот контракт существующий active аккаунт SHALL входить только с верным текущим паролем. Повтор SHALL NOT менять пароль, роль, баланс или источник привлечения.

#### Scenario: Верный пароль
- **WHEN** существующий active пользователь через обновлённую форму с outcome-header отправляет регистрацию с верным паролем
- **THEN** создаётся действительная сессия, видимо сообщение «Аккаунт уже существует. Вы вошли», выполняется автоматический безопасный переход без signup/повторного бонуса

#### Scenario: Неверный пароль
- **WHEN** существующий active пользователь отправляет регистрацию с неверным паролем
- **THEN** сообщается о существующем аккаунте, доступны вход/восстановление, email сохранён, новой сессии нет

#### Scenario: Конкурентная вставка
- **WHEN** два запроса пытаются зарегистрировать один email одновременно
- **THEN** один аккаунт и бонус, проигравший INSERT обрабатывается по тому же контракту без изменения учётных данных

### Requirement: Сохранение защит
Регистрация SHALL сохранять rate-limit/Origin/body/password/cookie/next guards. Login и forgot SHALL сохранять прежние приватные отказы.

#### Scenario: Удаляемый аккаунт или неподтверждённая сессия
- **WHEN** аккаунт не active либо действительная сессия не создана
- **THEN** нет успешного входа, сообщения об удалении и cookie-пустышки

#### Scenario: Ошибка сети или сервера
- **WHEN** запрос регистрации не подтверждён действительным успешным ответом
- **THEN** форма показывает ошибку и допускает повтор без ложного состояния авторизации

### Requirement: Переходная совместимость формы
Старый клиент без точного outcome-header SHALL NOT получать session при повторной регистрации. Это явное исключение из automatic existing-login для старой формы; обычный login остаётся доступен.

#### Scenario: Старая открытая вкладка
- **WHEN** старый клиент без outcome-header отправляет повторную регистрацию active аккаунта, в том числе с верным паролем
- **THEN** сервер возвращает409 с понятным сообщением, без новой сессии/cookie успеха; старый клиент не вызывает attribution/signup, пользователь может войти обычным способом или обновить форму

#### Scenario: Новый адрес в старой форме
- **WHEN** старый клиент отправляет регистрацию нового email
- **THEN** обычное создание аккаунта и действительной сессии сохраняется
