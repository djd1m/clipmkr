# Spec Delta

## Purpose

Изолированный TEST callback позволяет проверять оплату на QA-копии Clipmkr, сохраняя неподтверждёнными чужие события и не меняя действующую production обработку.

## ADDED Requirements

### Requirement: Отказ чужому финансовому событию до записи
QA callback MUST отвечать503 на проверенное TEST уведомление оплаты или возврата, если его пара intent/payment не принадлежит локальному QA состоянию, без изменения финансовых данных и ключей повторности.

#### Scenario: Позднее source событие и повторы
- **WHEN** проверенное TEST событие отсутствует в локальных QA намерениях либо provider payment ID не совпадает, включая повторные и параллельные доставки
- **THEN** каждая доставка получает503, а события, платежи, начисления, намерения и балансы QA не изменяются

### Requirement: Подлинность и ограниченный QA профиль
QA callback MUST сохранять штатные проверки тела, IP и повторного чтения провайдера; принимать финансовые события только в явно изолированном QA TEST профиле.

#### Scenario: Недопустимый профиль
- **WHEN** выбран production binding, выключенный provider или live payment mode
- **THEN** QA callback отвечает503 до обращения к финансовому consumer

#### Scenario: Поддельное уведомление
- **WHEN** отправитель или полученные от провайдера сведения не проходят существующие проверки
- **THEN** штатный отказ сохраняется и финансовых записей нет

### Requirement: Локальная идемпотентность и завершение после закрытия checkout
QA callback MUST обрабатывать известную локальную оплату и возврат штатным идемпотентным механизмом, в том числе после отзыва разрешения создавать новые checkout.

#### Scenario: Разрешение создавать оплаты отозвано
- **WHEN** новое оформление закрыто, но TEST provider сохранён и приходит событие уже привязанной локальной оплаты
- **THEN** доставка завершается; повтор не создаёт второго начисления

#### Scenario: Событие пришло до привязки provider ID
- **WHEN** локальный intent существует, но его provider payment ID ещё не сохранён
- **THEN** доставка получает503 без записи; после штатной привязки повтор может обработаться

### Requirement: Совместимость основного обработчика
Изменение MUST сохранять поведение canonical production endpoint, финансовые операторы и число путей изменения тарифа.

#### Scenario: Основной endpoint и неподдерживаемое событие
- **WHEN** вызывается основной endpoint либо приходит штатно игнорируемый тип события
- **THEN** прежняя семантика основного endpoint и ignored200 без финансовых записей сохраняется

### Requirement: Раздельная приёмка зависимости и переноса
Проверка QA guard MUST оставаться компонентной зависимостью исходного `qe-primary-01`; она не разрешает merchant/DNS/source изменения и не заменяет независимую closure родительской миграции.

#### Scenario: Компонентные тесты прошли
- **WHEN** guard проверен на локальном provider fixture и PostgreSQL
- **THEN** real merchant retry/UI E2E остаются отдельными проверками parent; прежние reviewer conditions и циклы сохраняются
