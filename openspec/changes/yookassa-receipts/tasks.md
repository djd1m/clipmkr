# Задачи реализации

OpenSpec хранит требования и этот список выполненных изменений. Авторитетный исполняемый план, независимые gates/QE и доставка находятся в features/yookassa-receipts. Checkbox не является receipt или разрешением публикации.

## 1. Контракт

- [ ] 1.1 Завершить требования, reuse, ADR и архитектуру; проверить точную связь с OpenSpec и готовность native QCSD в feature-adr.

## 2. Сборка данных и повторность

- [ ] 2.1 Передавать доверенные сведения покупателя и пакета; проверить запрет клиентской подмены и точное равенство сумм handler/provider тестами.
- [ ] 2.2 Сохранять исходные фискальные данные намерения для повторов; проверить реальным PostgreSQL, в том числе конкуренцию, неизменяемость и старые намерения.

## 3. Настройки и интеграция

- [ ] 3.1 Добавить явные фискальные настройки без угаданного НДС; проверить всю цепочку environment→runtime→provider и отказ при неполных значениях.
- [ ] 3.2 Передавать receipt в существующий запрос ЮKassa; проверить фактическое HTTP-тело, ошибки и повтор с тем же ключом через локальный contract server, сохранив webhook/начисления.
- [ ] 3.3 Обновить документацию настроек и ограничения; выполнить целевые тесты, build/typecheck/lint и code/spec anti-drift на конечных байтах.
