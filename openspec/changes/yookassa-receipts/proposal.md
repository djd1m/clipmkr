# Передача данных чеков ЮKassa

## Why

Боевой магазин владельца использует «Чеки от ЮKassa». Существующий адаптер создаёт платёж без receipt; для этого магазина требуется передать сведения о покупателе и позиции одновременно с платёжным запросом. Владелец поручил добавить недостающий блок10.11.2026.

## What Changes

- Передача данных чека через текущий checkout и адаптер ЮKassa без новой формы.
- Данные покупателя и пакета поступают из доверенных серверных источников; клиент не задаёт получателя, цену или налоговые реквизиты.
- Явная настройка фискальных параметров без угадывания НДС. Рабочее значение ожидает подтверждения владельца.
- Проверка точной суммы, повторов и отказов с сохранением существующего тестового режима, начислений и webhook-проверок.

## Capabilities

### New Capabilities

- `payment-receipts`: передача фискальных данных при создании платежа за доступ к Clipmkr.

### Modified Capabilities

Нет: в текущем корне OpenSpec inventory specs пуст. Это аддитивный журнал требований существующего продукта, а не декларация отсутствия платежей.

## Impact

Текущий серверный checkout, provider interface/ЮKassa adapter, доверенная сборка данных и настройки, адресные тесты и документация. Точный design/план/gates и динамическая приёмка хранятся в features/yookassa-receipts. Эта дельта не разрешает реальные списания, изменение merchant-настроек, Cloud.ru или DNS.
