## ADDED Requirements

### Requirement: Сохранность переноса
Перенос MUST сохранять все аккаунты, права, финансовую историю, рефералов, записи, клипы, ссылки и обращения/вложения поддержки без объединения аккаунтов и повторных начислений.

#### Scenario: Восстановленный срез
- **WHEN** восстановлена согласованная резервная копия
- **THEN** схема, строки всех таблиц и согласованные агрегаты совпадают; исходная и локальная базы сохранены отдельно

### Requirement: Единственный писатель
В каждый момент MUST существовать только один действующий комплект писателей перенесённого экземпляра, включая фоновые задачи и webhook.

#### Scenario: DNS-кеш старого адреса
- **WHEN** клиент обращается к прежнему IP после переключения
- **THEN** запрос обрабатывает новый экземпляр через relay либо пользователь видит согласованное обслуживание; старая база не принимает независимые записи

### Requirement: Проверки до переключения
Перенос MUST пройти проверку входа, загрузки, нарезки, просмотра, скачивания, почты, трёх ролей и TEST-платежей до ручного согласования DNS.

#### Scenario: Непройденная проверка
- **WHEN** тест не выполнен или не прошёл
- **THEN** результат остаётся открытым, DNS не переключается и реальные списания не включаются

### Requirement: Откат без потери новых записей
Откат MUST сохранять всю принятую после переключения историю.

#### Scenario: На новом сервере появились записи
- **WHEN** требуется вернуть старый сервер после новых регистраций, заданий или webhook
- **THEN** writers останавливаются и переносится актуальное состояние либо сохраняется единственная актуальная БД; возврат старого snapshot запрещён

### Requirement: Изолированный QA TEST callback

QA MUST отклонять чужое проверенное TEST payment/refund событие503 до финансовых записей и сохранять завершение собственных intent после закрытия новых checkout. Для этого допускается только отдельный QA web image из исходной source base с проверенным guard patch; production handler, source и workers не меняются.

#### Scenario: Позднее source событие пришло в QA
- **WHEN** verified notification не имеет точной локальной пары intent/provider payment ID
- **THEN** прямой QA TEST route отвечает503 при каждом повторе, без payment event/payment/grant writes; callback остаётся закрытым до parent independent closure и merchant допуска

#### Scenario: QA checkout разрешение отозвано
- **WHEN** приходит событие уже привязанной локальной QA оплаты при сохранённом TEST provider
- **THEN** штатная идемпотентная обработка завершается без повторного начисления

### Requirement: Данные до платёжной приёмки

По уточнению владельца09.11 система MUST сначала сохранить и перенести необходимые базы на целевой VPS, затем проверять оплату на перенесённой версии. Истории main, поддержки и legacy сохраняются раздельно; исторические финансовые аномалии не исправляются при копировании.

#### Scenario: Историческая TEST оплата записана в другом хранилище
- **WHEN** сверка обнаруживает main intent и legacy payment без соответствующего начисления
- **THEN** оба набора данных сохраняются и проверяются без слияния или финансового исправления; это не блокирует безопасное копирование, а платёжная приёмка выполняется после подготовки данных

#### Scenario: Завершено предварительное копирование
- **WHEN** источник ещё принимает записи
- **THEN** копия явно помечается предварительной; финальный согласованный срез и единственный writer остаются обязательными, DNS переключается только после отдельного разрешения
