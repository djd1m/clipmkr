# Показ реферального приглашения при регистрации

Переход по ссылке сохраняет источник на сервере, но скрытый пустой optional-блок вынуждает пользователя вручную извлекать код. Владелец согласовал макет `docs/research/referral-registration-ux/mockup.html`, SHA256 `040a988b2881e0e287e42d0f33deff8a9775cd7480d96eca977de576773b8315`, ответом «Да, реализовать этот макет».

Изменение: безопасный SSR display-код, раскрытое редактируемое поле, сохранение source и обе строки утверждённого notice с фактически применённым публичным кодом из серверного результата. Аддитивное `applied_code` связывается с записанным partner_code_id; stale SSR/input не используются как подтверждение. Сквозная приёмка проверяет одну регистрацию в канонических проекциях блогера и владельца на том же synthetic пути. Политика first-touch/guest/explicit/existing, `/r` 404, финансовый учёт, схемы и внешние интеграции сохраняются. Execution authority: `features/referral-registration-prefill/`; этот ledger сам по себе не разрешает coding и не удостоверяет gates.
