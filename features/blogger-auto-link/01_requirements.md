# Личная ссылка блогера — требования к реализации

Дата: 05.11.2026. Макет согласован владельцем; см. `owner-approval.md`.
Реализация разрешена по порядку, после настоящих feature-adr gates.
Источник: «блогеру будет неудобно самому придумывать ссылку самому — сделай так чтоб она
генерилась автоматом и он просто её отправлял своим подписчикам».
Дельта: `openspec/changes/blogger-auto-link/specs/blogger-referral/spec.md`;
Исходная ревизия макета: `18e4fa98e72fd8bdc84287d6c7495b4e3410b907`.
Текущая дельта OpenSpec и её точный SHA-256 закреплены в `requirements-revision.json`.

## Участники

Блогер входит в собственный аккаунт, копирует ссылку и смотрит свою статистику.
Подписчик переходит по действующему `/r/<code>`. Владелец назначает роль и принимает
макет; назначение роли другому аккаунту не означает создание ссылки владельца для него.

## Функциональные требования

- **FR-1 MUST.** Given назначенный блогер без кода, when открывает кабинет,
  then видит компактную открытую карточку готовой ссылки рядом с загрузкой/записями,
  без поля кода и «Создать ссылку». На desktop — справа от загрузки, на mobile — после
  её действий и до последних записей. Основное действие загрузки остаётся на первом экране.
- **FR-2 MUST.** Given активная ссылка, when нажато «Копировать ссылку», then копируется
  полный URL с доступным статусом; при отказе clipboard — честная ошибка и ручное выделение.
- **FR-3 MUST.** Given прежние коды, when повторный вход/обновление/конкурентные запросы,
  then сохраняется самый ранний код, другие URL/атрибуции/кампании и статистика не теряются;
  новые дубликаты не создаются, ротация и переименование в личном блоке не предлагаются.
- **FR-4 MUST.** Given обычный/удаляемый аккаунт, when mount/API-вызов, then автоматический
  код не создаётся. Права активного блогера проверяются сервером. Закрытый details обычного
  пользователя не должен получать скрытый побочный эффект от рендера.
- **FR-5 MUST.** Given заблокированный код/ограничения антифрода, when открытие/повтор,
  then новая активная ссылка не создаётся; показываются блокировка и прежняя статистика.
  В personal mode копирование blocked личного кода недоступно во всех представлениях,
  включая раскрытый список кампаний; другая active кампания и обычный mode сохраняют действия.
- **FR-6 MUST.** Given запрос не окончен, then URL/копирование не показаны готовыми.
  При ошибке видны объяснение и «Повторить», использующее тот же идемпотентный путь.
- **FR-7 MUST.** Given роль назначена владельцем, then ссылка принадлежит блогеру,
  чужая статистика недоступна; публичный origin берётся из существующей конфигурации.
  Для двух активных блогеров A/B с разными сессиями последовательная и конкурентная выдача
  возвращает разные собственные id/code, стабильные при повторе; DB owner совпадает с сессией.
  Dashboard каждого содержит только его коды, чужой code_id даёт 403 без чужих данных.

## Нефункциональные требования

Обе существующие компоновки и нейтральные палитры с зелёным акцентом, без синего.
390/1440 px и reflow 320 px/текст 200%; действия от 44 px, focus, подписи и `aria-live`.
Смена темы/вида не прерывает загрузку и не вызывает повторную выдачу кода.

## Ограничения

`ensurePartnerCode` уже генерирует 12 URL-safe символов, сериализует выдачу строкой
partner и сохраняет самый ранний код, включая заблокированный. Нельзя механически
вызвать его при mount общего PartnerPanel. Сохраняются account/role/antifraud guards.
Новый генератор, таблицы или библиотека не нужны. Контракт автоматической выдачи:
POST `partner.ensurePersonalLink` с пустым строгим объектом; account берётся из сессии.
GET, SSR и рендер обычного аккаунта не создают код. Подтверждение роли из SSR определяет
композицию, но POST повторно проверяет активность и роль под блокировкой account.
Ответ содержит прежний/созданный `{id,code,status,blocked_reason}` после COMMIT.
HTTP success — существующий 202; клиент считает ответ готовым только после успешного RPC.
Блокированный личный код возвращается как состояние `blocked`, без копирования и mint.
Блокировка другой кампании не удаляется; уже существующая активная личная ссылка остаётся
тем же кодом. Автовыдача не создаёт новую кампанию при наличии любого прежнего кода.
Первый код определяется по `created_at,id`; фильтр статистики не меняет личную ссылку.

## Границы

Текущий блок: M feature-adr на базе `24b4b4a`, показанный локальный UI и автоматическая
выдача с настоящими gates и независимым QE. Новые ставки/выплаты, самоназначение
роли, ручной выбор/смена кода, цены и лимиты не входят в запрос. Полный CJM
регистрации/использования/оплаты остаётся продуктовой приёмкой, макет его не доказывает.

## Приёмка и граница согласования

Принят компактный открытый блок «Ваша ссылка для подписчиков» с копированием и состояниями
утверждённого HTML. Полное упрощение UX в коммите 9365e990 не принято и сюда не переносится.
Блогеру не показывается форма ручного создания в личной карточке; прежний список кампаний
и вся статистика доступны ниже. Поведение обычной партнёрской панели сохраняется.
До передачи владельцу: реальные PostgreSQL, HTTP и browser checks на финальной ревизии;
согласование макета не доказывает исполнение этих проверок.

## Связь с OpenSpec, без двух независимых источников

OpenSpec хранит только пользовательскую дельту и BDD сценарии по capability; feature-adr
содержит её исполнимую интерпретацию, риски, решения, план и доказательства. Изменение смысла
требования сначала синхронизируется с указанной дельтой; hash обновляется до review snapshot.
При code/spec anti-drift сравниваются обе привязанные ревизии, а не два автономных бэклога.

| Feature-adr | OpenSpec spec.md: requirement / scenario |
|---|---|
| FR-1, FR-2 | Блогер получает готовую стабильную личную ссылку / Первый вход блогера |
| FR-3 | Прежний код и повторное открытие; Фильтр кампаний и другая заблокированная кампания |
| FR-4, FR-7 | Автоматическая выдача сохраняет права и блокировки / Обычный аккаунт; Мутация и конкурентное изменение роли |
| FR-5 | Прежняя ссылка заблокирована; Фильтр кампаний и другая заблокированная кампания; Заблокированный личный код в раскрытом списке кампаний |
| FR-7 | Два блогера получают только собственные ссылки и статистику |
| FR-6 | Ошибка загрузки или clipboard |
