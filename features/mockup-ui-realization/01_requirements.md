## Stakeholders и scope
Обычный пользователь, блогер и владелец используют действующие права и данные. Обязательны три style screens в Cabinet и Montage и одобренный upload→pause/reselect→processing→clips path. Другие role screens полного макета не получили blanket redesign approval; их действия/guards/theme regression защищены. Приёмка опубликованного приложения — clipmkr.ru; отдельный Cloud перенос только после ручной приёмки владельцем.

## Functional requirements
FR-1. Реализовать фактические композиции VC-1…VC-6 ниже, включая header/nav/реальный баланс, title/lead, пропорции и порядок ключевых областей. Tokens/classes/перенос одной кнопки при прежнем body не удовлетворяют FR. Reference screen/role toolbar, offline disclaimers, demo skip, fake balances/records/prices/media не переносить.
FR-2. Upload использует существующий native file input и реальный filechooser через компактный source-file row. Filename/форматы/selection/create/status доступны; настройки клипов закрыты по умолчанию в именованном native disclosure с mounted controls. Recent rows показывают существующие реальные video данные; лимит и баланс — отдельный aside. Partner/Pro/account/support остаются достижимы ниже основной области, без огромных форм в первом экране. Header/page повторно используют существующие authenticated reads, без новых API/SQL/политик.
FR-3. Передача показывает подтверждённые байты и процент по уникальным acknowledged parts, не таймер и не отправленные в fetch байты. Pause сохраняет последнее наблюдение с точной подписью; после reload неполного upload показывается «прогресс уточнится после продолжения». Re-select только проверяет SHA256; отдельное Continue выполняет существующую сверку/передачу. Ни частичные parts, ни UI-progress не записываются как full manifest v2. Processing начинается только по реальному server result; стадии не выдаются за известный процент.
FR-4. Cabinet result: один выбранный реальный 9:16 player с metadata/actions и список fragments справа. Montage: те же живые ClipCard в gallery справа от intro. Выбор строки меняет selectedClipId, активная строка имеет aria-current=true; polling сохраняет выбранный существующий ID, удаление выбирает первый доступный/первый. При явной смене selection прежний player приостанавливается без сброса времени; preference toggle не pause/play/remount. Download/copy/guest/expiry/unavailable/music/score действия и сообщения сохраняются.
FR-5. Packages отображают действующие CREDIT_SKUS/prices/credits/periods/purchaseWindows/current plan. Cabinet — три компактные колонки, Montage — numbered horizontal rows. Eligibility, disabled reasons, actual TEST marker, busy/error/retry и условия покупки видны у соответствующих действий. Единственный UpgradeScreen сохраняет SKU idempotency key и один pending checkout через preferences.
FR-6. Независимые layout/theme preferences сохраняют текущую реализацию SSR/cookie/document snapshot/Next cache. В каждом toggle сохраняются mounted input и выбранный File object, upload controller/key/options/active PUT/acknowledged receipt, selectedClip/player/currentTime, guest input/scroll и checkout key/busy/error. Не возникает новых create/Complete/jobs/reservations/checkout/RPC/RSC из самого toggle. Cookie denial сохраняет выбор в живом document; hard reload корректно возвращается к saved/default.
FR-7. Auth/erasure/owner/foreign404 выполняются server-side до приватных данных. Account switch не наследует File/upload/progress/player/payment state другого аккаунта. Public /,/c/,/g/,/upgrade/return сохраняют действующие scope/CSP/data. Ordinary90 и blogger120/default или owner override сохраняются; их фактическое end-to-end доказательство отдельно от CSS/unit checks.
FR-8. Приёмка требует actual paired reference/app screenshots и именованных geometry/assertions на final source/image SHA и actual clipmkr.ru origin. Матрица и условия ниже обязательны. Local PASS, старый baseline и mock provider не становятся published/genuine pass.

## Acceptance and evidence
AC-1: 2layouts×2themes×3screens×6widths(320/390/672/768/1024/1440)×Chromium/WebKit =144 base paired cases. Reference and app use same viewport/theme/layout/state; original reference bytes retained. Named content crops exclude demo toolbar; full screenshots retained. Mapping may explain real media/text differences, never mask geometry or actions. Use breakpoint checks above plus200% text, keyboard Tab/Enter/Space/visible focus and dark contrast/axe triage.
AC-2: Negative controls prove tests fail for restoring each of the three legacy screen bodies and for remounting an active state owner. Avoid a single global pixel ratio that tolerates wrong composition. Independent visual review accompanies geometry checks.
AC-3: Actual input change captured before React clears input; compare saved native File against File.prototype.slice receiver and active PUT, same connected input/key/options. Undefined===undefined is not proof. Actual browser beforeunload dialog during relevant pending states, cleanup after pause/unmount/terminal; race/hash/storage/account/auth regression persists.
AC-4: Running second real clip with controlled media source survives preferences and two observed ticks with strictly increasing currentTime; same video node/src and no extra guest focus/scroll. Busy checkout delayed success and rejection preserve key/error then explicit retry; no hidden duplicate mutation. Cookie-denial and cached soft navigation are separate cases.
AC-5: Network audit attributes requests to hydration/navigation H, interaction I, periodic P, focus/visibility F, unrelated U; toggle-origin I has zero unexpected mutations/RPC/RSC. Functional fixtures use genuine mounted Next app routes. Mock transport can test races but cannot prove storage/provider/payment availability.
AC-6: Published acceptance records source SHA/image digest, origin, private account/media evidence references, exact commands/results, paired screen paths and unexecuted/blocked cases. Payment provider, guest and ordinary90/blogger120 proof needs actual corresponding journey; existing baseline is labelled baseline. Preserve stateful data/config, no Cloud before owner acceptance.

## QCSD structural clarification — four original conditions
QC-CONTENT (quality-real-content-variability): На320/390 и1440, обе темы/компоновки, проверять 0/1/4 clips и recent records, длинное кириллическое название/filename (160символов, включая непрерывный фрагмент80символов), многострочные условия покупки. Empty имеет честное сообщение и доступный следующий шаг; unavailable сохраняет причину/доступные действия. Montage gallery после первых трёх продолжает новые строки, без скрытия четвёртой и последующих cards; Cabinet показывает все selector rows, действие каждого клипа достижимо выбором строки.
