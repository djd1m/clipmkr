# Переиспользование и план проверки

- `planScreenLayout` и `buildScreenLayoutGraph` уже умеют поместить область
  экрана целиком и отвести отдельное место движущейся камере. Эти блоки
  проверены на предоставленном примере текущим образом воркера.
- `getRenderInput` в `packages/db/src/render.ts` читает существующие
  намерение и последнюю опубликованную раскладку. Это первичная точка
  сверки для первой сборки и последующих повторов.
- `ClipLayoutChoice` и `ClipLayoutPreview` уже дают три варианта,
  проверку областей и подтверждение одной пересборки для готового клипа.
  Готовый пример можно получить через них без повторной расшифровки.
- FFmpeg строит экран и камеру отдельными ветвями. При чистой области
  демонстрации можно переиспользовать её кадрирование. Для наложенного
  окна локальный макет использует штатный `drawbox` только в ветви экрана.
  Предпросмотр уже рисует обе области через Canvas 2D. Их геометрия
  должна использовать одно правило исключения камеры, проверяемое на
  изображении предварительного просмотра и опубликованном MP4.
- Для короткого остатка последнего интервала отдельной проверки требует
  существующий фильтр выборки кадров. Действительный последний замер
  сохраняем штатной настройкой FFmpeg. Достоверно пустая камера сохраняет
  прежний защитный результат.
- Для локального доказательства использованы PostgreSQL в режиме чтения,
  один исходник и один опубликованный клип из рабочего S3, FFmpeg и
  действующий пакет сборки. Новая зависимость для композиции не требуется.

После выбора способа включения фиксируем макет и ADR. Затем автор
`gpt-6.2-sol high` связывает настройку с первой сборкой, а ревьюер
`gpt-6-astra xhigh` начинает независимую проверку с документов в новой
сессии. QA проверяет границы экрана на реальной записи и синтетических
кадрах, публикацию первой версии, сохранение настроек при продолжении
загрузки и отсутствие лишнего списания. Путь обычной нарезки проверяется
отдельной фикстурой. Подготовка этого черновика не меняет приложение.
