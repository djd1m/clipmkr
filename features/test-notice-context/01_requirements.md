# Требования: предупреждения по месту финансового действия

Источник: прямое поручение владельца «исправь» по переносу глобального TEST-предупреждения.
Оно разрешает описанный перенос без нового редизайна; согласование иных макетов не предполагается.
Stakeholders: посетитель лендинга, покупатель пакетов, блогер, владелец; приёмка поставки владельцем.

- FR-1: лендинг и вход не содержат глобального сообщения «Тестовый стенд ЮKassa…».
  При TEST-конфигурации root layout отдаёт обычный children без финансового баннера.
- FR-2: существующая страница покупки /upgrade явно предупреждает «TEST · Тестовая оплата.
  Реальных списаний нет.» рядом с каждой кнопкой покупки пакета; legacy кнопка оплаты
  также защищена. При testMode=false предупреждения нет. Existing TEST badge в intro сохраняется.
- FR-3: /dashboard/partner и /dashboard/bloggers перед статистикой/финансовым отчётом,
  а также /dashboard внутри existing details «Партнёрская программа» перед
  достижимым legacy PartnerPanel для is_blogger != true
  показывают «TEST · Тестовые платежи. Реальных списаний нет. Выручка и расчёты — учебные.»
  только при config.payments.mode === 'live' && config.payments.testMode.
  Рядом остаются прежние пояснения предварительного вознаграждения/отсутствия выплат.
  На blogger dashboard summary без финансовых сумм новое предупреждение не добавляется;
  общий баннер в кабинете не создаётся. Это уточнение инвентаризации по QE-TEST-001.
- FR-4: действующие TEST badge на /dashboard/account, авторизация, доступность checkout,
  маршруты оплаты, суммы, статистика, данные, сетевые вызовы и Cloud-конфигурация сохраняются.

Ограничение scope: только расположение и текст предупреждений; без CSS/редизайна/новых модулей.
Existing classes workspace-test/notice переиспользуются. Секреты или account identity не передаются клиенту.
Зависимости: существующий server config, UpgradeScreen.testMode, getRuntime/getScreenRuntime.
Открытых продуктовых вопросов нет. Допуск к коду ожидает реальный плановый review и K1/K2.
