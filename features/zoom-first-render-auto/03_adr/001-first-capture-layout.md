# ADR-001. Компоновка из визуальных наблюдений первой нарезки

## Context

В текущем первом рендере портретное кадрирование по лицу может потерять
демонстрацию даже при корректной загрузке. Ручная пересборка версии 3
принята на рабочем сайте. Её опубликованные снимки служат источником
повтора и последующей смены музыки.

## Decision

При первом рендере горизонтального видео добавить ограниченное число
наблюдений на штатном шаге 0,5 с в существующем процессе YuNet. Признаки
демонстрации — несколько протяжённых горизонтальных границ интерфейса и
хорошо видимые границы малого окна в верхнем углу с ровно одним лицом.
Минимум восемь ожидаемых точек и 60% положительных наблюдений среди
всех ожидаемых точек в сохранённых отрезках нужны для полного кадра.
Отсутствующее наблюдение входит в знаменатель. Для
переноса камеры нужны границы и лицо на каждом сохранённом замере и
одинаковый канонический прямоугольник на сетке анализа. Любое измеренное
движение окна запрещает перенос и маску. Пропуски в вырезанных отрезках
не влияют на решение.

Применить только выбранный существующий вариант 02 версии 3. При
подтверждённой демонстрации без стабильной камеры оставить исходный
кадр целиком. При отказе или дедлайне аналитики продолжить обычный
рендер. Перед формированием MP4 один раз зафиксировать решение в
`clip.initial_layout` под существующей оградой. SQL NULL означает, что
новому клипу ещё нужен анализ. JSON null означает старое или уже
согласованное стандартное поведение. Миграция помечает все существующие
строки JSON null, чтобы повтор старой работы мог принять ранее записанный
неизменяемый S3-объект. Новые строки получают SQL NULL. До первой записи
MP4 в S3 автоанализ уже отделён от повтора.

Первый допустимый писатель выбирает результат под `lockRender` и меняет
столбец только при SQL NULL и версии файла 1. Конкурирующий вызов
возвращает уже зафиксированный выбор, включая JSON null. Устаревшая
ограда, ручная пересборка и другие версии не пишут решение. После
фиксации результат возвращается только из БД, в том числе при повторе
без подтверждения предыдущей попытки.

Ненулевое поле камеры в сохранённой автоматической компоновке означает,
что камера уже подтверждена. Первый рендер и его повтор берут этот
вердикт без повторного обращения к YuNet. Отсутствие положительного
ответа, включая дедлайн аналитики, фиксируется как JSON null. Повтор
читает тот же стандартный выбор до начала записи S3. Публикация
проверяет точное совпадение снимка. Ручная пересборка
сверяет намерение или опубликованный снимок так же, как раньше.

На выкладке определить всех потребителей рабочей очереди render. Старые
video-воркеры завершают активную работу и останавливаются до миграции.
Штатный `packages/db/dist/migrate.js` из нового образа получает
`DATABASE_URL` подтверждённой роли администратора фактической БД.
До запуска сверяем OID, право владельца/суперпользователя и журнал 035.
После миграции рабочая роль должна
читать и обновлять новый столбец. Стартует совместимый воркер. После
включения возвращение старого воркера допустимо только в отсутствие
неопубликованных версий с ненулевым автоматическим решением, включая
ошибочные, отложенные и повторяемые вручную. Иначе исправление идёт вперёд.

## Confirmation

1. Сохранённая первая компоновка, недопустимая форма, старый ожидающий
   клип и повтор после попытки записи в S3:
   `tests/clip-layout.integration.test.ts`. Два конкурирующих разных
   кандидата получают выбор первого писателя. Старая ограда не пишет.
   Повтор после сохранения или PUT использует тот же результат при
   изменившемся или недоступном детекторе.
2. Положительная, непостоянная и отрицательная сцены, существующий
   нативный рендер: `tests/screen-layout-media.test.ts`. Различить 7/8
   ожидаемых замеров, границу 60%, пропуск в сохранённом и вырезанном
   отрезке и сдвиг окна на один пиксель. При сдвиге исходный кадр сохраняет
   камеру на месте и отдельное окно отсутствует.
3. На отдельной новой записи проверить авторизованный просмотр
   первой опубликованной версии 02 с камерой без ручной пересборки,
   неизменный счётчик пересборок и доступный файл. В шве
   `handleRenderJob` → `renderClip` инъекция пустого результата допускает
   стандартный вывод. Проверка `initial_auto_timeout_choice_survives_put_retry`
   в `tests/clip-layout.integration.test.ts` проверяет JSON null до PUT,
   повтор после PUT без повторной классификации и отсутствие лишнего
   списания и дополнительных заданий. Владелец проверки — автор,
   публичное подтверждение читает независимый проверяющий после ревью.
