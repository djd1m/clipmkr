# Интеграция первой компоновки

Штатный `handleRenderJob` даёт право автоанализа только первичной
попытке версии 1 с SQL NULL в `initial_layout`. Один `detectFaces` смотрит только
локальный источник, добавляет наблюдения малого окна и экрана к
обычному отчёту. Сборка связывает наблюдения с сохранёнными отрезками.
Детекция, CTA, заголовок и титры используют итоговый вариант 02 до
построения команды FFmpeg.

Информация о выбранной компоновке включается в существующий хэш
доставки на S3. До построения FFmpeg выбор фиксируется под текущей
оградой рендера. При повторе первая версия получает сохранённый выбор
и вердикт о камере без нового анализа. При дедлайне детектора этот выбор
стандартный, с JSON null. Движение или сомнительная граница окна допускают
полный кадр, а маска применяется только при одинаковом подтверждённом
прямоугольнике. `publishRenderResult` проверяет ожидаемую
компоновку и публикует канонический снимок при принятом результате.
Следующие рендеры используют снимок как обычно. Редактор показывает
сохранённые настройки. Автоматика действует только для новых клипов,
созданных после миграции.

Порядок выкладки — остановка старого video-воркера после активных задач,
резервная копия, штатная миграция на фактической БД под её администратором,
проверка прав текущего рантайма, затем запуск нового воркера. Веб
переиспользует опубликованный контракт версии 3.

Обработка запускается существующим тайм-аутом воркера. Частные кадры,
вырезки лица и визуальные наблюдения не сохраняются и не отправляются
наружу. Диагностика выпуска учитывает лишь выбранный вариант.
