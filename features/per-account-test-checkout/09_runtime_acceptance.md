Она восстановлена в уникальную временную БД существующего PostgreSQL 16 на управляющем
VPS; строки и структура всех публичных таблиц совпали со снимком. Временная БД после
проверки удалена. Рабочая БД из копии не восстанавливалась; миграции не запускались.
После поставки различий проверяемых таблиц со снимком нет.

Заменён только web и шесть согласованных переменных оплаты. Проверены сохранность
остальных переменных, включая почту, всех mounts и идентичность остальных контейнеров.
Откат не потребовался. Контейнеры, DNS и приложение Cloud.ru не менялись.

## Проверка политики на работающем артефакте

Повторно сверены DNS, SSH-идентичность цели, точные образ и ревизия, эффективная
конфигурация и привязка исходных путей. На реально опубликованном коде вызван
канонический `checkoutAllowedForAccount`; политики активных аккаунтов прочитаны
без записи в БД.

- Согласованный аккаунт активен, использует кредитную политику и допущен к покупке.
- Среди остальных 37 активных аккаунтов допущенных нет, включая 15 с кредитной политикой.
- `N5_CHECKOUT_ENABLED=false`; тестовый режим включён; префикс настоящего тестового
  ключа проверен без раскрытия значения.
- Идентификатор аккаунта и ключи находятся только в закрытых серверных настройках.

Дополнительно Chromium открыл настоящий HTTPS `/upgrade` с двумя собственными
тестовыми сессиями — обычного клиента и блогера. В обоих случаях конечный путь
остался `/upgrade`, кнопки покупки отсутствовали, ошибок страницы не было.
В кабинете тестового блогера персональная автоссылка по-прежнему видна.
Это ограниченная проверка регрессии; сессии демонстрационных и реальных пользователей
не использовались, видео и покупки не создавались.

`N5_PAYMENTS_MODE=live` здесь означает существующий драйвер API ЮKassa; в сочетании
с обязательными тестовым режимом и `test_`-ключом это тестовый магазин. Реальные
списания не включены.

## Что проверка не доказывает

Проверка политики не входила в аккаунт пользователя, не создавала намерение оплаты,
не вызывала API магазина и не меняла баланс. Поэтому опубликованный UI целевого
аккаунта, завершение тестовой покупки, доставка webhook и начисление по этой покупке
не объявляются пройденным E2E. Source-тесты с локальным HTTP-провайдером также не
заменяют настоящий магазин. Текущий S3-инцидент и весь основной CJM этим не закрыты.

## Ручная проверка владельцем

1. Войти согласованным аккаунтом на `https://clipmkr.ru`.
2. Открыть `https://clipmkr.ru/upgrade`; проверить пометку «TEST · Тестовая оплата»
   и доступность кнопок покупки пакетов.
3. При желании пройти тестовую оплату ЮKassa. Приёмка требует подтверждённого
   начисления в кабинете, а не только страницы возврата.
4. В отдельном контексте обычного аккаунта проверить отсутствие доступа к покупке.
