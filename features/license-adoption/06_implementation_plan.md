## Порядок и проверки

Чтение доноров и upstream независимо. Порядок выхода в реализацию — requirements и owner declaration → чистота целевых путей K1 → K2 → TASK-1…TASK-3 → контроль TASK-4 на неизменном diff → независимое ревью. Использовать `cmp`, `sha256sum`, статическую проверку Dockerfile/.dockerignore, `git diff --check` и strict OpenSpec. Git-коммит и передачу в зеркала координирует root.

Риск неполных условий передачи образов учесть точным описанием границы. Наблюдаемые записи Git не подменяют право выдачи лицензии, которое для перечисленного кода подтвердил владелец.
