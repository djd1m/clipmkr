## Требования и приёмка
- FR-1: для этого source-site использовать отдельный `deploy/source-proxy.Caddyfile`, побайтно равный принятой базе кроме единственной замены `reverse_proxy web:3000` → `reverse_proxy n5-clipmaker-web-1:3000`. Ожидаемый candidate SHA `cdefca96ac35bf1c293f39d6f5282232ccb3bf0c9f649688698a437715a6a023`. Базовый `proxy/Caddyfile`, `docker-compose.yml` и custom `N5_COMPOSE_PROJECT` сохраняются. Приёмка: hash/read/write/truncate считаются по captured UTF-8 bytes и len(bytes), не по числу Unicode-символов; diff только одного upstream; источник overlay выбран отдельным `deploy/source-proxy.compose.yml` и обязательными двумя `-f` для будущего ordinary source deploy; effective project/site проверяются до up, foreign/unknown отказывает, verified samecandidate даёт no-op. Текущий warm mount не переключается; обычная/custom установка продолжает portable путь.
- FR-2: existing private `validate_proxy_binding` допускает только exact новый disk SHA, один безусловный upstream exact-name:3000 и единственный selected-name candidate==approved main во всех сетях proxy. Сохраняются полный inventory/membership, artifact/image/revision, loaded==adapted, запреты DNS/hosts overrides и двойное store/shop/TEST identity. Приёмка: A1/A2/A3 positive/negative actual branch fixtures; наличие нескольких `web` больше не является выбранным DNS-именем, но дубликат нового имени всё равно STOP. Нельзя разрешить произвольные upstreams или подставить health вместо uniqueness.
- FR-3: runtime source proxy меняется только после независимого review и отдельного root GO: свежий mount/source/inode/identity/no-active-payment preflight с различением known callback record и unknown/incomplete proxy operations, private backup+hash, удержанный fd полной записи/truncate/fsync в тот же inode, Caddy validate/reload, container/PID неизменны, loaded==adapted/expected hash/health11a90/XFF. Приёмка: A4 local fd failure fixtures и actual root runtime evidence; при known synchronous failure и сохранном control/inode восстановить backup тем же inode с validate/reload/контролем. Timeout/unknown external completion → incident STOP без последующих write/reload до выяснения completion/control. Известный callback healthy_unconfirmed/applied=false marker с actual apply receipt не стирается; fresh canonical revalidate обязательна перед бизнес-действием. Copy/rename файла само по себе не закрывает single-file bind.
- FR-4: private runner/caller pins актуализируются согласованно после final review; старые bytes/hash/history сохраняются. Приёмка: baseline/guard проходят только после фактического site reload и нового binding; до этого отказ ожидаем. После rollback к ambiguous base платёжный CJM остаётся STOP/NOT VERIFIED. Сессии/checkout/provider mutation к проверке исправления DNS не добавляются.
- NFR-1: документыRU, секреты/raw inspect/backup вне Git; нет app/auth/SQL/payment policy/Cloud/DNS/network/base-Compose/container-name changes; отдельный source-only Compose override предназначен лишь будущему cold deploy, текущий runtime без recreate. Уже закрытый callback09305c, его `.fa-state`, executor/bridge и source identity не меняются. Независимые review и runtime GO отдельны от structural gates.
