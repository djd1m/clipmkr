## Конкретные стандартные runtime команды (только после отдельного GO)

Root сначала показывает exact hostsource/candidate/backup hashes, dev+inode, locks и параметры своей samefd записи; backup/write/truncate/fsync выполняются ранее проверенными fd primitives с результатом в отдельном proxy operation record. Это пока процедура плана, не исполненные команды. Конфигурация подключена single-file bind; не использовать mv/replace и не переключать mount.

```sh
docker exec n5-clipmaker-proxy-1 caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
docker exec n5-clipmaker-proxy-1 caddy adapt --config /etc/caddy/Caddyfile --adapter caddyfile
docker exec n5-clipmaker-proxy-1 caddy reload --config /etc/caddy/Caddyfile --adapter caddyfile
docker exec n5-clipmaker-proxy-1 wget -qO- http://127.0.0.1:2019/config/
docker exec n5-clipmaker-proxy-1 wget -qO- http://n5-clipmaker-web-1:3000/health
```

Validate обязателен до reload; adapted JSON и loaded admin JSON после reload должны совпасть. Повторные inspect проверяют container/PID/mount/inode, public /health ожидает revision/header11a90; accepted XFF-chain/rejection probes повторяются с теми же oracle, а unchanged trusted_proxies/transport подтверждаются adapted delta. Direct backendhealth — дополнительная проверка, не uniqueness proof. При неизвестном завершении любой внешней изменяющей команды запрещены следующие write/reload; root сначала выясняет completion/control. При доказанном sync failure rollback использует сохранённый exactbackup и тот же inode, затем эту же validation/control sequence. Новых SSH/Caddy вызовов автор плана не выполняет.
