# План: исключить переход во время загрузки

Статус: предложен; продуктовый код не изменён. Реализация ждёт checkpoint владельца и K2.
Tier: S. Inputs read: текущий Uploader, upload-parts, rpc, browser-конфигурация, действующий
feature-adr 1.5.25 и `docs/incidents/2026-11-02-upload.md`.

## Цель

Убрать действие, способное оборвать передачу до приёма файла. Сохранить существующий
автоматический переход к записи только после успешного завершения. Сеть, API и очередь
остаются источниками фактического состояния; новый процесс загрузки не создаётся.

Сначала проверить установленную версию, выполнить recall с `--project .`, затем записать только действительно выполненные этапы поддерживаемой командой dz. Это подготовка среды, не успешная приёмка.
- [ ] T1 (FR-1, FR-2, FR-3, после T0): добавить `tests/browser/upload-lifecycle.test.ts`, который через имеющийся Vite запускает настоящий React-компонент в Chromium и WebKit. Фикстуры изолируют сеть и Next navigation; они не создают записей и не запускают модели. Воспроизвести RED: задержать PUT и обнаружить доступную раннюю ссылку. Положительный контроль: после ответов PUT 200 и complete 202 переход выполнен ровно один раз к тому же ID. - [ ] T2 (FR-1, C-1, после T1 и K2): заменить только интерактивный идентификатор в `Uploader.tsx` обычным текстом. Переиспользовать существующий router.push после complete. Не добавлять новую загрузочную библиотеку, заголовки PUT или скрытый повтор.
- [ ] T3 (FR-1, FR-2, FR-3, C-1, после T2): GREEN того же теста; временное возвращение ссылки обязано снова дать RED, после восстановления — GREEN. Проверить узкий экран 320/375 и десктоп 1440 в обеих темах; просмотреть снимки без частного медиа. Проверить затронутые upload-тесты, typecheck, lint, сборку и обязательный полный набор с изолированными зависимостями. Непроведённые проверки не объявлять успешными.

## Выбор решения

Удаление раннего перехода требует меньше кода и устраняет соблазн перейти на ещё не готовую
страницу. `target=_blank` оставляет преждевременную карточку и не покрывает закрытие исходной
вкладки; новая система загрузки/heartbeat несоразмерна этому конкретному дефекту.

## Checkpoints и gates

Подтверждение владельца должно относиться к этому конкретному объёму и требованиям. Оно не
выводится из наличия файлов или успешных команд. K1: новых product-команд, модулей и экспортов
не планируется; новые npm scripts вызывают существующие OSS-команды. K2 запускается реальным
скриптом с `--tier=S --require-requirements` до изменения компонента. Receipt не заменяет approval.

Реальный полный E2E на опубликованной версии остаётся отдельной проверкой. Браузерные фикстуры
не доказывают доступность сети Windows пользователя и не устанавливают его действия.
