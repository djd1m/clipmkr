## Условия закрытия

**SEC-01 — HIGH, structural.** ADR-004 ограничивает первый server-generated signed URL известным S3 endpoint и использует allowlist протоколов/форматов, но не определяет, как ffprobe/FFmpeg обрабатывают HTTP 3xx. Allowlist протоколов сам по себе не закрепляет host каждого следующего HTTP запроса: перенаправление может раскрыть capability или обратиться к иному адресу. Зафиксировать проверяемую политику: по умолчанию прекратить чтение при redirect и вернуть безопасный unavailable, либо до каждого запроса обеспечить разрешённые origin, scheme и безопасную обработку capability; без нового proxy/сервиса. Указать реальный механизм, применимый к выбранному FFmpeg/Python пути, и запланировать контролируемые HTTP фикстуры 3xx same/cross-origin, downgrade и проверку отсутствия URL в ответах/логах. Текущее наблюдение — недостаток дизайна, не утверждение, что редирект уже эксплуатируется. Scope: `03_adr/004-cache-bounded-camera-seeds.md`, `05_architecture.md`.

**SEC-02 — HIGH, structural.** Новый общий render transport описывает seed `{kind:'layout-seed',clip_id,seed_revision}` и legacy `AttemptJob` без kind, но не определяет закрытый runtime dispatch для неизвестного kind, смешанных или дополнительных полей. Текущий worker исходной системы читает `video_id`/`fence` из job, а TypeScript тип не является валидацией данных Redis. Зафиксировать строгую схему обоих вариантов, запрет неизвестных/смешанных kind и клиентских URL/account/данных, недопущение fallback в legacy ветку, безопасный отказ без seed/render/quota side effects. Seed claim должен брать source/account из authoritative DB, сверять принадлежность, active/deletion/retention и revision/epoch до доступа; независимые тесты поддельного/просроченного identity и inactive/foreign account не должны приводить к чтению чужого source, публикации или утечке. Не предполагается, что Redis — публичный API или что эта уязвимость уже существует. Scope: `03_adr/004-cache-bounded-camera-seeds.md`, `05_architecture.md`.

## Модель угроз: 12 рабочих линз

1. **Активы и границы:** приватный source, право видеть его, account/clip, состояние и квота, old/new MP4, подписанный URL. Недоверенные границы browser→web, Redis→worker и storage→media parser; DB — authority для ownership, eligibility, intent и lease.
2. **S — подмена:** `layoutInfo`, `prepareLayout`, `setLayout` и Original обязаны проверять сессию/owner; неизвестный и чужой clip дают одинаковый 404, без side effects. `sourceRevision` — opaque server-derived identity, не credential и не доверенное значение клиента. Rate limit до тела; inactive/deleted/expired отсекаются и при фоновом claim/publish. Проверки предусмотрены дизайном, не исполнены.
3. **T — подмена ROI/аргументов:** ADR-001 закрывает объект и требует finite numbers, bounds, containment, детерминированное округление; сервер повторно валидирует DB read. Строить фильтры только из validated numeric values, вызывать child с argv без shell. Неизвестные поля, NaN/coercion и повреждённую версию отвергать с сохранением old MP4. Synthetic malicious geometry и ffmpeg filter-argument tests ещё нужны.
4. **T/R — replay и деньги:** ADR-002 предусматривает ownership до exact replay, сохранённый key + canonical layout + expected version/source, атомарные quota/lease/intent и 409 при изменении намерения; повтор не запускает STT/select и не списывает source credits. Проверить concurrent request, timeout, replay после последующей публикации, отказ quota/lease и Postgres rollback; доказательств выполнения нет.
5. **T/E — очередь:** только identity, authoritative DB и CAS revision/epoch; старые и новые сообщения нуждаются в закрытом dispatch по SEC-02. Нельзя считать существующий typed interface runtime gate.
6. **I — capability источника:** только известный storage object из доверенной записи; URL не от браузера, не в queue/DB/log; браузер использует same-origin Original без S3 redirect. Зафиксировать правила redirects по SEC-01. URL в argv виден привилегированным операторам host, что ADR-004 открыто признаёт; не обещать сокрытия от них.
7. **I — приватность:** не сохранять кадры, source key, URL, transcript/title; при child stderr/errors и diagnostics предусмотреть sanitization до логирования, не переписывать исключение с signed query. Synthetic canary в логах и queue/storage errors, а также authenticated/foreign Original Range тесты пока плановые.
8. **D — подготовка seed:** rate limit, однократный cache identity, максимум две попытки, lease/CAS, timeout 30 секунд, процесс и descendants прекращаются, stale result не публикуется. Отдельно измерить фактические сетевые байты и задержку обычного render: 2 GB и 30s не являются малым hard byte cap; Priority не вытесняет выполняемую работу.
9. **D — source parser:** список разрешённых протоколов и форматов исключает playlist/concat и внешние references; запрет shell и ограничение probe, timeout и безопасная обработка нераспознанного контента. Реальные FFmpeg/HTTP fixtures, включая игнорируемый Range и дочерние процессы, ещё не выполнялись.
10. **T/I — state и сохранность:** pending intent/cache отделены от published; current fence контролирует одновременную публикацию keys/layout; stale/failed попытки не должны менять опубликованный объект. Retention и erasure применяются на claim и publish. Реальный PostgreSQL, Redis fault и storage tests требуются позднее.
11. **R — миграция и откат:** additive migration → новый worker → новый web; при откате сначала остановить приём и drain активных intents новым worker. Иначе старый worker может принять новый intent и собрать legacy pixels. Наличие схемы не доказывает совместимость rollout или восстановление watchdog.
12. **Product/privacy boundary:** подтверждённая пользователем камера — прямоугольник текущего source, не установление личности. Сэмплирование каждые 0,5 с не доказывает отсутствие краткого исчезновения или замены лица в той же ROI. ADR-001 фиксирует ограничение; текст ZF-06/AC03 об отсутствии чужого лица шире доказуемой гарантии. Согласовать исполнимое обещание и отдельно проверить движущийся corpus; одобрение selector не является доказательством identity, runtime или согласованием ослабления требования.

## Прочитанные контракты существующего кода

`apps/web/src/app/api/trpc/[trpc]/route.ts` авторизует POST до чтения тела, отключает batching; `apps/web/src/server/rate-limit.ts` хранит лимиты по HMAC account/IP. `apps/web/src/server/clip-music.ts` показывает шаблон owner/video→clip lock и quota/lease в транзакции. `packages/db/src/attempts.ts`/`render.ts` — fence и восстановление. `packages/queue/src/queues.ts` и `apps/worker/src/workers/render.ts` — identity существующего job и DB reread, не validator будущего union. `apps/worker/src/media/download.ts` — временный файл с очисткой; существующий локальный ffprobe использует file-only policy, новая удалённая policy ещё не существует. Это только чтение исходников соответствующей базовой ревизии, не успешная проверка нового поведения.

## Границы и ожидаемые дальнейшие доказательства

Ни приватные кадры, live данные, БД, S3, credentials, ни mutation/запуск worker не использовались. Сканирование зависимостей, DAST, реальные FFmpeg/Postgres/Redis тесты, rollout и security QE не выполнялись. Параллельный общий код во время ревью не менялся этим агентом. После правок координатора для SEC-01/02 нужен новый host snapshot и независимая phase-specific проверка исправленного дизайна этим же reviewer; затем обязательные плановые K1/K2, implementation и runtime QE. Исход этой записи не является закрытым этапом 03.5.
