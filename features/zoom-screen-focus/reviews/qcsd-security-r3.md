# Независимое security origin-refresh R3

**Вердикт: clean для дизайна.** Исходные условия SEC-01 и SEC-02 сохранены без изменения; исправления R2 остаются в силе на снимке R3. Новых серьёзных security-условий в точечной дельте не выявлено. Это не проверка реализации или результатов runtime QE.

Роль `qcsd-security`, `owner-exception`, независимая сессия; nonce `0276c1f3-2f7b-4e38-96c4-10258020aca1`, revision `e66723874cc112533766c6896c800786109567d430efd4f5a7ff1b30382acfdd`. Самостоятельно пересчитаны все девять SHA host manifest; все совпадают. Membership host R2 и R3 одинаков; среди них изменены только ADR-003, 04, 05, а ADR-004 с контролями SEC-01/02 имеет побайтно тот же SHA. Архивные SHA всех девяти R2 документов/досье совпали; просмотрены изменения ADR-003, 04, 05, 06 и OpenSpec, а также состав и оценка `changedScope`/`newRisks` авторского handoff на 143 кумулятивных пути.

SEC-01: ADR-004 и 05 по-прежнему требуют `max_redirects=0` для обоих ffprobe/ffmpeg, exact origin/scheme, TLS, закрытые сообщения об ошибках, безопасный unavailable и будущие controlled redirect/TLS/canary проверки. SEC-02: сохранены закрытый runtime parser seed/legacy без fallback, authoritative DB owner/active/retention/source revision/epoch перед чтением и при публикации, а также будущие Redis и PostgreSQL проверки. R3 не ослабляет эти требования и не является доказательством их фактической работы.

По новой границе очистки local draft: accepted/pending/reload/failed сохраняют envelope; submitted snapshot отделён от текущего draft. Автоочистка допускается только при подтверждённой публикации exact intent с установленными request key и render version, совпадающим canonical config и sourceRevision и непосредственно перечитанными неизменёнными account/clip/draftVersion/layout. Сверка и удаление выполняются без async-разрыва. Поздние правки и A→B→A с новой версией не должны удаляться старой публикацией; потерянный ответ разрешается exact replay, без нового произвольного списания. План содержит будущие различающие сценарии публикации, отказа и поздних правок. Сохраняются прежние account-scoped storage, отсутствие кадров/URL/credentials и лимиты unavailable storage. Никакого утверждения о фактической browser concurrency или privacy проверки здесь нет.

HTML selector имеет согласованный SHA `76acda5003083138245031f5e96c6697e74844a8b5324e1007d397ac993eb1f0`; это не подтверждение дополнительных текстовых состояний и движущегося результата. Original route/helper остаётся зависимостью интеграции. Код, БД, S3, API/media и runtime tests не запускались. Флаг `implementationVerified:true` в ideation receipt обозначает исключительно проверку документов на указанной revision; обязательные implementation, K1/K2, security и QE ещё впереди.
