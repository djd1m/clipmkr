# Zoom: замороженный вход для проектирования

Статус: авторский baseline v1 для согласования и независимого планирования, не approved gate.
Основание: явный выбор владельцем варианта03 из `docs/research/zoom-screen-layout`;
новый selector и точная политика областей ещё требуют согласования макета/ADR.
База `e66d9addfad16e1b6dcd7bd07bf06c5abb1343f1`.

## Участники

Ведущий демонстрации загружает запись; зритель смотрит 9:16/скачивает MP4;
владелец согласует UI и принимает тестовую копию. API, worker, clip viewer и download
потребляют одну опубликованную конфигурацию. Автор кода и независимый QE различаются моделями.

## Функциональные требования

| ID | MUST / проверяемое поведение |
|---|---|
| ZF-01 | В явно выбранном режиме «Экран + лицо» начальный вариант03 «Фокус на действии». Подкаст/старые записи без новых настроек сохраняют прежнее поведение. Не применять режим к каждому wide source автоматически. |
| ZF-02 | 01 «Весь экран», 02 «Экран и лицо отдельно», 03 «Фокус на действии» доступны в закрытых дополнительных настройках оформления. Выбор меняет только локальный черновик/превью до явного подтверждения. |
| ZF-03 | 03 показывает выбранную область экранного действия крупно и вставляет движущуюся камеру поверх; 01 сохраняет выбранный экран целиком, 02 отделяет камеру. Устройство сцены не зашивается координатами одного файла. |
| ZF-04 | Область экрана и камера задаются/проверяются относительно source dimensions; пользователь может уточнить экранную область и камеру. Неуверенное автоопределение не выдаётся за установленное действие/автора. |
| ZF-05 | Перед применением доступен просмотр всей длительности выбранного клипа с началом/концом, сменой окна, меню/диалогом, прокруткой и интервалами без камеры; один стоп-кадр не закрывает приёмку. |
| ZF-06 | Нет лица/камера исчезла/детектор отказал: не включать podcast center crop, не показывать замороженное или чужое лицо. Сохранить экран/действие; показать объяснение отсутствующей камеры. Если нельзя подтвердить безопасную область действия — сохранить полный выбранный экран и предложить уточнение. |
| ZF-07 | Применение к готовому клипу — отдельное явное действие с подтверждением области, последствия и доступной серверной квоты пересборки. Точный текст квоты берётся из реального контракта, не обещает бесплатность. Сам выбор, отмена и preview не создают job/charge. |
| ZF-08 | Изменяется только выбранный клип. Прежний MP4/preview/download доступны до успешной публикации нового в срок хранения. Ошибка/конфликт не уничтожают материал и черновик. Повтор запроса/двойной клик не дают повторного списания исходных кредитов и второй принятой операции. |
| ZF-09 | Звук, экран, камера, субтитры и эффекты используют один cut_plan и временной контекст. Подписи/CTA/teaser/обязательная метка не закрывают отмеченную область действия; метка остаётся последним слоем. |
| ZF-10 | Legacy single/dual/center, музыка/CTA и существующие готовые материалы сохраняются; pending intent и published settings/version различаются. Обновление страницы и polling не подменяют черновик новой опубликованной версией без объяснения. |

## Критерии приёмки (Given / When / Then)

- AC01/ZF01–03: дан screen+face draft; при первом открытии selector выбран03; выбор01/02 меняет компоновку preview, число mutation RPC/queue/credit writes равно0; до применения текущий MP4 неизменен.
- AC02/ZF03–04: даны synthetic источники разных разрешений и расположений камеры; применённые normalized ROI дают ожидаемые screen/camera pixels, чётные валидные crop, без hardcode1816×968.
- AC03/ZF04–06: даны missing/no-face/moving camera/смена окна/неполные metadata; рендер сохраняет выбранный screen context, камера не подменяется лицом со слайда; fallback явно указан и проверен по интервалам.
- AC04/ZF05/09: дан движущийся synthetic source со сценами, счётчиком и общим cut_plan; результат01/02/03 сохраняет время/звук, действия внутри ROI, safe overlay zones и порядок обязательной метки.
- AC05/ZF07–08: дан готовый clip; выбор/отмена не делают mutation; два concurrent подтверждения/timeout+retry дают одну принятую пересборку; чужой/несуществующий clip одинаково404; old MP4 сохраняется при fail и stale-fence publication.
- AC06/ZF08/10: дан оплаченный source и готовые clips; явная пересборка не делает STT/select и не меняет source credit charge, соседние клипы/настройки; ошибка publish сохраняет прежнюю версию. Проверка на настоящем PostgreSQL, без настоящего списания.
- AC07/ZF02/10: на390/1440 в согласованном Cabinet dark selector изначально закрыт, доступен с клавиатуры; при закрытии/polling draft и player node сохраняются; действий/горизонтального overflow нет за границей экрана.

## Нефункциональные требования и ограничения

Нейтральный Cabinet, зелёный акцент, текущие токены/компоненты; mobile-first, touch44,
обе темы приложения, контрольные ширины390/1440 и применимый responsive gate.
Новая ML-модель/сервис/зависимость не нужны без измеренного недостатка FFmpeg/OpenCV/YuNet.
Качество/скорость автоопределения ещё не измерены; SLA/«всегда читаемо» не обещаются.
На360px нельзя одновременно сохранить широкую страницу и сделать весь мелкий текст читаемым:
выбор03 осознанно может убрать края, это видно в preview до подтверждения.
Приватные кадры и signed URL не входят в Git; synthetic media для тестов воспроизводимы локально.

## Границы

Входит: screen+face layout, выбор01/02/03, ROI, fallback, explicit rerender intent и безопасная публикация.
Не входит: новый active speaker/OCR/action-understanding, segmentation головы, отдельная camera track,
массовая пересборка существующих clips, новый source charge, autodeploy/production/DNS.
Новые реальные rerender/upload/S3 private GET выполняются только в отдельном разрешённом тестовом scope.

## Требующие решения вопросы

1. Владелец должен согласовать конкретный selector/preview390/1440; выбор03 уже авторизован.
2. ADR/QCSD должны определить, достаточно ли первой версии с ручным подтверждением ROI и безопасным seed;
   универсальное автоматическое определение action region не доказано. Это не просьба владельцу выбрать библиотеку.
3. До кода планировщик фиксирует серверный контракт подтверждения/идемпотентности/квоты и migration shape;
   это инженерные решения внутри scope, их не нужно перекладывать на владельца.
