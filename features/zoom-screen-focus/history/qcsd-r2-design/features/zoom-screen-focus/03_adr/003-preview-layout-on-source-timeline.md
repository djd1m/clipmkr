# ADR-003: Показывать локальный draft по защищённому source и сохранённому cut_plan

## Status
proposed — обратимо до UI интеграции; пересмотреть, если будет нужна точная до пикселя симуляция финального encode. UI placement уже согласован владельцем; этот ADR не повторное согласование. Requirements: ZF-02, ZF-04, ZF-05, ZF-07, ZF-10; AC01, AC04, AC07.

## Context
Три radio choices и ROI sliders должны немедленно менять preview без render jobs. Один стоп-кадр не обнаруживает потерю меню/смену окна. Готовый MP4 уже обрезан legacy framing и не может вернуть исчезнувшие source pixels. Отдельная Original-фича создаёт авторизованный Range доступ к исходнику; дублировать его auth/storage не нужно.

## Decision Drivers
1. HIGH: весь выбранный clip можно просмотреть до apply, screen/camera синхронны.
2. HIGH: draft/cancel/radio не пишут серверное состояние и не тратят квоту.
3. HIGH: private source остаётся в существующей owner/session boundary.
4. MEDIUM: стабильный player, optional advanced, reuse browser video без dependencies.

## Considered Options
| Вариант | Плюсы | Минусы | D1/D2/D3/D4 |
|---|---|---|---|
| Новый preview MP4 при каждом выборе | Финальный renderer даёт точные effects | Латентность, jobs/storage/cleanup, расход на каждый control | +/−/+/− |
| Статичный poster/CSS mockup | Мгновенно и дёшево | Не проверяет весь clip и смену окна | −/+/+/+ |
| Один source video + canvas composition | Движение, общая позиция source, local controls | Approximate transitions/effects, browser codec/seek границы | +/+/+/+ |

## Decision
Новый модуль `ClipLayoutChoice` владеет local draft/dirty/request identity. `ClipLayoutPreview` владеет одним source `<video>` и canvas. Его `src` — локально построенный `/api/videos/${encodeURIComponent(videoId)}/original`; GET/HEAD/Range и `?metadata=1` реализуются Original-фичей с owner/session проверкой на каждый запрос. Browser props не содержат S3key/signed URL/public tokens. Exact metadata seam согласован с Original архитектором: `OriginalSourceMetadata`: ready `{videoId,state:'ready',available:true,sourceRevision,media:{kind:'video'|'audio'|'unknown',mime,extension,bytes:string,durationSeconds:number|null}}`; остальные `{videoId,state:'incomplete'|'missing'|'error',available:false,unavailableReason}` без revision/media. `sourceRevision` — lowercase SHA256 UTF8 от `JSON.stringify(['original-source-v1',videoId,objectKey,uploadId??null,String(actualBytes)])`, не video.updated_at. Root закрепил canonical server-only leaf `packages/shared/src/server/original-source.ts`, export `originalSourceRevision`, import `@clipmaker/shared/server/original-source` (ownership Original). `packages/shared/src/index.ts` его не re-export-ит: node:crypto не должен попадать в browser bundle. Existing `./*` package exports уже достаточны; package/dependency changes не нужны. Worker не импортирует web/server module. Layout API пересчитывает его сервером. Actual ETag не требуется при immutable source contract.

Clip-specific read projection дополнительно даёт `{clipId,start,end,cutPlan,renderVersion,publishedRenderVersion,publishedLayout,seedStatus,seed?,rerenderQuota}`. `cutPlan` валидируется на сервере; NULL значит один интервал[start,end]. Source layout request передаёт `expected_source_revision`, чтобы stale geometry не принять после смены identity. До ready metadata/source video loaded/readable seekable состояние preview имеет конкретную причину; apply не предлагает подтвердить неувиденный кадр.

Один decoder обеспечивает camera и screen один и тот же кадр. `requestVideoFrameCallback` перерисовывает canvas, `seeked` перерисовывает при scrub; fallback requestAnimationFrame на поддерживаемых браузерах без callback. Canvas использует shared geometry из ADR-001; ни `toDataURL`, ни export/screenshot source, ни сохранение кадров/localStorage не нужны. Same-origin endpoint Original обеспечивает origin-clean canvas и reauth; redirect на S3 здесь не допускается. При ошибке/истечении сессии показать причину, сохранить draft и старый published player.

Для compaction выделить **существующую** pure timing часть `parseCutPlan`, `planDuration`, `mapTime`, `COMPACT_FPS`, `COMPACT_XFADE_SECONDS` в `packages/shared/src/cut-timeline.ts`; worker compaction переэкспортирует их, graph generation остаётся на worker. Это перенос без изменения алгоритма, проверяется прежними compaction tests. Preview проходит сохранённые retained segments; на0.08s crossfade использует hard cut в midpoint с тем же output duration/time mapping, не пытается имитировать два decoder/audio mixers. В переходе можно открыть исходник и проверить обе стороны; фраза рядом с preview: «Проверка кадра и движения. Переходы, музыка и подписи окончательно собираются после применения». Preview не называется финальнымMP4. Gate требует проверку всех retained segments от начала до конца, включая ±0.5s вокруг cuts.

Shared preview time mapping возвращает source timestamp(s) для output position; если crossfade даёт две позиции, draft выбирает раннюю до midpoint, позднюю после. Native source audio следует выбранной позиции; финальный music/packshot mix в preview не обещается. Relative clip progress использует planDuration, end clamp и seeked, а не исходную продолжительность всего файла. Синхронизация screen/camera в canvas всегда точная, поскольку drawImage один и тот же video frame. Доказательство time mapping отдельно от заявления о frame-exact browser seek.

При первом **явном** включении режима seed-analysis по ADR-004; status/ready/error отображаются в существующей области preview. При достаточном seed camera предлагается автоматически; optional ROI controls остаются закрыты. Обновление seed/polling может заполнить только pristine draft, никогда не затереть dirty пользовательские ROI. Любое изменение layout/ROI или применённого seed сбрасывает checkbox просмотра; pending confirmation считается пользовательским выбором и не перезаписывается поздним seed. Radio01/02/03, sliders, close/cancel, playback, quota-read —0 render mutations/jobs/charges. Открытие `<details>` само по себе не означает применение. Нет обязательного нового wizard.

Apply показывает выбранный clip/вариант/камеру/fallback, подтверждение просмотра областей на всём фрагменте и **серверные** limit/remaining/reset состояния `user_rerenders`. День/reset вычисляются existing moscowDay/quotaResetAt, owner exemption читается hasOwnerUnlimited; unlimited показывается без выдуманного остатка. Число20 или «бесплатно» не зашивается. Quota read advisory; mutation повторно проверяет её атомарно. После accepted request старый MP4 доступен и сохраняет mounted identity до фактической new published version. Polling показывает pending/failed/conflict; local draft живёт при fail; reload раздельно восстанавливает accepted server intent/published config и локальный draft по политике ниже. Close settings/polling не сбрасывают draft. При external publish и dirty draft сообщить конфликт; не заменять его молча.

### Доступные controls, confirmation и async status (ACC-01/02)

Native `<details>/<summary>`, radio group и range controls сохраняют keyboard semantics и видимый focus. Выбор цели имеет доступное имя «Уточняемая область» и значения «Экран»/«Камера»; radio01/02/03 названы полностью. Каждая ROI control строит label из **текущей** цели: «Камера: положение по горизонтали, %», «Камера: положение по вертикали, %», «Камера: ширина, %» (для экрана — «Экран: …»); аналогично height, если управляется существующим control. Отображаемый readout и accessible value берутся из одной canonical normalized ROI, а не из сырого event.target. Проценты относятся к ширине/высоте ориентированного source; min/max/step и `aria-valuetext` содержат эти единицы. Смена цели загружает её ROI целиком; каждое изменение сначала normalize+clamp, затем атомарно обновляет geometry, DOM value, min/max и readout. Если width растёт и x зажат, x-control тоже обновляется: нет скрытого расхождения числа и crop. Нативный range использует value/min/max; `aria-valuenow` при custom role не расходится с ними. Не добавлять новых controls ради этого контракта.

Confirmation переиспользует существующий dialog: доступное имя через `aria-labelledby` на видимый заголовок «Применить оформление клипа», описание содержит clip/variant, состояние focus/camera, sampling limitation и реальную quota. При открытии focus на заголовке с tabindex=-1 либо первом подтверждающем checkbox, внутри modal удерживается Tab/Shift+Tab. Escape и «Отмена» закрывают dialog без apply, сохраняют draft и возвращают focus на вызвавшую кнопку; если её больше нет, на доступный summary этого clip. После accepted focus возвращается на устойчивый summary/статус выбранного clip, не исчезающий disabled node. Закрытие `<details>` не бросает focus на hidden input: переносится на summary по пользовательскому действию.

Один существующий status region `role=status`/polite/atomic объявляет **переходы**, не каждый polling: seed pending («Определяем область камеры»), ready («Область камеры предложена; просмотрите весь фрагмент»), unavailable (причина + необязательное уточнение/весь экран), preview ready/loading/unsupported (что доступно дальше), conflict (черновик сохранён; нужна проверка актуальных настроек), accepted («Пересборка принята; прежний клип доступен»), failed (причина + повтор/правка). Ошибка действия связывается с control/description; announce не вызывает focus(). Сравнивать семантические state/reason/operation identity, а не ссылку нового polling object. Неизменный pending/ready не объявляется повторно. Текст whole-screen и sampling limitation присутствует в preview и confirmation, читается assistive technology. Manual screen-reader QA остаётся отдельным доказательством реализации.

### Черновик при навигации и reload (UX-01)

Переиспользовать форму closed schema + try/read-back из `lib/upload-resume.ts`, dirty/pending из `ClipMusicChoice`, lifecycle `beforeunload` из `Uploader`. Не использовать upload key/schema: приватные функции внутри уже планируемого `ClipLayoutChoice` сохраняют только version1/accountScope/clipId/sourceRevision/baseRenderVersion/canonical layout и, если apply исход неизвестен, **тот же** request_key/expected versions. Ни кадры/URL/source key/название записи, ни cookie/token не хранятся. Account scope приходит из owner-only layoutInfo (новое поле accountScope из текущей session; добавляется в уже планируемый DTO); не клиентский authority для RPC.

На каждое изменение до сообщения «Черновик сохранён в этой вкладке» синхронно записать и перечитать sessionStorage key, scoped по account+clip; dirty local state при ошибке остаётся. Запись живёт в этой вкладке до успешного apply/явного discard/смены account, удаления/истечения ресурса либо закрытия tab. Закрытие editor, смена clip и внутренняя навигация не удаляют запись. При возвращении/refresh сначала авторизованное layoutInfo+metadata, затем closed validation draft; восстановить только совпадающие account/clip/sourceRevision. При новой renderVersion сохранить draft отдельно, показать конфликт и сбросить reviewed; автоapply запрещён. Source mismatch/недоступный ресурс отбрасывает draft с явной причиной. Никакой cross-account restoration; выход/смена account очищают in-memory state и записи прежнего account.

Восстановленное: «Черновик восстановлен в этой вкладке; ещё не применён». Нет записи: «Показаны сохранённые настройки; черновик этой вкладки не найден». Storage недоступно/запись повреждена: конкретная причина и «Несохранённые изменения не восстановлены». Эти сообщения находятся в существующей status области; accepted intent читается с сервера отдельно. Восстановленный draft не считается просмотренным: reviewed=false, чтобы пользователь сверил актуальный source. Поздний seed/polling не перетирают restored dirty/confirming state. Неизвестный исход apply сверяется с server intent/exact replay прежде новой operation, чтобы reload не создавал второй charge.

Если sessionStorage запись/проверка не удалась, **до ухода**, сразу при изменении показывать постоянное «Черновик хранится только до ухода с этой страницы. Не удалось сохранить его в этой вкладке». Пока dirty, подключён native beforeunload (по существующему pattern); отмена браузерного выхода сохраняет DOM/draft. Для управляемых UI переходов/смены clip при failed storage используется browser native confirm о потере; cancel оставляет clip/route/focus/draft. Browser back в пределах SPA нельзя надёжно отменить через beforeunload: явное предварительное предупреждение — предел fallback, после возврата всегда показано отсутствие восстановленного draft. Не обещать crash/reload recovery при заблокированном/очищенном storage. При рабочем storage back/forward/refresh восстанавливают draft без зависимости от cancellable navigation. Нового router/history manager/страницы/wizard нет.

### Один звук при каждом play (ACC-03/UX-03)

Thin parent coordinator в VideoDetail регистрирует существующие refs preview, published player(s) и Original. **Каждый** `play` любого источника синхронно вызывает `onMediaActivate(kind, clipId, node)` и pause всех остальных refs до продолжения воспроизведения; регистрация/обработчик действуют и для уже выбранного clip, не зависят от изменения selectedClipId. Существующий ClipCard `onSelect` остаётся отдельно от media arbitration. Все шесть направлений preview↔published↔Original обязательны. Polling не remount-ит published/Original узлы; pause сохраняет currentTime. Close/clip change дополнительно pause preview, отменяет frame callback, освобождает decoder; восстановленный draft не исчезает. Play rejection не включает другой player автоматически. Никакого глобального media manager и второго audio mixer.

## Rationale
D1 требует original source, а не готового crop. D2/D4 достигаются browser-only composition и отдельным explicit apply. D3 reuse защищённого Original endpoint исключает второй публичный source access path. Exact encode preview был бы дороже задачи и провоцировал новые renderjobs.

## Consequences
### Positive
Одна source playback позиция, мгновенный local layout change, reuse existing layout tokens и player lifecycle.
### Negative / Accepted Downsides
Не все source codecs проигрываются браузером; unsupported показывает конкретный отказ preview, download Original остаётся доступен, apply не выдаёт непроверенный draft за просмотренный. Crossfade/music/ASS не имитируются точно. По0.08s переходу требуется проверить соседние source состояния; окончательная приёмка — настоящий MP4. Unsaved draft хранится только в sessionStorage текущей вкладки; при запрещённом/очищенном storage возможна потеря после явного предупреждения. Pending intent восстанавливается с сервера отдельно; persistence не является подтверждением apply.
### Follow-up ADRs
ADR-002 — request identity; ADR-004 — advisory auto seed. Новая proxy/auth/CORS система в этой фиче не создаётся.
### After-action Review
Owner: UI автор и координатор. Через30 дней после приёмки: unsupported codecs, failed seeks и конфликты draft/publish.

## Confirmation
- Method: mounted React browser tests Chromium/WebKit, real synthetic same-origin Range video,390/1440 обе темы; owner wholeclip acceptance.
- Monitoring: без логирования source URLs/кадров; счётчики mutation requests/jobs/quota в тестах; UX state error/loading/ready/pending/failed проверяется снаружи.
- Success metric: screen/camera sample counter равны; все retained segments доступны; radio/slider/cancel дают0 render calls; polling не меняет video node/dirty draft; одна seed operation при explicit mode; apply retry использует тот же request key.
- Owner: автор UI + независимый accessibility/QX QE.
- Load-bearing property: draft не запускает платный/долгий render и не разрушает опубликованный клип, private media доступно только owner.
- R2 oracles: `roi_accessible_values_follow_target_and_clamp`, `confirmation_focus_and_semantic_status_announcements`, `dirty_layout_survives_navigation_reload_and_late_seed`, `storage_failure_warns_before_loss_and_cancel_keeps_draft`, `every_media_play_pauses_the_other_two` в browser suite. Проверки монтируют реальные controls/player refs: статичные camera labels, stale x после clamp, повтор объявления того же polling, потеря draft и play уже selected clip должны ломать тест.
- Required automated check: `tests/browser/clip-layout.test.ts`, `tests/screen-layout.test.ts`, `tests/clip-layout.integration.test.ts`, `tests/compaction-media.test.ts`.
