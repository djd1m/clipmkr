# Наглядная проверка Zoom на настоящей записи

## Граница работы

Поручение владельца 16.11.2026: вместо неподходящей синтетической записи подготовить короткий настоящий Zoom-фрагмент «до → после», используя согласованный03 «Фокус на действии». Это подготовка приёмочного медиа по существующим ZF-03/04/05 и ADR-001, без изменения требований, приложения или миграций. Основной feature-adr/QE не открывается заново; новых успешных checkpoints этот документ не объявляет. OpenSpec `openspec/changes/zoom-screen-focus/specs/screen-face-layout/spec.md` остаётся журналом существующих требований.

Исходная запись: `598ed160-6760-45c8-9731-90b0fa3e8d69`. Не заменять её готовые клипы или настройки. Использовать ограниченный20-секундный фрагмент с настоящим экраном и камерой; отдельные файлы для владельца. Пользовательские кадры, MP4, подписанные URL и ключи S3 не публиковать в Git.

## Переиспользование и выполнение

- Закреплённый dz recall: урок о непригодности whole-screen/camera=null для визуальной приёмки прочитан фактически.
- Штатный `renderClip` из опубликованного worker image `sha256:03e0e7e1da09cddb42bffe8eeb697d2df4c98bb81810c5cf4df328aa1f9d641a`; существующие YuNet, shared layout geometry и FFmpeg. Никаких новых библиотек или детектора.
- Ручные области из ранее исследованного реального кадра: screen(0,40,1496,886), focus(550,100,720,720), camera(1496,0,320,180), source1816×968. Это настройки именно этого примера, не координаты алгоритма для всех записей.
- Без новой расшифровки/LLM, списания кредитов, заданий BullMQ и записи в БД. S3 только GET существующего исходника. Локальные файлы в приватном каталоге; ограниченные операции под наблюдением до терминального результата.
- Автор подготавливает пример и замеры; независимый `gpt-6.1-terra xhigh` в отдельной сессии получает требования и фактическое медиа. Результат не считается пользовательской приёмкой автоматически.

## Достаточные проверки

| Требование / риск | Проверка |
|---|---|
| Камера реально присутствует, не синтетический портрет | Native detector outcome + визуальные кадры начала/середины/конца, изменение пикселей камеры |
| Действия видны, лицо не дублируется | Исходник рядом с результатом; source screen исключает исходную webcam; проверить кадры и всю длительность |
| Камера не скрывает выбранный фокус | Фактические geometry source/destination и отсутствие пересечения protectedAction/camera |
| Звук и время сохранены | ffprobe, полное декодирование, совпадение20s source excerpt/result; без уплотнения пауз, музыки и новых субтитров |
| Доказательства не подменяют продуктовую приёмку | Отдельно указать native-render demonstration, UI E2E, human acceptance и ограничения |

Продуктовые тесты старой ревизии не объявляются новым прогоном. При отсутствии изменения исходников повторять полный набор тестов приложения не требуется. Если реальное медиа выявит дефект, сначала зафиксировать причину и необходимый diff в существующем feature-adr, затем выполнять применимые gates.

**Существенное ограничение:** в финальном варианте PiP закрывает часть верхнего текста/панели браузера на нескольких проверенных кадрах. Подтверждённый focus ниже него свободен. Полная читаемость всего browser и комфорт чтения на телефоне не доказаны; нельзя назвать это полной визуальной приёмкой владельца. Новый auto action tracker, автоматическое перемещение PiP по содержимому и исправление алгоритма в рамках этой демонстрации не выполнены.

Владельцу передаются отдельные MP4 исходника, результата и синхронного сравнения. Это демонстрация настоящего опубликованного renderer на явно выбранных областях; **не новая публикация клипа в кабинете и не новый UI E2E**. Полное воспроизведение проверено браузером; независимый визуальный осмотр ограничен пятью кадрами. Старые clip IDs, render versions, кредиты, задания и настройки пользователя не менялись.

Code/spec anti-drift: приложение, зависимости, схемы, OpenSpec требования и конфигурация не изменены. В Git попадает только этот протокол; пользовательское медиа и приватные adapters остаются вне репозитория. Основные feature-adr gates прежней реализации и владелец визуальной приёмки не подменяются новой квитанцией. Cloud.ru/DNS не затрагивались.
