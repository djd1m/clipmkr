# Диагностика UPLOAD-001, 17.11.2026

В рабочей БД найдены две записи указанного аккаунта за день обращения. Обе
обработаны. Имя исходного файла не хранится в БД, поэтому точная заявка SD-WAN
по этим данным не идентифицирована. Рабочие видео, заявки и S3-объекты не менялись.

В браузере на опубликованной ревизии `4603e54` с подменой только операций
передачи воспроизвели последовательность: пауза → включить музыку → выбрать тот
же файл. До повторного выбора продолжение недоступно. Повторный выбор разрешает
продолжение, сбрасывает переключатель музыки и блокирует его. Оба запроса
`video.create` имеют один ключ и прежнее значение музыки. Это объясняет
потерю настройки в воспроизводимом сценарии.

Отдельный адресный прогон на PostgreSQL и реальном Cloud.ru S3 подтвердил
HTTP 200 первого PUT, конфликт 409 при попытке изменить музыку в
`video.create`, тот же `video_id` и тот же multipart при повторе с исходными
настройками. ListParts подтвердил первую часть, выдана только подпись второй,
использован один слот загрузки. Один сценарий выполнен успешно, остальные
17 отфильтрованы по имени. В первом прогоне ожидание сравнивало ETag с внешними
кавычками и без них; исправлено только это сравнение в диагностическом тесте.
Тестовый префикс очищен. Проверка итогового клипа остаётся на исправленной сборке.
