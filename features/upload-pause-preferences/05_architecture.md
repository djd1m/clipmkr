# Контур изменения

`Uploader → video.create (транспорт, прежние options) → ListParts → PUT недостающих частей`
остаётся прежним. `Uploader → upload/complete (manifest + необязательный финальный снимок) →
PG FOR UPDATE → queued с итоговыми полями → идемпотентная очередь`.

Изолированы три состояния: выбранные в текущей вкладке значения; snapshot первоначального
create; неизменяемый payload Complete. Хранилище вкладки принимает прежние записи v2 и
строго ограниченные необязательные поля. Переход к созданию нового upload остаётся
отдельным явным действием. Отмена локальной попытки не удаляет объект или части.
Граничные функции: полный SHA, проверка account_scope на create, проверка ownership
в Complete, Zod и семантический CTA, список частей S3, fail-closed при недоступном
sessionStorage. Отказ от записи настроек после queued закрывает гонку и дубли.
