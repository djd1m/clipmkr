## Находка UXA-001 — HIGH, structural

**Где:** `03_adr/002-preserve-state-with-stable-owners.md:30,38-44` обещает после исчезновения/скрытия исходной кнопки вернуть фокус к summary текущего клипа, затем к заголовку результата. `05_architecture.md:17,121-126` связывает это с единой гостевой панелью. Существующий `apps/web/src/app/videos/[videoId]/VideoDetail.tsx:15-20` содержит обычный `<h1>` без `tabIndex`; строки 113–132 строят карточки по `clips.map` и допускают пустой список. План `06_implementation_plan.md:47,53` упоминает возврат фокуса в целом, но не последний fallback.

**Сценарий и риск:** пользователь открыл гостевую форму клавиатурой, затем при обновлении DTO исходная карточка исчезла и карточек больше нет; при закрытии уже нет trigger и summary текущего клипа. Названный существующий h1 нельзя просто сфокусировать вызовом `focus()` без добавления программной фокусируемости; активный элемент рискует остаться в скрытом контексте или уйти на body. Это контрпример к достаточности описанного способа, а не наблюдённый runtime-дефект будущего кода.

**Требуемое исправление design:** в ADR-002 и Confirmation явно определить всегда доступный связанный с результатом fallback, программно фокусируемый без добавления лишнего постоянного Tab-остановa (например h1 с `tabIndex=-1`), условия его видимости и порядок после удаления последней карточки. Согласованная компоновка не меняется. **Confirmation:** будущий browser test `share_focus_return_missing_trigger` открывает форму, заменяет DTO на пустой список и закрывает её; `document.activeElement` — подключённый видимый fallback, следующий Tab продолжает последовательную навигацию. Вторая ветка с другим выбранным клипом проверяет summary; удаление механизма фокусируемости обязано ломать первую ветку. Отдельный независимый reviewer должен проверить исправленный design на новой ревизии; тесты пока NOT RUN.

## Будущие проверяемые сценарии, без дополнительных условий

- **Keyboard и формы:** Tab/Shift+Tab/Enter/Space по всем ролям; закрытые native details не содержат Tab-целей. Для CTA без submit и для вложенного owner limit 1/1441/2.5 раскрыть каждого предка, показать название и ошибку, сфокусировать реально неверное поле и проверить ноль upload/RPC; одновременно неверные поля, переход к первому и повторное исправление проверить в Chromium/WebKit. Начало и окончание перехода в account и blogger stats: понятный заголовок, focus/Back/direct URL/reload и guard загрузки.
- **Контраст и цвета:** на фактических computed foreground/background во всех dark/light × workspace/studio для обычного текста, крупного текста и значимых границ/состояний проверить соответственно 4.5:1, 3:1 и 3:1, включая error, selected, focus и расположение indicator относительно соседних цветов. Измерять реальные сочетания, не одни имена CSS tokens; исключения и состояния disabled оценивать отдельно. ADR-003 сохраняет tokens, но одни скриншоты и существующий `:focus-visible` не доказывают контраст; при обнаружении конфликта согласовать scoped коррекцию.
- **Reflow:** 320/390/1440 CSS px × обе темы/layout, отдельно 200% text zoom; account и stats — отдельные состояния, а не снимки dashboard. Длинные URL/email, цена/условия, 0/1/4 клипа: текст, управление, фокус и сообщения не обрезаны, нет нежелательного горизонтального скролла; проверить keyboard при увеличении. 320 CSS px не равен сам по себе доказательству браузерного 400% zoom.
- **Гость и диалоги:** открытие по клавиатуре ставит фокус в имя, закрытие возвращает его, fallback UXA-001; после смены состава/недоступности клипа согласие сброшено и create недоступен; busy/ошибка озвучиваются и не теряются при закрытии. Если будет реальный modal dialog — имя/роль, вход, ограничение Tab, Escape при допустимом закрытии и возврат на видимую цель; дизайн выбирает contextual панель, поэтому modal не предполагается.
- **Player и статусы:** доступное имя нативного video, управление без мыши и порядок player→download→«Ещё» в обычном и partial состоянии, player не пересоздаётся от poll; при status/error/ready screen reader получает осмысленное объявление без повторов каждые 5 секунд. Тестировать реальными AT, включая изменившийся live region; alert не должен скрывать доступные клипы. Retry только при серверном `next_action`, отсутствие partial retry не маскировать UI.
- **Сопоставление:** утверждённый HTML → соответствующий React компонент → проверка в одинаковых state/theme/layout/width. Прототип содержит демонстрационные действия и не является oracle серверной авторизации, personal TEST checkout, auto-link или recovery capability. Сохранить эти существующие потоки, без нового API/DB/pkg.
