## Подтверждённые замечания

### UX-R1 · P1 · Согласие автоматически переносится на следующий пакет

**Место:** `docs/design/2026-11-05-ux-simplification.html:51`, `:68`, `:73`; FR-5 и OpenSpec о сохранении согласий. Native source: `apps/web/src/app/clips/GuestPacks.tsx:43` сбрасывает `consent` после успешного создания.

**Воспроизведение:** готовые клипы → «Ещё» → «Поделиться» → «Отправить гостю» → имя первого гостя + согласие → создать закрытый пакет → включить ссылку → закрыть → выбрать другой клип → снова открыть форму гостя. Новое имя пусто, новый клип выбран, но `guest-consent.checked === true`, а кнопка создания уже enabled. После ввода другого имени новый пакет можно создать без подтверждения согласия для него. Это наблюдение локального прототипа; реальная публикация не выполнялась.

**Исправление:** согласие привязать к конкретному создаваемому пакету и сбрасывать после create/начала нового пакета. Начальная форма нового гостя должна требовать явного подтверждения; сохранение черновика в рамках той же задачи не должно выдавать согласие на следующую.

### UX-R2 · P2 · Подтверждённый CTA исчезает при воспроизведении

**Место:** HTML `:51`, `:62`, `:67`, `:73`; FR-3. Native source: `apps/web/src/app/videos/CtaFields.tsx:31` хранит текущий и сохранённый вид/URL отдельно.

**Воспроизведение:** результат → «Ещё» → «Изменить оформление» → раскрыть настройки записи → выбрать «Перейти по ссылке» → `https://example.test/cta` → «Сохранить призыв» → Play. Макет сообщает о сохранении, но следующий render возвращает `edit-cta-kind=none`, пустой URL и закрытые настройки. Повторное открытие не возвращает заданное значение. Простое сворачивание без render само по себе значения не уничтожает; дефект возникает от доступного основного действия воспроизведения.

**Исправление:** хранить состояние CTA записи и музыки выбранного клипа независимо от перерисовки/панели; после сохранения и повторного открытия показывать действующие значения и краткий итог отклонений. Это локальное состояние макета, нового API не требуется.

### UX-R3 · P2 · Скрытое неверное поле блокирует owner-save без видимой ошибки

**Место:** HTML `:53`, `:73`; FR-5/FR-7. Native validation owner API: `apps/web/src/server/blogger-owner-handler.ts:7` — целое 2–1440 и обязательная причина; серверный контракт не предлагается менять.

**Воспроизведение:** owner → найти аккаунт → назначить → дополнительные настройки → лимит `1` → свернуть → заполнить корректную причину → «Сохранить назначение». Сохранение заблокировано; details остаётся закрытым, фокус не переходит к лимиту. Chromium выдаёт `An invalid form control with name='' is not focusable.` Пользователь не получает обнаружимого исправления.

**Исправление:** при invalid раскрывать контейнер поля, выводить понятную ошибку и фокусировать поле. Проверить также дробь и верхнюю границу. Контроль валидности не переносить только на отправку сервера.

### UX-R4 · P2 · После закрытия теряется управление уже включённой гостевой ссылкой

**Место:** HTML `:51`, `:68`; FR-3/FR-5. Native source: `apps/web/src/app/clips/GuestPacks.tsx:66` сохраняет и показывает список созданных пакетов с copy/revoke.

**Воспроизведение:** создать пакет → включить ссылку → «Закрыть» → «Поделиться». До закрытия в DOM есть copy/revoke гостевого пакета; после возврата оба отсутствуют, остаются только короткая ссылка клипа и вход в новую форму гостя. Другого входа к прежнему пакету в восьми экранах нет. Пользователь не может вернуться к сроку/copy/отзыву доступа.

**Исправление:** отделить сохранённый список пакетов от видимости контекстной панели. Добавить обнаружимый возврат к существующим пакетам с состоянием, сроком и отзывом; закрытие панели не должно уничтожать управление доступом.

### UX-R5 · P2 · Часть обещанных дополнительных функций не имеет нового места в макете

**Место:** HTML `:51–52`; `audits/regular.md` (музыкальные preview и guest selection), `audits/blogger.md` (дополнительные referral-коды); FR-3 и `04_screen_decisions.md` о сохранении функций.

**Наблюдение:** гостевая форма показывает единственный предвыбранный disabled checkbox, поэтому нельзя собрать несколько готовых клипов; нет входа создания дополнительного referral-кода; в контекстном редактировании музыки нет предпрослушивания. Матрицы обещают сохранить эти существующие возможности контекстно/в advanced. Источники: `GuestPacks.tsx:58`, `PartnerPanel.tsx:54`, `ClipMusicChoice.tsx:32`. Полный музыкальный каталог или действующие сетевые запросы для макета не требуются.

**Исправление:** показать соответствующие контекстные входы/controls либо явно обозначить в самом предложении, где сохраняется неизменённый действующий интерфейс. Не добавлять эти вторичные действия на основной экран; привести audit → решение → макет к одному набору возможностей.
