# ADR-001. Приватный адаптер уведомлений Libredesk

## Status
Принято для реализации в пределах поручения владельца.

## Context
Libredesk v2.9.0 подписывает фиксированный JSON события. Telegram принимает отдельный запрос с заранее выбранным чатом и безопасно сформированным текстом. Прямой вебхук отправляет в Telegram всё событие, а URL с токеном попадает в журнал Libredesk.

## Decision
Запустить один сервис на существующем образе Node.js рядом с Libredesk, без host-портов. Принимать только HMAC-подписанные сообщения, фильтровать входящие сообщения контакта, передавать только фиксированный текст и ссылку на диалог. Секреты передаются в среду контейнера из закрытых файлов. Telegram-вызов ограничен по времени, одно обращение к Bot API на событие. Сбой доставки не меняет обработку чата.

## Consequences
Сохраняем существующую группу и Libredesk. Единственный новый процесс не имеет доступа к БД. Уведомления best effort. Для отката отключают только новый вебхук и останавливают сервис.

## Confirmation
- Проверка сырых байтов подписи, полей фильтра, ссылки, конфигурации и транспортного отказа — `tests/libredesk-telegram-adapter.test.mjs`.
- Docker Compose и браузерный проход из виджета с отдельным синтетическим диалогом на текущем VPS.

Отдельно проверить ошибки Telegram (429/5xx, отрицательный JSON, тайм-аут) с одной попыткой и HTTP 204, а также 401/400/413 входа без вызова Telegram. Для E2E два уведомления подтверждаются через Bot API по ID и совпадению группы и текста, ответ сотрудника проверяется в виджете. Открытие ссылки проверяется с действующей сессией сотрудника.
