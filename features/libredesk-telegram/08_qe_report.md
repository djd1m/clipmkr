# Проверка Telegram-уведомлений поддержки

## Primary QE pass

Независимый `gpt-6-astra xhigh`, отдельная сессия без истории автора. Первичный снимок `30fbf19196bdf424d63b3128e433c42234a662d904fa8169e4eb11c17de45fc8`, исходный conditional с четырьмя условиями. Исправленная ревизия `7c2582992a832404e068180cb3be0234dc4cf534ab72f09375ca65d831d0d085`.

| Условие | Результат исправления |
| --- | --- |
| qe-primary-001 | Включённая SSRF-защита имеет только /32 адаптера. Штатный подписанный тест Libredesk получил HTTP 204. Контрольный внутренний адрес остался заблокирован. |
| qe-primary-002 | `npm run test:support-telegram` исполнил 5/5 с Node 22 и в закреплённом Docker-образе. |
| qe-primary-003 | Реальный контейнер healthy, точный digest, user=node, код режима 0644. Публикуемых портов нет. |
| qe-primary-004 | Журнал отклонений содержит только тип и код причины. Тест проверяет точный набор событий без пользовательских данных. |

Контрольное испытание работы Libredesk было на выключенной основной подписке. Бот не получил дополнительных запросов. Перезапустился только Libredesk, внешний health восстановлен, отметка запуска Clipmkr web совпала. Проверочное SSRF-правило в списке вебхуков удалено.

## Проверки и границы

- `openspec validate libredesk-telegram --strict`: exit 0. Подпись сырого тела, первое и последующие сообщения, исключения, ошибки Telegram и токен покрыты целевой проверкой.
- `npm run test:support-telegram`: 5/5. Фальсификация HMAC, фильтра закрытых сообщений и логирования отклонений в отдельных копиях привела к падению соответствующих тестов.
- `docker compose ... config --quiet`: exit 0 с закрытыми переменными. Код и compose в staged-каталоге проверены по SHA-256, source совпадает со снимком ревью.
- Code/spec anti-drift: один webhook `message.created`, подпись HMAC, три поля фильтра, URL по UUID, отсутствие пересылки тела и данных контакта. Один исходящий вызов, best effort. Принятые события получают 204, а недоставка видна отдельно. Закрытые env и конфигурация Libredesk не входят в Git.
