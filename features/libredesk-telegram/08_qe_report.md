## Проверки и границы

- `openspec validate libredesk-telegram --strict`: exit 0. Подпись сырого тела, первое и последующие сообщения, исключения, ошибки Telegram и токен покрыты целевой проверкой.
- `npm run test:support-telegram`: 5/5. Фальсификация HMAC, фильтра закрытых сообщений и логирования отклонений в отдельных копиях привела к падению соответствующих тестов.
- `docker compose ... config --quiet`: exit 0 с закрытыми переменными. Код и compose в staged-каталоге проверены по SHA-256, source совпадает со снимком ревью.
- Code/spec anti-drift: один webhook `message.created`, подпись HMAC, три поля фильтра, URL по UUID, отсутствие пересылки тела и данных контакта. Один исходящий вызов, best effort. Принятые события получают 204, а недоставка видна отдельно. Закрытые env и конфигурация Libredesk не входят в Git.

## Активация на clipmkr.ru

- Native QE `evaluate`: closed, снимок `7c2582992a832404e068180cb3be0234dc4cf534ab72f09375ca65d831d0d085`. Повторная проверка исходным `gpt-6-astra xhigh` закрыла все четыре условия. Код поставки находится в коммите `8c17afceb6884b877ade551a0d476e800c05dac0`.
- Включён один подписанный вебхук Libredesk `message.created`. Отдельный Compose-сервис остаётся healthy без опубликованного порта.
- В браузере отправлены первое и второе синтетические сообщения в одном новом диалоге. Libredesk подтвердил два HTTP 204. Telegram Bot API подтвердил два уникальных сообщения, ожидаемые чат и текст со ссылкой. Тестовый сценарий остановился после второй отправки, поэтому остаток проверен на том же диалоге без повторной отправки.
- В браузере под отдельной сессией сотрудника открыта точная ссылка на этот диалог. Обе реплики видны. Ответ сотрудника виден в исходном виджете. Журнал адаптера подтвердил фильтрацию исходящего сообщения без третьего вызова Telegram.
- Приёмка подтверждает принятие уведомлений Telegram Bot API. Личное открытие сообщений получателем в Telegram-клиенте не наблюдалось. Очередь доставки и автоматический повтор отсутствуют, как задано в требованиях.
