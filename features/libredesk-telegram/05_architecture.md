# Архитектура

Виджет Clipmkr → Libredesk → подписанный HTTP POST по внутреннему DNS Docker → адаптер → Telegram Bot API → закрытая группа. Сотрудник отвечает в текущей панели. Клиент видит ответ в виджете.

Фильтр требует `type=incoming`, `sender_type=contact`, `private=false` и валидный UUID диалога как часть заранее определённого URL. Невалидный ввод и ошибку Telegram журналировать в виде кода, без тела, заголовков и полного URL. Токен и чат подаются из ранее созданного профиля. Webhook Secret генерируется отдельно от токена бота. Событие `webhook.test` можно принять без отправки в группу.

Один Compose overlay связывает сервис с действующей сетью. Лимиты ресурсов и тела запроса, ограничение длительности доставки, отсутствие доступа к Docker socket, базе данных и bind mount приватных файлов. Производственный вебхук включается после согласованной проверки локального контейнера. Откат ограничен подпиской и сервисом адаптера.

## Контракт источника

Проверен Libredesk [v2.9.0, приём сообщения из виджета](https://github.com/abhinavxd/libredesk/blob/v2.9.0/cmd/chat.go#L276-L298), [событие после сохранения](https://github.com/abhinavxd/libredesk/blob/v2.9.0/internal/conversation/message.go#L858-L864), [сериализация и подпись](https://github.com/abhinavxd/libredesk/blob/v2.9.0/internal/webhook/webhook.go#L363-L392). `X-Libredesk-Signature: sha256=<64 lowercase hex>` означает HMAC-SHA256 от точных байтов UTF-8 тела с отдельным секретом. JSON ниже схематический, тела из рабочих диалогов не используются.

```json
{"event":"message.created","timestamp":"2026-11-18T12:00:00Z","payload":{"uuid":"82f4894c-3191-4942-8896-c35844660041","conversation_uuid":"ec0f1213-2cf9-47b4-bdd2-0460a24bbcb7","type":"incoming","sender_type":"contact","private":false,"content":"SYNTHETIC_SENTINEL"}}
```

Идентификатор сообщения используется в контрактной фикстуре и не попадает в текст Telegram. Ссылку строим только из `payload.conversation_uuid`. Отсутствие либо несовпадение подписи выдаёт 401, включая изменение сырых байтов. Подписанный некорректный JSON, невалидная структура и неправильные типы обязательных полей фильтра и UUID дают 400. Чужое событие или корректное исключённое сообщение даёт 204 без отправки. Тело сверх лимита даёт 413. Негативные проверки подтверждают ноль обращений к Telegram.

## Подтверждение приёма

Подписанное принятое событие получает 204 независимо от результата отправки. У Telegram на одну попытку до 2 секунд. При HTTP 429/5xx, `ok:false`, ошибке сети или превышении срока журнал фиксирует обезличенный код отказа. При успехе отмечаем `message_id` после проверки ответа Telegram, совпадения чата и текста. Журнал пропуска содержит только код фильтра. ACK означает приём, результат доставки берётся из журнала. Повторы адаптером отсутствуют. Если снаружи заново прислать то же событие, допускается повторное уведомление. Никакого влияния на асинхронную работу виджета.
