В требованиях есть проверяемые серверные границы, снимок на video и ограниченный доступ владельца. Основные пробелы плана — недостаточно явное различение реального маршрута и статической разметки, сквозного 120-минутного результата и короткого/замоканного прогона, а также людей и нескольких записей одного человека.

## Условия покрытия

1. **QT-1 / HIGH / structural: серверный допуск и снимок.** В `tests/blogger-policy.integration.test.ts` создать записи через настоящий VideoService/create и пройти настоящий probe на изолированной PostgreSQL: обычный 5400/5400.1, блогер 7200/7200.1, override 9000/9000.1. Передать ложный лимит через клиент и получить прежний серверный результат. Изменить роль/override после create в обе стороны и доказать неизменность `video.source_limit_seconds` до probe и при retry. Для отказа проверить отсутствие списания минут/кредитов и отсутствие STT-вызова, а также корректный возврат upload-слота. Сохранить независимые квоты: роль блогера сама по себе не выдаёт оплаченные минуты. Проверка числа в исходнике или mock `acceptProbe` этого не доказывает.

2. **QT-2 / HIGH / structural: права и атомарность.** На реальном owner API и DB проверить матрицу anonymous/обычный/блогер/неактивный owner/активный owner, подстановку account_id и owner-флага, ошибочный origin, невалидные минуты/20/30/null и rate limit. У отказа нет изменений account и operator_action; у успешного изменения ровно одна согласованная запись аудита. Проверить откат при ошибке записи аудита. Запуск после добавления плановых тестов: `N5_ACCEPTANCE=1 npm test -- tests/blogger-policy.test.ts tests/blogger-policy.integration.test.ts tests/queue-probe.integration.test.ts tests/transcription.integration.test.ts tests/credit-packages.integration.test.ts`. Секреты не выводить; `DATABASE_URL` должен указывать на localhost БД с окончанием `_test`. Любой skip означает, что покрытие не получено.

3. **QT-3 / HIGH / structural: независимые месячные агрегаты.** В `tests/blogger-report.integration.test.ts` один привлечённый человек с несколькими video и двумя проверенными платежами должен дать одного человека, соответствующее число готовых записей и ровно два платежа без перемножения JOIN. Добавить второго человека, второго блогера, две ссылки одного блогера, self-referral/rejected, pending/failed/needs_review, несовпадающие payment_intent и возвраты по принятому фильтру. Границы месяца проверить вокруг московской полуночи, включая декабрь/январь; отдельно задать семантику времени для регистрации, использования и оплаты. Ставка null — без оценки, 20/30 — целые копейки с зафиксированным округлением. Команда: `N5_ACCEPTANCE=1 npm test -- tests/blogger-report.integration.test.ts tests/partner.integration.test.ts tests/partner.test.ts tests/partner-route.test.ts tests/billing.integration.test.ts`. Fake provider покрывает инварианты, но не снимает BLOCKED настоящего магазина.

4. **QT-4 / HIGH / structural: браузерный путь и сохранение кабинета.** `tests/browser/blogger-cabinet.test.ts` должен использовать настоящий localhost web/API и отдельные контексты владельца, блогера и клиента: существующая ссылка → регистрация → использование → совпадающая статистика; refresh и повторное событие не удваивают счётчики. Прямой запрос чужих данных отвергается. Владелец сохраняет лимит, блогер видит применимый лимит; ошибка API/клавиатура/320,375,1440/обе темы/Chromium и WebKit покрыты. Текущий `tests/browser/billing.test.ts` обслуживает статическую React-разметку: такой образец годится для вёрстки, но не доказывает обработчики, сессию или сохранение. Реальная команда данного проекта — `N5_ACCEPTANCE=1 npm test -- --config vitest.browser.config.ts tests/browser/blogger-cabinet.test.ts`; отдельный Playwright runner здесь не настроен. Нужен воспроизводимый startup localhost web и тестовых сессий, указанный в плане/тесте.

5. **QT-5 / HIGH / structural: длинный тракт и честные границы доказательства.** После unit/integration выполнить отдельную приёмку файла ровно 120 минут через upload/resume → probe → chunker → STT/credits → готовые клипы → просмотр/скачивание; сохранить длительность ffprobe, разрешённый снимок, переходы состояний и результат без приватного медиа/подписанных URL. Локальный тракт с контролируемым STT и реальными PG/Redis/MinIO даёт интеграционное доказательство лимита и очереди; его явно отделить от настоящей модели. В рамках данной рецензии платные вызовы запрещены. Baseline 88 минут и замоканный duration=7200 не закрывают реальную 120-минутную приёмку. До появления магазина оплата сохраняет BLOCKED; после предоставления профиля — checkout, отмена/отказ, проверенное событие, повтор события без двойных прав, повторный вход и использование полученных прав. Общие команды после реализации: `npm run typecheck`, `npm run lint`, `npm run build`; они не заменяют перечисленные сценарии.

Эти условия относятся к содержанию плана и будущим свидетельствам. Закрытие текущего QCSD требует внесения их проверяемого смысла в артефакты и повторной независимой проверки актуального snapshot; наличие этого отчёта не разрешает кодирование автоматически.
