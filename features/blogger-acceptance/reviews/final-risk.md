# Независимое QE / оценка риска выпуска Clipmkr

Проверено 2 ноября 2026 года, только чтение. Код: 002744d и 0f7fa36.

## Результат

Новых подтверждённых HIGH или MEDIUM дефектов в рассмотренном чужом коде и заявленной последовательности выпуска не найдено. Это не разрешение считать живую приёмку и общий прогон завершёнными: на момент ревью длинная запись ещё рендерится, клиентская проходит выбор, полный набор тестов выполняется. До фактических результатов выпуск не получает PASS по обязательным CJM.

## Проверенные существенные границы

- Отчёт владельца проверен независимо: действующий владелец, один repeatable-read снимок; отдельные агрегаты регистраций, уникальных активных людей и платежей; точные native-связи payment/intent/account/provider_payment_id/amount, succeeded, fulfilled, отсутствие review/refund, допустимые пакеты, assigned_at. Московские границы месяца корректны. Расчёт в целых копейках, без автоматической выплаты.
- Owner API/UI проверены независимо: actor берётся из сессии, Origin и rate limit обязательны, strict JSON и ограничение тела, обычному пользователю/блогеру доступ запрещён. Типы DB не попадают в клиентский runtime. Сохранение настройки не объявляется неуспешным из-за отдельного отказа обновления статистики.
- 0f7fa36 меняет только представление молчания и существующий мобильный промежуток: watchdog, приём расходов, отказные состояния и retry не изменены. Ошибка too_long больше не сообщает блогеру неверные 90 минут.
- Приватный compose прочитан только программной белой проекцией: web=0f7fa36, все три worker=002744d, main payments off=true, прежняя сеть n5-clipmaker_default и постоянные volumes сохранены. Значения environment не выводились и не открывались рецензенту.
- Read-only проверка основной БД на момент ревью: queued/transcribing/selecting/rendering отсутствуют. Поэтому текущих заданий, которые прямо сейчас оборвутся при замене worker, не обнаружено.

## Условия выпуска и известные ограничения

1. Сохранять заявленный порядок: резервная копия основной БД, штатная миграция 026 с проверкой SHA, все три совместимых worker, затем web. Не публиковать допускающий 120 минут web перед совместимыми worker. Откат не запускает старый worker с пределом 5400 поверх уже принятых длинных задач.
2. У worker штатный graceful close есть, но stop_grace_period в подготовленном compose отсутствует (Docker default). Сейчас основная очередь пуста; непосредственно перед заменой повторить проверку активных задач либо обеспечить завершение работы. Это конкретная граница безопасного переключения, не найденный дефект нового кода.
3. Приватный compose содержит только DB/Redis/web/3 worker, без proxy. Выполнять заявленные адресные обновления приложений; не применять к нему down или remove-orphans, иначе можно затронуть сохранённую маршрутизацию. Сам план этого не предписывает.
4. Основной контур остаётся paymentsoff, тестовый магазин и webhook -test остаются на отдельном n5-контуре. Общий S3, хост и внешние provider credentials означают разделение DB/Redis, но не полную изоляцию ресурсов и расходов. Удаление только собственных UUID-объектов; глобальная очистка бакета недопустима.
5. Отчёт использует текущую атрибуцию и текущую ставку. При смене ссылки историческое распределение регистраций может измениться; после нового assigned_at старые платежи новому источнику не приписываются. Это предварительная сводка, не неизменяемый реестр долга и не автоматическая выплата.
6. До приёмки дождаться фактов: длинное видео до готовых воспроизводимых/скачиваемых клипов; привлечённый клиент до готового клипа после настоящей тестовой оплаты; совпадение трёх контекстов и повторных уведомлений; общий набор тестов без неоговорённых провалов/пропусков. Успешный checkout или промежуточный rendering этого не заменяет.
