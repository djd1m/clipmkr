Статус: проект требований для реализации по текущему поручению владельца. Макеты01/02 от11.11 используются как эталон; перед любым кодом владелец должен получить ссылки и план. Это не новая квитанция K1/K2. Пользователь — автор записи; consumers — canvas preview, native FFmpeg, viewer/download, последующие music/CTA rerender. Владелец принимает UI на clipmkr.ru.

## Приёмочные требования

- MC-01:01 показывает весь подтверждённый screen без обрезки действия; камера справа поверх него как в эталоне. Для контрольного источника геометрия совпадает с исходным макетом с допуском растеризации≤2px на1080×1920. Камера не переносится над экраном и не уменьшается произвольно.
- MC-02:02 показывает camera справа сверху отдельно от увеличенной рабочей области ниже; контрольная ROI930×704 занимает полную ширину. Панели не меняются местами; aspect ratio обоих источников сохранён. Для контрольной геометрии тот же допуск≤2px.
- MC-03:preview и готовый MP4 используют одну версионированную геометрию, но oracle в тестах вычисляется независимо из закреплённого оригинального макета. Сначала существующий wrong01/02 должен дать RED по позиции/масштабу; build/import errors не являются полезным RED.
- MC-04:01/02 доступны в уже одобренных дополнительных настройках;03 остаётся вариантом по умолчанию. Переключение — локальный черновик, без применения/рендера/списания. Не хардкодить исследовательские пиксельныеROI для всех записей и не выдавать центр кадра за распознанное действие. Существующий широкий screen не превращать молча в будто подтверждённую workROI.
- MC-05:для02 пользователь должен уметь подтвердить рабочую область нужного соотношения сторон; текущий width-only control этому мешает. Если нужен новый/изменённый control, до UI-кода создать и показать конкретный макет этого уточнения; не считать исходный composition mockup согласованием любого нового элемента. Точное решение — в ADR/плане до K2.
- MC-06:готовые существующие MP4,03/legacy, credits/retention/access, music/CTA сохраняются. Исправленная геометрия применяется только после явного выбора/подтверждения нового оформления. Смена музыки/CTA старого клипа не должна незаметно переводить старые01/02 на новую геометрию. Это требует отдельного решения о versioned композиции до кода.
- MC-07:реальное движущееся видео, camera source/timebase, no-camera fallback, cut_plan/subtitles/watermark сохраняют прежние гарантии.01 намеренно допускает PiP перекрытие угла screen, как в оригинале; это явно заменяет позднее blanket non-overlap для новой композиции, но не обещает невидимую камеру без риска перекрытия текста.
- MC-08:выпуск блокируют source pins/original oracle mismatch, непройденный обязательный тест, незакрытое значимое independent замечание, отсутствие проверенного QA-примера или фактическая ревизия, отличная от проверенной. Визуальная приёмка владельца отдельно от автоматического PASS. Без его согласования не обновлять эталоны и не обходить guard. Заявления об абсолютной гарантии не допускаются.

## Проверяемые сценарии

Контрольный source+ROI01→готовый01 matches etalon; тот же для02; wrong legacy geometry→RED; preview↔MP4 frame/geometry agreement; версия прежнего01/02 после music/CTA остаётся прежней; новое явное оформление→исправленная версия;03 unchanged; odd/SAR/rotated geometry и camera unavailable; двуклик/replay одного apply не повторяет debit; чужой account не получает source/clip. Последние security/financial checks переиспользовать существующие и запускать по реальному changed impact, без общего платёжного E2E при отсутствии изменений billing.

## Дополнение QER-03/QER-04: actual DB и административная граница,17.11.2026

Наблюдение, а не успешный этап: actual apply кандидата a6731d9a52700da2d6734c158709dba06e394b93 остановился17:15:51UTC до033. PostgreSQL сообщил42501 permission denied for schema public на CREATE TABLE IF NOT EXISTS _schema_migration. Backup ошибочно выбирал другую POSTGRES_DB. Исходный18763e1530739aff87825634af75a670bb62198f восстановлен17:21, public health200;033 отсутствует. Failed evidence сохраняется, исторические K1/K2/QE не переписываются.

- FR-ZOOM-DB-001 MUST: до pause и до установки pauseAttempted квалифицировать реальное DATABASE_URL каждого web/worker-stt/worker-llm/worker-video: DNS/endpoint к pinned DB container, database name/OID, runtime role/search_path и равенство целевого назначения. Restricted runtime не требует pg_control_system или DDL. Existing admin connection отдельно подтверждает system_identifier/OID/name того же bound PostgreSQL и права CREATE в нужной schema, journal SELECT/INSERT и effective inherited ownership authority ALTER clip_layout_intent (superuser либо pg_has_role(..., owner, USAGE), не просто MEMBER, требующий SET ROLE). Нет credential/host/query overrides из caller manifest. Ошибка qualification вызывает ноль pause/Caddy persist/load/stop/automatic-close.
- FR-ZOOM-DB-002 MUST: после штатного drain backup вызывает native pg_dump с явным actual app database name, qualified existing admin user, fresh0600 archive; сохраняет exit/size/SHA/TOC и DB identity. Отдельный realPG test восстанавливает только свой synthetic fixture dump в своей второй БД, проверяя source sentinel и отсутствие decoy данных; это proof поведения helper, не restore свежего production archive. Восстановление actual production dump в этот допуск не входит и не заявляется. POSTGRES_DB не является authority app DB.
- FR-ZOOM-DB-003 MUST: только отдельный transient admin connection к тому же bound DB вызывает existing exported migrate(pool) из immutable candidate image. Secret передаётся in-memory→stdin JSON→Pool(config), не через argv/envfile/Docker Config.Env; runtime DATABASE_URL, memberships, DML/DDL grants не меняются. В initial candidate pending delta ровно033; already033 с exact SHA допускает idempotent forward/recovery при отсутствии иных pending entries. Rollback C0 требует033 с exact SHA и не вызывает DDL; unknown/other pending entries отвергаются. Все прежние SHA,032 и DDL prerequisites проверяются read-only до pause и повторно перед backup/migration; unqualified journal/intent должны разрешаться в exact public objects при trusted admin search_path=public, runtime search_path не меняется. После штатной остановки services recheck использует saved qualified runtime target + immutable inspect + admin SQL; docker exec в уже остановленные четыре app процесса не требуется. Ни production retry, ни GRANT, ни custom SQL runner/down migration этим дополнением не разрешены.
- FR-ZOOM-DB-004 MUST: connect/query/process имеют bounded timeouts и terminal ownership. Timeout Docker CLI не доказывает завершение admin Node/DDL: собственный container/child и backend операции должны получить подтверждённое terminal состояние, иначе исход UNKNOWN и retry запрещён до reconcile. В private0600 evidence остаются phase, SQLSTATE, child exit/signal и secret-free DB identity; внешняя ошибка не выводит credentials/DSN/SQL с пользовательскими данными. После отказа до pause здоровый сайт не останавливается; после фактического pause сохраняется действующий fail-closed recovery contract.

Приёмка: реальные две собственные logical DB и restricted runtime role на существующем QE PostgreSQL, без нового DB/Redis stack, постоянных сервисов или production DDL; ephemeral pinned candidate Node для stdin/admin boundary допустим и проверяется. Проверяются exact target dump/restore, native restricted-role42501, qualified admin033, неизменность runtime DSN/grants и negative pre-pause side effects. Успех до такого прогона не установлен. OpenSpec delta выше обновлена этим же дополнением; исходный UI/oracle не менялся.
