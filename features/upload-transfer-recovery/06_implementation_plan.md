## Целевое состояние

Передача и обработка различимы; обновление списка не создаёт опасный путь к текущей записи.
После ухода пользователь видит способ продолжить прежнюю загрузку. Существующий multipart
остаётся единственным транспортом. Приёмка не требует новых длинных платных прогонов.

## Задачи

- T1 (FR-1, FR-3): сначала RED на повторно появившуюся uploading-карточку и ложный текст
  на странице записи; тест настоящих React-компонентов, отдельный контроль queued/transcribing.
- T2 (FR-2, FR-4, FR-5, после T1 и K2): расширить browser fixture реальными переходами
  по сторонней ссылке, отказом от ухода, подтверждением ухода/возвратом с тем же файлом,
  отказом complete и успешным автоматическим переходом. Зафиксировать RED до исправления.
- T3 (FR-1, FR-2, FR-3, FR-4, FR-5, после T2): минимально изменить существующие компоненты,
  без нового хранилища, API, dependencies, очереди, повышения квот или ручного начисления.
- T4 (после T3): GREEN в Chromium/WebKit, typecheck/lint/build, применимый полный regression,
  responsive-прибор на затронутых экранах; мутация возвращённой ссылки и ложного uploading-текста.
- T5 (после T4): независимое cross-model ревью с чистым контекстом, spec/code anti-drift,
  commit/push; развёртывание только тестовых целей с сохранением данных и контролем активных
  загрузок. Воспроизвести обход через обновлённый список на опубликованном UI с собственной
  ограниченной multipart-пробой; это не подмена полного длинного CJM.

## Зависимости и checkpoints

T1 → T2 → T3 → T4 → T5. Записи выполняются последовательно, кодирующий агент — в отдельном
worktree. K1: новых экспортов/модулей/команд не планируется. K2 обязателен до T1/T2.
Результат теста и факт выкладки фиксируются отдельно. Провал не переписывается успешным receipt.

## Риски

Штатный confirm различается между браузерами; отмена перехода должна оставить PUT живым.
beforeunload не покрывает все SPA history-переходы: FR-4 проверяет фактическое восстановление.
Не угадывать наличие File по серверному статусу и не обещать продолжение из другой сессии.
Не менять работающие контейнеры во время пользовательского PUT без необходимости.
