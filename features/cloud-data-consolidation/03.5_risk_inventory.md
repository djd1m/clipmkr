# Риски для независимого QCSD

Это author risk inventory, **не независимое ревью и не closed ideation**. Root должен подготовить snapshot и отдельный reviewer по model policy; прежние findings cloudru-release-parity сохраняют своих владельцев.

| Риск | Severity | Требование / отрицательный сценарий | Митигирующее решение / проверка |
|---|---|---|---|
| Присвоение данных при same email/different owner | CRITICAL | FR-3/4, A1/A7 | ADR-001, explicit identity proof; cross-account 404, source token denied |
| Замена c source dump или silent skipped rows | CRITICAL | FR-2/10, A2 | Independent restore обеих DB, mapping всех строк, сохранённый c before-image |
| Duplicate grant/подавленный payment event | CRITICAL | FR-5/6, A3 | ADR-002, shop/mode provenance, pending/refund/replay и original order lookup |
| Повреждение historic billing INSERT trigger | HIGH | FR-5 | 022 trigger + post-import field comparison на PG16, не balance-only |
| S3 collision/неправильный prefix/права | CRITICAL | FR-9, A4 | ADR-003, whitelist + per-object SHA256 + no-overwrite |
| Потеря данных при update-only delta | CRITICAL | FR-11, A5 | ADR-004, complete final snapshots/deletes/fence всех writers |
| Rollback теряет новые account/payment/video | CRITICAL | FR-11, A6 | New-write marker, forward recovery/reconciliation |
| Старый controller считает Cloud пустым | HIGH | FR-1/2 | Не reuse старого admission; новый extension после K1/QCSD |
| Ошибка monthly/referral ownership после merge | HIGH | FR-7 | Per-code native metrics, Moscow границы и20/30/null, snapshot history |
| Shared code на разных origin ведёт не туда | HIGH | FR-8 | Origin-aware compatibility, никакого blind redirect |
| Retention удаляет backup/copy либо resurrects deleted | HIGH | FR-2/9 | Tombstones/expiry, согласованный backup lifecycle и writer fence |
| Старый tunnel/profile принят за current | HIGH | FR-1/10 | Fresh target binding и отдельно проверенный резерв; никаких key changes сейчас |
| Диск/RTO не выдерживают два backups и candidate | HIGH | FR-10 | Сначала безопасные агрегаты capacity, затем measured restore; не cleanup чужих volumes |

Методики: studio-extended-qe в reference mode, shift-left failure analysis и требования→сценарий; risk-based приоритет по последствиям, без выдуманной вероятности. AQE runtime/swarm и tests не запускались. Все mitigations выше — запланированные проверки, не доказанная защита. Отдельный review должен проверить полноту неизвестных связей и данных, не только наличие строк этой таблицы.
