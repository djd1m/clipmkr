## Несущие отрицательные сценарии
- A1: совпадение email/UUID не присваивает данные другого владельца.
- A2: restore/повторный импорт не заменяет существующий dataset c.
- A3: повтор webhook/импорта не выдаёт второй grant и не подавляет чужой shop event.
- A4: одинаковый object key с разными bytes не перезаписывает target.
- A5: drift после freeze, неизвестный writer или потерянный delta блокирует cutover.
- A6: rollback после target writes не теряет новые данные/платежи.
- A7: старые токены и ссылки не дают cross-account access.
