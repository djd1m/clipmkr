## Функциональные требования

Все FR — MUST.

| ID | Условие/действие → проверяемый результат |
|---|---|
| FR-1 | Собственная активная запись с завершённой загрузкой и подтверждённым объектом → компактная строка «Исходник · Смотреть · Скачать» под заголовком, реальные длительность/тип/HEAD bytes; без выдуманного срока |
| FR-2 | «Смотреть» → исходник в существующей области без autoplay; выбор клипа сохранён; «К клипам» и выбор клипа возвращают его; играет один media; keyboard/focus и 390/1440 px соответствуют pinned макету |
| FR-3 | «Скачать» → attachment с безопасным UTF-8 именем и расширением проверенного контейнера; исходное имя не обещается, поскольку его нет в БД; браузер получает файл без JS Blob/полного скачивания сервером |
| FR-4 | Аноним, foreign ID, неизвестный ID, удалённая запись/неактивный аккаунт, owner против чужой записи → одинаковый 404, без метаданных, HEAD/GET и подписи; guest/showcase/referral не дают доступ |
| FR-5 | Загрузка не завершена → нет подписи; завершённый объект во время обработки допустим; отсутствие объекта → недоступен; timeout/5xx S3 → временная ошибка, не ложное удаление; неизвестный TTL не превращать в expiry |
| FR-6 | Подписанный GET ограничен 900 с и меньшим реально известным сроком; Range/206/seek подтверждаются на Cloud.ru; новая попытка после expiry обновляет авторизацию один раз с позицией/pause, без бесконечного retry |
| FR-7 | MP3/M4A → аудиопросмотр, MOV/WebM/MP4 → по проверенному контейнеру; неподдержанный codec → честный отказ просмотра при доступном скачивании, без платной конвертации |
| FR-8 | Чтение/скачивание → не запускает jobs, не меняет credits/growth clip download/retention; готовые клипы живут независимо |

## Нефункциональные требования

NFR-1: авторизация через существующие session/rate-limit/UUID/active account/ownership и DB object_key; никакого client supplied key. NFR-2: redirect/metadata/errors `private, no-store`, `no-referrer`, безопасные сообщения без сырого S3 error/URL/token; подписи не попадают в SSR, list/get poll, logs, telemetry, local/session storage или Git. NFR-3: HEAD и ограниченные первые bytes только по запросу отдельного original read seam, не HEAD всех видео в 5-секундном poll; не вводить cross-user cache. NFR-4: существующий signer сохраняет byte/URL контракты clip/showcase без новых options; изменения обратно совместимы. NFR-5: отсутствие новых env/schema/integration; реальный Cloud.ru, не MinIO как доказательство поставщика.

## Ограничения и границы

Нет изменения retention, новых публичных original endpoints без account check, массовых операций и автоматической конвертации. Не доказывать наличие исторических исходников одним примером. Не изменять email/payment/Cloud/DNS и существующие исследовательские материалы. S3 fixture uploads только после gates в тестовый prefix; planning не скачивает production media. Источник lifecycle/purge неизвестен: не обещать вечного хранения. Истёкший clip не означает истёкший source. Подпись остаётся временным bearer до expiry; немедленный отзыв не обещается.

## Открытые вопросы

Точный макет показывает только normal MP4/watch/return/download. Inline состояния loading/check-failed+retry/missing/incomplete/audio/unsupported/URL-refresh не нарисованы. До frontend подготовить конкретное дополнение и получить owner approval, как требует AGENTS.md. Текущий scope разрешает backend planning, не даёт разрешения незаметно добавить эти элементы. Архитектор должен решить минимальный metadata/refresh seam, MIME detection и формат fallback filename до K1/K2. Runtime lifecycle inventory выполняется read-only после согласования доступа; без него срока в UI нет. Иных продуктовых уточнений для backend scope не требуется.
