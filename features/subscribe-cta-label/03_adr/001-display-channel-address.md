# ADR-001 Показывать адрес подписки через существующий CTA

Статус: принято после согласования показа адреса на двух поверхностях.

## Контекст и критерии

Исторический ADR о призыве намеренно оставлял адрес в HTML. Для подписки владелец запросил сам адрес. Нужны читаемость, сохранение обоих путей публикации и отсутствие нового вычислительного или сетевого сервиса.

## Решение

В публичной кнопке подписки показать полный проверенный HTTPS-адрес. В рендер передаётся адрес только для подписки. Для надписи выбирается короткая публичная ASCII-ссылка с хостом DNS-формы и путём из ASCII-букв, цифр, точки, дефиса, подчёркивания, тильды, @ и слешей. Адрес проходит существующую канонизацию HTTPS. Query, фрагмент, порт и escape-последовательности для пикселей исключаются. Право на показ проверяется теми же метриками шрифта, минимальным кеглем и полями, что и в рендере 1080×1920. Ссылка передаётся FFmpeg через временный текстовый файл по образцу заголовка. Непригодный адрес остаётся на веб-странице, прочие режимы сохраняют статический текст. Изменение строки в пикселях запускает прежнюю атомарную пересборку. В контракте хранилища используется хеш отображаемого значения.

Вариант с изменением только HTML проще, но оставляет прежнюю надпись в скачанном клипе. Вставка полного произвольного значения прямо в фильтр ухудшает изоляцию данных и не помещается на части видео.

## Последствия

Для применения нужны web и video worker. Миграции, новые зависимости и автоматическая пересборка архива не нужны. Готовый MP4 обновляется при следующей успешной штатной пересборке. При окончательном отказе сохраняется прежний файл, кнопка уже указывает на новый адрес. Повтор того же значения сам по себе новую задачу не создаёт. Старый контракт объектов сохраняется для статических надписей. Перед сменой версии воркера сверить незавершённые попытки, которые уже могли записать объект, и дождаться их завершения или оставить выкладку на ожидании при неясном состоянии.
