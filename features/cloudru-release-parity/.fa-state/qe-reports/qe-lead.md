Параметр берётся из закрытой привязки именно этой ВМ, а не из произвольного ввода:

```bash
sudo -n ip route add local "$CLOUD_SELF_IPV4/32" dev lo table local
ip -j route get "$CLOUD_SELF_IPV4"
# Откат только добавленного этим оператором маршрута:
sudo -n ip route del local "$CLOUD_SELF_IPV4/32" dev lo table local
```

Маршрут непостоянный; после reboot его требуется заново проверить и, при
сохранении этой сетевой особенности, восстановить. Точные адреса, before/after,
привязки и квитанции хранятся вне Git. Это установленный обход наблюдаемого
маршрута; причина поведения облачной сети на стороне провайдера не утверждается.

## 4 ноября: постоянное сопровождение рабочей Cloud ВМ

Владелец отдельно потребовал устранить временный срок административного доступа.
Установлены два постоянных обратных SSH-канала на разных существующих приёмниках:
управляющий сервер и VPS сайта. У каждого свои ключи, ограниченный технический
пользователь, localhost listener, включённый unit с Restart=always и без
RuntimeMax/календарного истечения. Приватные ключи каналов остались в Cloud;
административный ключ резерва создан непосредственно на VPS сайта.

Фактически проверены новые входы, SFTP/SHA/cleanup, автоматический restart
обоих SSH-клиентов, резервный вход при остановленном основном туннеле и запуск
основного через резерв. Обычный операторский профиль переведён на постоянный
канал. После всех действий неизменны IDs/StartedAt/restart counts всех 7 Cloud
и 68 Site контейнеров. Перезагрузка ВМ не выполнялась; boot enable проверен.

Независимая новая сессия проверки выявила незакрытый streamlocal forwarding
и неоднозначный абзац о сроке старого ключа. Добавлен явный запрет Unix-socket
forwarding обоим новым приёмникам, выполнены реальные отрицательные проверки;
абзац исправлен. Основной reviewer перепроверил конфигурацию, резерв проверяется
отдельно. Private отчёты и точные подключения сохранены вне Git.
Полный порядок и пределы доказательства: [SSH runbook](../../../../docs/runbooks/cloudru-reverse-ssh.md).
В issue Cloudru Hub уточнён контракт постоянного транспорта и новых коротких
сессий для существующей ВМ; реализация такого режима в Hub не заявляется.
