# ADR-002: обновление существующих тестовых копий с изолированным S3

Status: proposed; обратимо совместимым выпуском приложения; production cutover исключён.
Дата: 03.11.2026. Требования FR-2, FR-4, FR-5, FR-7.

## Context

Inventory: Cloud.ru содержит три аккаунта, локальный stage — один; на обеих
копиях нет видео, клипов и платежей. Обе имеют 26 миграций, новый код — 28.
Дополнительные 026/027 расширяют модель без удаления аккаунтов. Прежние аккаунты
не объявлены ненужными. Старые тестовые настройки S3 совпадают с production,
а запуск web включает фоновых писателей.

Первый проект с параллельным cookie-маршрутом признан сложным для реферальных
переходов, payment return и независимых браузерных контекстов. До реализации
решение пересмотрено по условиям независимого QCSD.

## Decision drivers

Сохранение данных, отсутствие второго пользовательского маршрута на одном origin,
минимум новых компонентов, предсказуемые ресурсы и настоящий публичный E2E.

## Considered options

| Вариант | Преимущества | Ограничения |
|---|---|---|
| Обновить существующую тестовую копию с её БД | Сохраняет аккаунты и обычные ссылки, меньше ресурсов | Нужны backup/restore и проверяемая совместимость миграций |
| Параллельный project и cookie выбора backend | Прежняя версия продолжает работать | Два auth/cache контекста на origin, сложнее referral и callback |
| Новый hostname/project | Ясная browser-изоляция | Дополнительный DNS и ресурсы, не нужны при отсутствии тестового медиа |

## Decision

Обновить только явно инвентаризированные тестовые копии. Сначала независимые
backup и реальный restore, затем отдельные S3 bucket/keys без production-прав,
сверка полного списка S3-ссылок в тестовых БД: список должен быть пуст, иначе
подготовка останавливается до отдельного плана копирования объектов.

Существующие тестовые DB/Redis/volumes сохраняются, их данные не заменяются.
Применяются добавляющие миграции 026/027 после проверки исходного schema journal.
Старый web/worker тестовой цели останавливается на время изменения конфигурации,
production-сервисы не затрагиваются. Новая конфигурация не наследует production
SESSION_SECRET/DB/Redis/S3/SMTP/payment credentials. Аккаунты сохраняются;
после смены session secret потребуется повторный вход.

Cloud-кандидат использует обычный c.clipmkr.ru без cookie-селектора и без
переключения DNS. Для каждой новой роли/ссылки/return действует один backend.
Источник нового кода — локальный Git; точная вторая цель фиксируется до apply.

Живая оплата требует отдельного тестового магазина или маршрута с сохранением
прежнего test receiver и проверкой принадлежности intent. До его реальной
настройки оплата blocked. Никакой fan-out неизвестных платежей и молчаливой смены
существующего callback. Самостоятельно подставленное событие не даёт E2E passed.

## Consequences

Плюсы: обычный origin и все ссылки работают без допуска cookie; сохраняются
аккаунты, нет удвоения app/worker на небольшой Cloud ВМ. Минусы: начальный
апгрейд 26→28 требует тестового окна; старую версию после новой схемы нельзя
восстанавливать автоматически без доказательства совместимости.

## Confirmation

1. tests/release-candidate.test.ts: явный production guard, отсутствие общих
   production-ресурсов, пустой список медиа, проверенный backup/restore и journal.
2. tests/release-candidate-acid.test.ts: подмена тестовой цели или пропуск
   проверки isolation/schema/backup приводит к отказу.
3. Реальная сверка аккаунтов до/после 026/027; публичные browser-контексты владельца,
   блогера и клиента; обычные referral/payment return без candidate cookie.
4. Admission по FR-7 и остановка только своей тестовой цели при неуспехе.

Load-bearing property: обновление не заменяет данные теста данными production,
не даёт фоновой обработке production S3 и не меняет production-маршрут.
Owner: оператор выпуска; независимое QE проверяет реальные доказательства.

## Review

Эта структурная поправка требует focused review исходных QCSD-ролей. Новый
платёжный маршрут остаётся внешней зависимостью; его отсутствие не скрывается.
