# Технические уточнения к согласованной политике

Статус: предложения исполнителя для checkpoint, НЕ новые одобрения владельца. Согласованы 7 суток free, оплаченный период +30 суток, письма −3/−1 сутки, история после удаления, существующие материалы без перехода. Точная ревизия OpenSpec закрепляется владельцем требования в `requirements-revision.json`.

1. **Область оплаченного права.** Минимальная рекомендация: для всех физически сохранённых клипов аккаунта `deadline = max(ready_at + 7 суток, последнее применимое paid_end + 30 суток)`. Сохранять прежний account-wide принцип. Для credit_grant учитывать только source=payment с начавшимся entitlement_start; будущий scheduled период сам по себе ещё не активное право. Нужна фиксация: должен ли уже оплаченный будущий scheduled период сразу защищать клипы от удаления. Результаты после окончания прошлой оплаты тоже получают max; владелец пока не уточнял иной scope.
2. **Готовность.** Новый ready_at — момент первой принятой публикации конкретного клипа, без сброса от CTA/музыки/retry. История: сначала min job_attempt.finished_at WHERE stage=render AND status=succeeded AND NOT rerender; затем video.finished_at как явно помеченная менее точная историческая граница. Если обе отсутствуют, не брать дату выкладки/created_at; исключить из destructive cleanup и показать, что дата уточняется. Нужна оценка реального количества таких строк до выкладки (без приватных данных в Git).
3. **Блогер.** Рекомендуемый минимум: обычная политика free/paid действует и для блогера; 120 минут — только длительность. Отдельно предлагается явная настраиваемая владельцем политика хранения с журналом назначения. Её тип/числа/приоритет ещё не одобрены и не должны тайно превращать is_blogger в бессрочное хранение. Пока FR-7 остаётся блокирующим уточнением для полной заявленной фичи.
4. **Продление и удаление.** Рекомендуется различать expiry, необратимый logical claim `deletion_started_at` и подтверждённое S3 `media_deleted_at`. Оплата и claim сериализуются account row lock. Продление, применённое до claim, учитывается при повторной проверке; после claim байты не обещаются к восстановлению. Нужна фиксация именно этой границы: гарантия «до физического удаления всех байтов» не обеспечивается простым S3 DELETE после crash/частичного отказа. Альтернатива — временный карантин/версионирование с восстановлением и новый ADR/стоимость; в минимум не включена.
5. **Письма.** Предлагается одно логическое письмо на запись, конкретную дату группы клипов и offset (3/1). Если готовность клипов отличается, даты/группы разные, одна «дата всей записи» скрыла бы более ранний срок. Продление supersede старые pending. Для старых материалов в catch-up: при 1–3 сутках до expiry отправить только −1, при 3+ только актуальное −3; истёкшим не слать «успейте». Точный catch-up и группировка пока не согласованы.
6. **Unknown Resend.** accepted означает принятие провайдером, не доставку в inbox. Durable unique key предотвращает повторные логические события; provider idempotency с тем же неизменным payload необходим для повторов после timeout. После окончания проверенного срока dedupe unknown не повторять автоматически, оставить оператору. SMTP не даёт аналогичной гарантии: для reminder либо только настроенный Resend, либо явное ослабление гарантии; режим не переключать тайно. Официальный контракт Resend проверен координатором: 24 часа, тот же ключ и payload; источник и ограничения в 02_research.md. Интеграционный тест ещё не выполнен.
7. **Исключения.** Существующие owner_unlimited, paid/operator, paid/none и SHOWCASE_CLIPS являются явными текущими исключениями. Рекомендуется сохранить их в этой дельте и явно показывать политику; это не доказательство численных условий блогера. Если владелец хочет отменить бессрочность operator/legacy — отдельное решение до cleanup. Явный clip.expires_at с непустыми ключами не сбрасывать без установления происхождения; при пустых ключах не обещать восстановление.
8. **Тексты и макет.** `apps/web/src/app/dashboard/ProInterest.tsx` обещает «хранение без срока»; `apps/web/src/lib/legal-documents.ts`, privacy §6.2 — файлы до удаления аккаунта. Новая политика с ними конфликтует. Требуются конкретные согласованные тексты, обновление ссылки на источник юридического контента и UI макет до кода; правовые утверждения здесь не оценивались.

Ни один пункт не означает прохождения requirements/QCSD/ADR/architecture/plan/K1/K2 gate. Это список решений, которые нужно превратить в проверяемый контракт до реализации.
