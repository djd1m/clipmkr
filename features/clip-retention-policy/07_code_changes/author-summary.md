## Anti-drift и пределы доказательства

FR-1…FR-8 реализованы через существующие shared/SQL/storage/mail/runtime блоки, без новой платежной модели, source-auto-delete, blogger perks или owner proxy. История и исходник сохраняются; account erasure сильнее и удаляет notice. Accepted письма не означают inbox delivery. Исторические null keys не объявляются доказанным физическим удалением; unknown readiness не получает destructive cleanup.

Deadline заканчивает выдачу новых ссылок; существующие URL/загрузки/локальные копии не отзываются. Media_deleted_at — первый успешный sweep; durable recheck продолжает обязанность позднего PUT. Цена — периодические S3 listings и backlog delay, без выдуманного физического SLO. Неизвестная legacy история после прежнего операторского сброса не восстанавливается по догадке.

Independent primary/fleet code/QE, подтверждение текущего snapshot и разрешённая поставка ещё впереди. `../deployment-plan.md` ограничивает runtime; старый image с3-дневным cleanup не считается безопасным откатом7-дневной политики. Ни один author результат не объявляет production приёмку, разрешение миграции или выполненную отправку пользовательского письма.
