# План поставки правил хранения

Цель — действующий Clipmkr на VPS 77.83.87.178. Cloud.ru, DNS, старый сервер и настоящие списания вне этого изменения. Выпуск следует после проверки кода, независимого QE и проверки настоящего кабинета на изолированных данных. Этот план не является подтверждением выполненной выкладки.

1. Зафиксировать проверенную ревизию и одинаковый commit в трёх Git-репозиториях. Собрать web и worker из этой ревизии; сохранить прежние image ID и закрытый Compose-профиль для диагностики.
2. Проверить свободное место, состояние текущих задач и свежую согласованную резервную копию БД. Не удалять данные или образы других проектов. Миграция 028 добавляет поля и таблицу уведомлений; первая готовность старых клипов восстанавливается из исторических событий, не из времени выкладки.
3. Применить миграцию к действующей БД и заменить только web и три worker текущего приложения. Не пересоздавать PostgreSQL, Redis и поддержку. Сохранить действующие ключи, S3-префикс, почту и ограничения тестовой оплаты. Не использовать тестовый профиль браузерной проверки для работающего сайта.
4. Проверить здоровье, чтение истории и расчёт дат на действующем сайте. Убедиться, что настройки почты доступны; принятие письма провайдером и получение во входящих — разные результаты. Проверка UI и просмотра не означает повторную проверку всей оплаты и генерации.
5. После пересоздания контейнеров обновить закрытую привязку резервирования по фактическим ID, образам и подключениям. Проверить работу резервного копирования: прежняя привязка специально запрещает резервирование неизвестного runtime.
6. Опубликовать фактический результат, ссылку и короткую инструкцию ручной проверки. Удалить только собственные синтетические файлы S3 и изолированную БД браузерной проверки после сохранения доказательств.

## Ограничения отката

Схема добавляется без удаления прежних колонок, но старый образ реализует трёхдневную очистку. Поэтому его простой запуск не является безопасным откатом новой семидневной политики. При отказе новой версии сначала остановить изменённые процессы, сохранить актуальную БД и диагностические данные, затем исправить версию вперёд либо подготовить проверенный откат с отключённой старой очисткой. Восстановление старой копии БД поверх новых пользовательских записей не допускается. Удалённые байты не восстанавливаются одной заменой образа или изменением даты в БД.
