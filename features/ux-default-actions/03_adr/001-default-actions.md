# ADR-001. Основные действия и пояснения

## Статус

Предложен для согласования 24.11.2026. Источник решения — [требования UX-001](../01_requirements.md), текущие компоненты на `5053cb84d157d3adb3f04dd4a1399bcb3e17f1b1` и [макет](../../../docs/design/2026-11-24-ux-default-actions.html).

## Контекст

Четыре экрана выводят информацию из текущих UI-проекций. Пользователь видит повторы лимита/состояния, а блогер и владелец читают служебное пояснение до действия или повторно в карточках. Критические различия между передачей и обработкой, ошибкой и ожиданием, отсутствием ставки и суммой уже есть в данных.

## Критерии

Сохранить открытые условия и действия, при которых пользователь теряет время, доступ к готовому файлу либо ошибается в стоимости. Сохранить текущие темы и компоновки, переиспользовать `details/summary`, область исходника и существующие действия.

## Варианты

1. Сохранить порядок, сократить формулировки. Имеет самый малый diff. Повторная структура и дополнительный текст до основной задачи частично сохраняются.
2. Сделать одну основную сводку и переместить методику/историю в нативные раскрытия. Порядок отражает задачу, вторичные объяснения доступны. Нужны проверки развёрнутых/закрытых состояний, с клавиатурой в обеих темах.
3. Собрать новые сводные экраны и компоненты. Даёт свободу композиции, но увеличивает diff, повторяет существующий UI и повышает риск сброса состояния.

## Решение

Вариант 2: презентационная дельта в `Uploader`, `VideoDetail`, `PartnerPanel` и `BloggerAdmin`. Условия, числа, видимость действий и имя файла получают прежние проверенные значения. Для записей с фактическим отказом действие определяется `next_action`, доступность клипа — его собственным состоянием. Для отсутствия ставки остаётся null, а для начисленной предварительной оценки остаётся сумма отчёта. Основная метка результата выводится один раз, активная обработка сохраняет открытую ленту.

## Последствия

Объяснения появляются по явному раскрытию. Ошибка, восстановление, стоимость, условия и плеер остаются в обычном порядке просмотра. Локальный прогресс подтверждённых частей и ответ о принятии файла остаются различимыми. Клиповые данные и черновик редактирования продолжают жить на текущих ключах. Новых миграций, API и внешних зависимостей не требуется.

При независимом ревью проверить, что замена блоков не перемонтирует медиа и контролы при poll/theme/layout. При ручной приёмке владелец подтверждает доступность методики и этапов после раскрытия.

- `tests/progress-screen.test.ts`: явный сигнал восстановления, завершённый частичный результат, stale, неудачный результат и состояние передачи.
- `tests/browser/upload-lifecycle.test.ts`: сохранённые параметры, повтор частей, корректное отличие данных о передаче и начала обработки, reload и фокус.
- `tests/browser/clip-layout.test.ts`: фокус и действие сохранения в существующем редакторе.
- Критерий принятия: браузерные проверки на стабильной реализации, независимое подтверждение области диффа и ручная проверка на тестовом стенде владельцем.
