# Быстрый возврат трёх пунктов при добавлении автоплатежей

Текст изменён отдельным коммитом `931256429e18ffe597678101e69ac8565321d490`. В нём только два файла: `apps/web/src/lib/legal-documents.ts` и `tests/artifacts/legal-pages/approved-replacements.json`. Исходные строки также сохранены в полях `old` трёх добавленных записей. Остальные условия не переписаны.

Когда будет согласована новая версия с рекуррентными платежами, штатный обратный патч вернёт прежний текст и одновременно уберёт соответствующие три разрешённые замены из golden map:

```sh
git revert --no-commit 931256429e18ffe597678101e69ac8565321d490
npm test -- --run tests/legal-pages.test.ts
git diff --check
```

Затем проверить дифф, зафиксировать новое изменение и поставить его через обычные feature-adr/dz/QE. Сам `git revert` не включает сохранение карты или автосписание: это только обратная текстовая правка. До готовности и согласования рекуррентных платежей старые обещания возвращать не нужно.

Если к тому времени соседние условия изменились, Git может показать конфликт. Разрешать его по этим трём пунктам; не заменять целиком файлы старой версией и не откатывать пользовательские данные или платёжные настройки. Вместо прежней формулировки можно согласовать новую — исходный текст сохранён как точка сравнения, а не как гарантия его пригодности будущей модели.

Независимый проверяющий уже выполнил фактические `git apply --reverse --check` и `git apply --reverse` в отдельной временной копии: оба файла побайтно восстановились к исходной базе, существующие6тестов повторно прошли. Отчёт: [08_primary_review.md](08_primary_review.md). Эта проверка относится к текущей дельте; будущие изменения могут потребовать разрешения конфликтов.
